済i260830-02ブロックとして扱っていないタグの構造が失われる

次のタグは BlockTags に無いため、中身が地の文として 1 つに連結される。テキストは消えないが構造は失われる。

タグいまの出力本来あるべき形

済2026-09-01 にテキストを落とさない対処を入れた。hr を除くすべてを走査の対象に加え、dt dd summary も個別に挙げて項目ごとの段落にした。address と caption も同時に対応した。

済i260830-03章の外で見出しの段が飛ぶ

入力章の中章の外

h2 だけが章の内外で段を変え、h3 は変えていない。章の外の h3 を ### にするか、h2 を章の中と同じ ### に統一するかを決める。

済i260830-04意味を持つインラインタグが平文になる

del ins sup sub mark kbd abbr small q cite time はタグが消えて中身のテキストだけが残る。取り消し線や上付きの区別は Markdown に出ない。

GitHub は ~~取り消し線~~ を解釈するので del は記法にできる。sup sub kbd は HTML のまま残す手もある。どこまで対応するかを決める。

済2026-09-01 に対処。del は ~~、GitHub で生き残るタグ（ins sup sub mark kbd q）はタグのまま残す。~~ も ** と同じ前後判定を受けるため、強調と同じセンチネル方式に載せた。成立しない位置では <del> で出る。

どのタグが残るかは実測で決めた。11 個すべてタグで出す実装にしたあと api.github.com/markdown へ投げたところ、abbr small cite time の 4 個は除去された（中身のテキストは残る）。表示に効かないため平文に落とすことにした。

この対応で退避の仕組みに潜んでいた欠陥が表面化した。キーの両端が同じ制御文字だったため、2<sup>10</sup> のように数字が隣接すると偽のキーができ、別の退避内容に置き換わっていた。両端を別の文字にして直した。

済i260830-10SVG 切り出し時に CSS 変数を解決する

デザインルールは stop-color="var(--accent)" の書き方を前提にしているが、SVG を単体ファイルに切り出すと変数が解決されず色が失われる。

<section class="ch03">
	<svg><linearGradient id="g-03-1a">
		<stop stop-color="var(--accent)"/>    ← .ch03 の定義が要る
	</linearGradient></svg>
</section>

<style> から .chNN { --accent: … } を読み、切り出す svg の祖先 section のクラスと突き合わせれば静的に解決できる。@media と JS による上書きは対象外とする。

ルールに従って書いた HTML ほどこの問題を踏む。この html2md 自身の図はリテラルの hsl() で書いていたため表面化していなかった。

済2026-09-02 に対処。上の方針どおり実装した。定義も既定値も無いものは書き換えずに残す（消すと図が壊れるより、そのままのほうが気づける）。@media の中はブロックごと落としてから読む。

フォールバックの取り出しは括弧を数えている。var(--x, hsl(280,78%,25%)) のように既定値の中に括弧が入ると [^)]* では途中で切れて壊れる。

あわせて、テストが .md しか比べていなかったのを直し、切り出した .svg も exe と ps1 で突き合わせるようにした。既存 6 プロジェクトの SVG に var( を含むものは無く、影響は出ていなかった。

済i260912-05アイコンだけのリンクが Markdown で空になる

2026-09-12、ai-chat-lite-reviewer から指摘（html2md ルーム #793）。共通ルール「root の README.html と資料の html は相互リンクする」に戻るリンクをアイコンだけにする規定が入ったが、html2md がそれを Markdown に落とせない。

実測

指摘を受けて tmp/ に見本を作り、変換した。指摘のとおりだった。

<a class="backlink" href="../"><svg width="16" height="16" …><path d="M8 1 1 7h2v7h4v-4h2v4h4V7h2z"/></svg></a>
[](../)
[](01-前.html) [](03-次.html) [](README.md)

リンクテキストが空になり、GitHub では何も表示されない。SVG の images/ への切り出しも起きない（リンクの中の SVG は対象外の扱い）。

あわせて確認した点

指摘元から「docs/ 配下の前へ・次へ・目次バッジは置き換わっているか」と問われたので調べた。置き換わっていない。<< ・ >> ・ ^^ への置換はソース全体で 1 件も実装されていない（共通ルール「資料間のリンク」には規定がある）。

.backlink だけの問題ではない。アイコンだけのリンク全般が対象で、docs/ を持つプロジェクトでは前へ・次へ・目次の 3 つが同じように空になる。

決めたこと

何に置き換えるかは共通ルールで決まっていた（前へ << ／ 次へ >> ／ 目次 ^^）。決めたのはどのアイコンかをどう判別するか。次の順で手がかりを探す。

順手がかり置き換え
1<a aria-label>語が表にあれば記号。表に無い語はその語をそのまま文字にする
2<a title>
3svg の中の <title>
4<a class="backlink">^^
5どれも無い空のまま。検査で指摘する

SVG の形（path の d）では判別しない。共通ルールはアイコンの意味（⌂ ・ ‹ ・ ›）だけを定めており、d の実値に規定が無い。辞書を持っても当たる保証が無く、外れたときに静かに空のまま通る。推測で当てるより、指摘して書き手に気づかせる方を採った。

途中で見つかったもの

<< が消えていた。最終段の汎用タグ除去（<[^>]+>）が <<](b.md) [> をタグ 1 個と誤認して飲み込み、[>](b.md) だけが残る。

既存の <br> と同じセンチネル退避方式で直した。制御文字（15）に置いてタグ除去を通過させ、通過後に << へ戻す。汎用タグ除去の正規表現を厳しくする方が根本的だが、全ケースに影響が及ぶため、影響が閉じる方を採った。

「HTML に無い文言」検査も 2 点直した。(1) 記号 << ・ >> ・ ^^ を両側から落とす（共通ルールが認めた代替なので付け足しではない）。(2) aria-label を元の位置に埋めてから突き合わせる。末尾にまとめて足す作りだったため、…にする: 付録 のように地の文と繋がった行が一致しなかった。

テスト

ケース icon-link を新設。期待値（終了コードと ★ 行）を手で書いてから実装したので、実装の出力に引きずられていない。手で書いた expected.txt と実装の出力は一致した。

済i260912-01公開前検査（check-public）を作るか

2026-09-12、ai-agent-rules から依頼（public ルーム #777）。public のリポジトリに出す前に、個人名・実体パス・認証情報が混ざっていないかを機械で止めたい。公開資料を作るプロジェクトが他にもあるため、共有ツール側に入れれば全部が守られる、という理由。

希望された形は check-contrast ・ check-markdown と同じ独立コマンド（check-public など）で、html2md の検査からも呼ぶ。変換が起きない場面（コミット前・リモート作成前）でも走らせたいため。

検査してほしいと挙がったもの

対象補足
メールアドレス—
実体パスC:\Users\ の直後が実名のもの。プレースホルダは除外
認証情報password / passwd / secret / api_key / token=。コード例の変数名が誤検出しやすく、調整が要る
除外語リスト顧客名・案件名・内部システム名
異体字の混入キリル・ハングル。日本語に紛れると目視で気づけない
git の authorローカルユーザー名が本文に出ていないか。環境から取れるので、名前をリストに書かずに済む

除外語リストの置き場は先頭 _ のファイルを既定に、という希望。リスト自体が機密のため、共通ルール「.gitignore の共通除外設定」で全階層が管理外になることを前提にしている。

決めること

  • 受けるかどうか。html2md は「HTML と Markdown の変換と検証」の置き場で、公開前検査はその外側にある。共有ツール置き場として引き受けるなら、位置づけを計画書に書き足す必要がある
  • 引き受ける場合の実装。exe（C#）と ps1 の 2 本立てにするか、check-contrast ・ check-markdown と同じ ps1 だけにするか
  • 誤検出をどこまで許すか。止める検査は、誤検出が多いと使われなくなる
  • 除外語リストの形式と、リストが無いときの振る舞い

依頼元は「どう作るかはお任せ。課題に残すかどうかも含めて」と書いている。受けない判断もあり得る。その場合は、どこに置くのが適切かを返す。

2026-09-13 に作った

引き受けて check-public として作った（src/check-public/main.ts）。挙がった 6 項目をすべて入れ、--skip で 1 つずつ外せる。実装は TypeScript で、ほかの 6 つと揃えた。

決めごとへの答え。

  • 受けた。公開前検査は変換の外側だが、check-contrast ・ check-markdown と同じ「出す前に実物で確かめる」道具であり、置き場としては揃う
  • TypeScript 1 本。ps1 と exe の 2 本立てにしない。この時点で 3 ツールの移植が済み、ps1 版も TypeScript へ移していたため
  • 誤検出は件数で縛った。テストの材料に「当たる 4 つ」と「当たらない 10 個」を置き、当たる件数が 4 を超えたら落ちるようにしてある
  • リストが無ければ、飛ばしたことを画面に出す。黙っては通さない

作った直後、このプロジェクト自身に掛けたら 12 件出た。中身を見たら全部が誤検出だった（const token = argv[i] ・ token: string ・ HTML でエスケープされた伏せ字）。判定を直して 0 件にした。止める検査は、誤検出が多いと道具ごと使われなくなる。
