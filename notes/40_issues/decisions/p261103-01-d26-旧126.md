## 案

- A: 決定済み (2026-11-05、利用者の判断): A : state キーをやめ、items/ の下の todo/ (未) ・ doing/ (着手) ・ done/ (済) ・ archived/ (グループごと片付いて退避) で持つ。状態の変更は issue set (内部で git mv) か直接の移動で行い、issue check が食い違いを検出する (推す理由: 実測で、未・着手だけ読む費用が、キャッシュの判定より小さい (390 件 ・ 14% で 4.9 ms 対 16 ms)。費用が、全体の件数ではなく未・着手の件数で決まる。同じ課題を同時に更新することは基本的に無いので、移動の競合は小さい)
- B: 従来どおり state キーで持つ (archived/ だけ分ける) (推す理由: 状態を変えても、ファイルは動かない。ただし、実測で効果が出ない (全部読む費用が、全体の件数に比例する))
