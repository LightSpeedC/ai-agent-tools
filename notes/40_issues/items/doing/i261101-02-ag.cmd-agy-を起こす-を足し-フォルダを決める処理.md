2026-11-01、利用者の希望。`cx.cmd` (`codex` を起こす) とほぼ同じ形で、`agy` を起こす `bin/ag.cmd` を作る。<strong>機能の追加なので、計画 → 承認 → 実装の順で進める。</strong>計画は [ag.cmd と起動の共通部 計画](../10_plan/i261101-02-ag-cmdと起動の共通部.md) (承認待ち。80-A の実装も含む)。

**決めたこと (同日、利用者の判断)。**

- [済] <strong>82-B。</strong>フォルダを決める処理 (`W:\` 以下の年のフォルダで、名前の一部が一致するものを探し、無ければ `<日付>-<名前>` を作る) を、1 本の共通部 (84-A で TypeScript に改めた) に切り出し、`cc.cmd` ・ `cx.cmd` ・ `ag.cmd` が呼ぶ。動いている `cc.cmd` と `cx.cmd` を書き換える。80-A (`setlocal` と後始末) の実装と重なるので、同じ計画にまとめる
- [済] **83-B。**`codex-trusted` と同じ形で、`ag-trusted` を作り、`agy` の `settings.json` の `trustedWorkspaces` にフォルダを書き足してから起動する。`settings.json` は `~/.gemini/antigravity-cli/` にあり、`agy` 自身が承認のたびに書き換える (許可リストを持つ)。書き足しは、配列に 1 行足す文字列の挿入で行い、書く前に控えを取り、起動中の書き込みと衝突しない形にする
- [済] <strong>起動の引数 (利用者の指定)。</strong>続きから開くときは `agy --dangerously-skip-permissions --mode auto -c`。新規のときは `-c` を付けない。続きにするかは、そのフォルダにそのエージェントの履歴があるかで決める (下の項)
- [済] <strong>続きにする条件 (利用者の指定)。</strong>既存のフォルダでも、**そのエージェントの履歴が無ければ、続きにせず新規で起動する** (`agy` は `-c` を付けない。`cx` は `resume` を付けない。`cc` は `-c` を付けない)。別のエージェントが先にフォルダを作り、このエージェントが後から起動されることがあるため。新しく作ったフォルダは、必ず履歴が無いので、同じ扱いになる。履歴の判定は、`claude` が `~/.claude/projects/<符号化したパス>/*.jsonl` を数える (`W:\2026\<名前>` → `W--2026-<名前>`。フォルダだけあって `*.jsonl` が 0 個のものがあるので、ファイルを数える)。`agy` が `~/.gemini/antigravity-cli/cache/last_conversations.json` にフォルダのキーがあるか。`codex` が `~/.codex/state_5.sqlite` の `threads` 表の `cwd` で、削除されていない会話があるか (表の定義は実測済み。値は読んでいない)
- [済] <strong>84-A。</strong>共通部は TypeScript の 1 本にする。`cc.cmd` ・ `cx.cmd` ・ `ag.cmd` は薄い入口で、共通部が (1) フォルダを決める、(2) そのエージェントの履歴の有無を判定する、を持つ。判定は `node:test` の単体試験にする。82-B の「1 本の内部 cmd」を、これに改める
- [済] <strong>85-A ・ 86-A (計画の中で決めた点)。</strong>共通部が、決めて起こすところまで行う (cmd は 1 行。日本語のフォルダ名を cmd に返さない)。名前を渡さずに呼んだときは、3 本とも `[NG]` を出して終了する (`cx` は無言終了でなくなる)
- [済] <strong>窓のタイトル (利用者の指定)。</strong>3 本とも `start "<エージェント名> <フォルダ名>"` の形に揃える。エージェント名は `cc` ・ `cx` ・ `ag` (87-B、利用者の判断。入口のコマンド名と一致させる)
- [済] <strong>終了のあとの再起動 (88 ・ 89、利用者の指定)。</strong>終了したあとで「再起動 / 終了」を尋ね、再起動なら続きから起動し直す。`cc` だけでなく `cx` ・ `ag` にも入れる。<strong>90-A (利用者の判断)。</strong>常駐は作らず、起動は短命の node、窓の番人は cmd のループにする (エージェントの数だけ node ・ bun を起動すると、メモリと不要なプロセスが無駄になるため。実測: node の待機は約 18〜49 MB、cmd は約 8 MB)。88-A (窓ごとに node の番人) は、これで改めた
