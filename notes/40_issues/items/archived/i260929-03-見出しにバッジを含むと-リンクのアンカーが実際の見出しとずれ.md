2026-09-29、`20260905-windows-pc-memory-inspection` から報告（public ルーム #1264）。見出し `1. 出力の安全性 ✅ 済 3 件（済 3）` の実際のアンカー（`github-slugger` の出力）は `1-出力の安全性--済-3-件済-3` だが、html2md のリンクは `#1-出力の安全性-済-3-件済-3` になる。`2. 自動化 ⚠ 着手 1 件（着手 1）` も同じ。

### 調べた

報告の推測（`getAnchorText()` が空白を畳む）とは違った。`getAnchor()` は空白 1 個をハイフン 1 個にしており、畳んでいない。

<strong>原因は、アンカーを計算する文字列と、Markdown に書き出す見出しが食い違っていること。</strong>アンカーは HTML の見出しからタグを落とした文字列（`getAnchorText()`）で計算する。一方、Markdown の見出しではバッジを `✅ **済** `（記号・空白・太字・空白）に、課題番号（`.no`）を後ろに空白を足して書き出す（`src/html2md/inline.ts`）。記号と補った空白が、アンカーの計算に入らない。

| 見出し（Markdown） | html2md のリンク | 実際のアンカー |
|---|---|---|
| `1. 出力の安全性 ✅ **済** 3 件（済 3）` | `#1-出力の安全性-済-3-件済-3` | `#1-出力の安全性--済-3-件済-3` |
| `✅ **済** i260929-01 件名です` | `#済i260929-01件名です` | `#-済-i260929-01-件名です` |

2 行目は報告に無かった形で、課題一覧の `<summary>` のようにバッジと課題番号が隣り合うと、**空白がすべて消えてアンカーが別物になる**。i260923-01 でタグの境界に空白を入れない `getAnchorText()` にしたとき、バッジと課題番号の後ろに補う空白の分が抜けた。

### 決めること（直し方）

- A: アンカーを、実際に書き出す Markdown の見出し（インライン変換のあと、`**` や ``` などの記法を外した文字列）から計算する。書き出しとアンカーが同じ元から出るので、インライン変換を変えてもずれない
- B: `getAnchorText()` に、バッジ（記号と空白）と課題番号（後ろの空白）の書き出し規則を写す。変更は小さいが、書き出し側を変えるたびに両方を直すことになる

他プロジェクトからの報告なので、直したあとも報告元の確認が取れるまで「済」にしない。

### 直した（2026-09-29、A で）

- アンカーの計算を、見出しを書き出すのと同じ順（インライン変換 → コードを戻す → 強調を決める）で作った Markdown の見出しから行うようにした（`converter.ts` の `headingAnchor`）。章の `h1`、id 付きの `h2`・`h3`、`md-flat` の `summary` の 3 か所
- 「Markdown の見出し → アンカー」を `getMarkdownHeadingAnchor`（`htmlutil.ts`）にまとめ、検査（`checks.ts`）と共有した。使われなくなった `getAnchorText()` は消した
- **もう 1 つずれていた**: `getAnchor()` が記号を落としたあとにもう一度 `trim()` していた。github-slugger には無い処理で、先頭が絵文字の見出し（`✅ 済 …`）で先頭のハイフンが落ちていた（実際は `-済-…`）。検査も同じ関数を使うため、検査の側もずれを見逃していた
- テストを先に書き、落ちるのを見てから直した（`tests/cases/anchor-badge/`。期待値は github-slugger の規則で手計算）。全テストが bun ・ node とも通る
- C# 版（`Html2MdCs`）は直していない。C# 版は 28 ケース中 12 ケースが落ちるほどずれていたため、扱いは i260929-02 の判断を先にする
