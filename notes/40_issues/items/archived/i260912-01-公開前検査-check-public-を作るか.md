2026-09-12、`ai-agent-rules` から依頼（public ルーム #777）。<strong>public のリポジトリに出す前に、個人名・実体パス・認証情報が混ざっていないかを機械で止めたい。</strong>公開資料を作るプロジェクトが他にもあるため、共有ツール側に入れれば全部が守られる、という理由。

希望された形は `check-contrast` ・ `check-markdown` と同じ**独立コマンド**（`check-public` など）で、html2md の検査からも呼ぶ。変換が起きない場面（コミット前・リモート作成前）でも走らせたいため。

### 検査してほしいと挙がったもの

| 対象 | 補足 |
|---|---|
| メールアドレス | — |
| 実体パス | `C:\Users\` の直後が実名のもの。プレースホルダは除外 |
| 認証情報 | `password` / `passwd` / `secret` / `api_key` / `token=`。**コード例の変数名が誤検出しやすく、調整が要る** |
| 除外語リスト | 顧客名・案件名・内部システム名 |
| 異体字の混入 | キリル・ハングル。日本語に紛れると目視で気づけない |
| git の author | ローカルユーザー名が本文に出ていないか。**環境から取れるので、名前をリストに書かずに済む** |

除外語リストの置き場は**先頭 `_` のファイルを既定に**、という希望。リスト自体が機密のため、共通ルール「.gitignore の共通除外設定」で全階層が管理外になることを前提にしている。

### 決めること

- <strong>受けるかどうか。</strong>html2md は「HTML と Markdown の変換と検証」の置き場で、公開前検査はその外側にある。共有ツール置き場として引き受けるなら、位置づけを計画書に書き足す必要がある
- 引き受ける場合の実装。exe（C#）と ps1 の 2 本立てにするか、`check-contrast` ・ `check-markdown` と同じ ps1 だけにするか
- 誤検出をどこまで許すか。**止める検査は、誤検出が多いと使われなくなる**
- 除外語リストの形式と、リストが無いときの振る舞い

> [!IMPORTANT]
> <strong>依頼元は「どう作るかはお任せ。課題に残すかどうかも含めて」と書いている。</strong>受けない判断もあり得る。その場合は、どこに置くのが適切かを返す。

### 2026-09-13 に作った

**引き受けて `check-public` として作った**（`src/check-public/main.ts`）。挙がった 6 項目をすべて入れ、`--skip` で 1 つずつ外せる。実装は TypeScript で、ほかの 6 つと揃えた。

決めごとへの答え。

- <strong>受けた。</strong>公開前検査は変換の外側だが、`check-contrast` ・ `check-markdown` と同じ「出す前に実物で確かめる」道具であり、置き場としては揃う
- <strong>TypeScript 1 本。</strong>ps1 と exe の 2 本立てにしない。この時点で 3 ツールの移植が済み、ps1 版も TypeScript へ移していたため
- <strong>誤検出は件数で縛った。</strong>テストの材料に「当たる 4 つ」と「当たらない 10 個」を置き、**当たる件数が 4 を超えたら落ちる**ようにしてある
- <strong>リストが無ければ、飛ばしたことを画面に出す。</strong>黙っては通さない

> [!WARNING]
> **作った直後、このプロジェクト自身に掛けたら 12 件出た。中身を見たら全部が誤検出だった**（`const token = argv[i]` ・ `token: string` ・ HTML でエスケープされた伏せ字）。判定を直して 0 件にした。**止める検査は、誤検出が多いと道具ごと使われなくなる。**
