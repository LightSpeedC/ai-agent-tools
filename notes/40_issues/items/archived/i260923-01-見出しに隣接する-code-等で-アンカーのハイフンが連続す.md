2026-09-22、`i260921-01` の検証中に `ai-chat-lite` から追加報告（public ルーム #994）。**見出しに `-c`・`:id:` のようなコードを含むとき、リンク側のスラッグが実際の見出しと一致しない**とのこと（先方の `i260903-02`：見出し「`## **☑** i260903-02 ID の名乗り方を作り直す（`-c` を廃し、コマンドの直後に `:id:` で固定する）`」）。

### 調べた

最初は「記号除去後に空白が連続してハイフン2個になる」という仮説を立てたが、GitHub の実際のスラッグ生成（`github-slugger`、[GitHub上のソース](https://github.com/Flet/github-slugger/blob/main/index.js)で確認）は `value.replace(規則で記号を除去, '').replace(/ /g, '-')` という単純な処理で、**連続するハイフンをまとめる処理は無い**ことが分かった（仮説は誤り）。

**本当の原因は `getAnchor()` 側ではなく、共通で使っている `getPlainText()`（`src/html2md/htmlutil.ts`）側だった。**`getPlainText()` はタグを無条件に空白1個へ置き換える（`html.replace(/<[^>]+>/g, ' ')`）。見出しの中で `（<code>-c</code>` のように**タグの前後に元々空白が無い**場合、タグを消すたびに余計な空白が生まれる。`getAnchor()` がその空白をハイフンに変換するため、`-c` 自身が持つハイフンと連続して `--c` のような二重ハイフンになり、GitHub の実際のアンカーとずれる。GitHub 側はレンダリング後のテキストをそのまま使うため、タグの境界だからといって空白は入らない。

> [!IMPORTANT]
> **このプロジェクト自身も対象。**`issues.html` 自身が、バッジと id の間に空白を置かない書き方（`<span class="badge...">済</span><span class="no">i260830-01</span>`）を使っている。他プロジェクト固有の問題ではなく、このプロジェクトが将来 `md-flat` を使えば同じ壊れ方をする位置にあった。

### 直した

✅ **済** `getPlainText()` の全呼び出し（9箇所）を洗い出したところ、**アンカー計算に使っているのは3箇所だけ**（section の h1 タイトル・id 付き h2/h3・`i260921-01` で追加した md-flat details の summary）で、残り6箇所は空文字判定や緩い文言存在チェックのみで影響が無いと確認した。

アンカー計算専用に **タグ境界に空白を入れない** `getAnchorText()` を新設し、影響する3箇所だけ差し替えた（既存の `getPlainText()` は他6箇所のためそのまま残した）。テストケース `tests/cases/anchor-adjacent-code/`（`-c` と同じ構造で再現）を新設し、修正前のコードで実際に `--c-` のアンカー切れが起きることを確認したうえで修正し、直ることを確認した。全体テスト・型チェック・文字コード検査は確認済み。

✅ **済** 2026-09-23、報告元（`ai-chat-lite`、public ルーム #1037）が実際のページで検証し、アンカー切れが0件になったことを確認。OK が出たため「済」にする。
