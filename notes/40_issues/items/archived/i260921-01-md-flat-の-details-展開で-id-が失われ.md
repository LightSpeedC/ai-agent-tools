2026-09-19、`ai-chat-lite` から報告（public ルーム #914、待受けを張り直した際に読んだ）。**`md-flat` を付けた `details` を数十件含む一覧ページ（この課題一覧のような形）を変換すると、内部の課題間リンク（`href="#i260830-09"` 形式）がほぼ全滅する**とのこと。報告元の実測: 同じファイルで `md-flat` 無しなら内部リンク切れ 0 件、有りだと 100 件超。

### 調べた

**報告のとおり。**`src/html2md/converter.ts` の `convertDetails()` は、`md-flat` のとき `summary` のテキストを `## ` 見出しへ展開するだけで、元の `<details id="...">`（`<section>`／`<li>` 等が持つ課題番号の `id`）を一切受け取っていない（呼び出し元 `convertBlocks()` も `inner` と `class` しか渡していない）。GitHub 側は見出しテキストを正規化した文字列から自動でアンカーを作るため、`「## 済 i260830-09 …」`のような見出しは `#i260830-09` という短いアンカーにならず、元の `id` を指すリンクが軒並み外れる。

> [!IMPORTANT]
> **このファイル（`issues.html` 自身）も対象。** `<details>` に `md-flat` は付けていないため今は影響を受けていないが、課題間リンク（i260910-02 等）を多用する構造そのものが、将来 `md-flat` を付けた瞬間に同じ壊れ方をする位置にある。

### 直し方（判断待ち）

報告元も「修正の方向性は判断をお任せします」としている。**生成される Markdown の形が変わる**（このツールを使う全プロジェクトに影響する）ため、共通ルール「判断が要るもの」に該当し、ここでは実装しない。

- <strong>A: 見出しの直前に明示アンカーを差し込む。</strong>Markdown 中に `<a id="i260830-09"></a>`（生 HTML）を1行足してから `## ` 見出しを続ける。GitHub は Markdown 内の生 HTML の `id` をアンカーとして解決するため、既存の `href="#i260830-09"` がそのまま生きる。`convertDetails()` に元要素の `id` 属性を渡す必要がある（呼び出し元の追加対応も要る）
- B: リンク側を書き換える。`href="#i260830-09"` を GitHub のスラッグ生成規則に合わせて動的に付け替える。バッジ・記号（✅ **済** 等）を含む見出しの正規化規則を追随させ続ける必要があり、GitHub 側の仕様変更に弱い

A の方が実装が閉じており壊れにくいと見ていたが、実装時にコードを読み直したところ、**このプロジェクトは既に「見出しの id → 実際に生成されるアンカー」を事前計算するマップ（`buildAnchorMap()`）を持っており、`<section>` の h1 と id 付き `<h2>`/`<h3>` は既にこの経路でリンクが正しく張り替わっている**ことが分かった。案A（生 Markdown に `<a id>` を追加）は生成される Markdown の中身が変わるが、**この既存のマップを `md-flat` の `<details>` にも拡張する形なら、生成される Markdown は一切変えずに直せる**（見出し自体の出力は変わらず、それを指すリンクの `href` だけが正しいアンカーへ書き換わる）。

### 決定・実装（2026-09-22）

利用者の判断: **1-A**（上記の拡張マップ方式を採用）、**2 広げる（B: `<details>` 自身に `id` が無くても、直接くるむ `<li>`／`<section>` の `id` を拾う）**、**3 テスト追加**。

✅ **済** `src/html2md/converter.ts` の `buildAnchorMap()` に `collectFlatDetailsAnchors()` を追加。`section`・`li`・`div`・`ul`・`ol` を辿りながら「直近の id 持ちの li/section」を運び、`md-flat` の `details` に着いた時点で自分の `id` が無ければそれを使う。テストケース `tests/cases/flat-details-anchor/`（直接 id・section 経由 id の両方）を新設し、`tools/40_test/run-tests.ps1` に登録。全体テスト・型チェック・文字コード検査は確認済み。

<strong>実装時に踏んだ落とし穴。</strong>最初 `<li id="..."><details class="md-flat">`（`li` で `details` をくるむ形）でテストを書いたが、このプロジェクトの実装では `li` の中身は見出しへ展開されず地の文として1行にまとめられる仕様だった（`md-flat` の対象外）。`section` でくるむ形に直してテストを作り直した。

✅ **済** 2026-09-23、報告元（`ai-chat-lite`、public ルーム #1037）が実際のページで検証し、アンカー切れが0件になったことを確認。OK が出たため「済」にする。
