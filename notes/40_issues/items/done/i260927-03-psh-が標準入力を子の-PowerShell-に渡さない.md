**2026-10-03 に `ai-agent-rules` から不具合として報告があった（ai-chat-lite #1327）。**`echo hello| psh probe.ps1` で `[Console]::In.ReadToEnd()` が 0 文字（`--pwsh` も同じ）、`powershell -File` を直接呼べば 7 文字。<strong>標準入力の JSON を読む ps1（Claude Code のフック等）を psh 経由で試すと、入力が空のまま正常終了し、動いたように見える。</strong>報告元の期待は「標準入力を ps1 へ引き継ぐ。引き継がない仕様なら資料に書く」。

`src/psh/psh-main.ts` は PowerShell を起動した直後に `child.stdin.end()` で標準入力を閉じる（Rust 版 `src/psh-rs/src/psh-main.rs` は `Stdio::null()` で最初から渡さない）。<strong>そのため `echo abc | psh foo.ps1` の `abc` は ps1 に届かない。</strong>ps1 から見た標準入力は最初から空（EOF）になる。

<strong>利用者が決めた仕様ではない。</strong>追加時（`68a15ff`、2026-09-12）の `spawnSync` も入力を渡しておらず、spawn へ移したとき（`de1ef3b`、2026-09-13）に AI エージェントが明示的に閉じる形にした。理由は「閉じないと相手が入力を待って止まる。Claude Code の Bash ツールは対話的な入力を返せない」。計画書・課題に決めた記録は無い。

決めること:

- 標準入力をどう扱うか（常に子へ渡す／リダイレクトされているときだけ渡し、端末のときは閉じる、など）
- 止まる問題への備えをどこに置くか（入力を渡すと、端末から起動した場合に子が入力を待ちうる）
- 同じく `child.stdin.end()` を持つ `check-public` を揃えるか

<strong>決めたこと（2026-10-03、利用者の判断）。</strong>標準入力は常にそのまま子へ引き継ぐ（`powershell -File` を直に呼んだときと同じ）。`check-public` はそのまま。

はじめは「パイプやファイルのときだけ渡し、端末のときは閉じる」と決めたが、閉じる理由（Claude Code の Bash ツールは入力を返せない）が実測で崩れたので改めた。Bash ツールの標準入力は端末ではなく NUL で、読めばすぐ EOF になる。また Windows の node では、パイプも `isFIFO()` が偽になり、パイプかどうかを見分けられない。

- [済] TS 版は `stdio: ['inherit', 'pipe', 'pipe']`、Rust 版は `Stdio::inherit()` にした。テスト 13（パイプの入力が届く ・ `-c` でも読める ・ 空の入力で止まらない）を先に書き、落ちるのを見てから直した。全テスト成功。cmd から `echo hello| psh stdin.ps1` で 5.1 ・ 7 とも届くことを確かめた
- [済] `TOOLS-USAGE.html` の psh の章に「標準入力は ps1 に渡る」を足した
- [済] **人が窓から呼ぶと止まった**（利用者が確かめた）。PowerShell は自分専用のコンソールにいるので、窓の入力を引き継ぐと窓のキー入力を読み続け、Ctrl+C も届かず、窓ごと操作できなくなった
- [済] **出力先が窓なら、PowerShell を同じ窓で `-File` のまま起動し、入出力をすべて引き継ぐ形にした**（利用者の判断）。直に呼んだのと同じ動きで、窓のコードページも変えない。出力先がパイプやファイルなら今までどおり（自分専用のコンソール ・ 65001 ・ 受け取って直す）で、そのとき標準入力が窓なら渡さない。TS 版 ・ Rust 版とも。自動のテストは出力がパイプの側だけを確かめている
- [済] 窓から使う側の動きを、利用者が cmd の窓で確かめた（2026-10-03）。打った文字が ps1 に届く（`[abc]`）・ Ctrl+C で止まりプロンプトに戻る ・ `psh -c "'日本語の表示'"` が化けない

<strong>報告元の確認（2026-10-03、ai-chat-lite #1332）。</strong>cmd から `echo hello| psh probe.ps1` が 5.1 ・ 7 とも届き、`type file | psh probe.ps1` も届いた。標準入力の JSON を読むフック用の ps1 も、psh 経由で期待どおり動いた。

関連: psh は子の出力を終わるまでまとめて受け取ってから流すため、`psh ... | 次のコマンド` には逐次には流れない。
