✅ **済** 2026-09-12 に実施した。`convert-encoding` に **`--check`** を足し、`--info` がフォルダを受けるようにした。

### なぜ

道具を作ったのに、<strong>同じ話（BOM が落ちた・改行が LF になった）を何度も繰り返していた。</strong>気づく手段が人の目しか無く、`.gitattributes` の正規化のせいで `git status` にも `git diff` にも出ない場面がある。**見つける側を機械に寄せた。**

| 足したもの | 内容 |
|---|---|
| `--check` | **規約に合わないものだけ**を出す。1 件でもあれば終了コード 1 |
| `--info` の拡張 | フォルダを受け、その下を再帰して**全件**出す。終了コードは常に 0 |
| 絞り込み | `--include` ・ `--exclude` ・ `--exclude-dir`（カンマ区切り可）。既定の除外に**足す** |
| 全テストへの組み込み | `run-all-tests.ps1` の最後で `--check` を回す。違反があれば全体を失敗にする |

あるべき組は**拡張子で決まる**。表に無い拡張子はすべて「BOM 無し UTF-8 ＋ LF」として見るので、**今後 ts ・ js ・ mjs ・ json が増えても表を直さずに済む**。仕様は [convert-encoding の計画](../10_plan/p260906-01-convert-encoding.md)に書いた。

テストを先に書いてから実装した（8 件が落ちる状態を作ってから着手）。最終は **123 件すべて成功**。

### 入れてすぐ見つかったもの

| 件数 | 中身 | 原因 |
|---:|---|---|
| 15 | `tests/golden/*/expected.txt` が CRLF | `WriteAllLines` が `Environment.NewLine` で書いていた。**生成側（`-UpdateGolden`）を LF に直した** |
| 8 | 日本語を含まない `cmd` が「SJIS でない」と出た | 誤検知。**純 ASCII は UTF-8 と SJIS でバイト列が同じ**ので違反にしない、と直した |

> [!TIP]
> <strong>検査を足した回に違反が見つかるのは、検査が効いている証拠。</strong>15 件は `.gitattributes` の `eol=lf` で正規化されるため、git の差分には一度も出ていなかった。

### そのあと直した 3 点

同じ日に、表示と判定の作りを見直した。**どれも「検査が誤解を招く／誤検知する」たぐい**で、放っておくと検査そのものが信用されなくなる。

| 直した点 | 前 | 後 |
|---|---|---|
| 表示を小文字に | `SJIS` `UTF8BOM` `CRLF=47` | `sjis` `utf8bom` `crlf=47`。**`--to` ・ `--from` に書く綴りと同じ**になり、出た名前をそのまま指定へ渡せる。`text` は元から小文字で、`convert-encoding` だけが揃っていなかった |
| 純 ASCII は `ascii` | `check-contrast.cmd  UTF8` | `check-contrast.cmd  ascii`。**「cmd なのに utf8」と読めてしまう**のを止めた。判定する組は増やさず（`--from ascii` は受けない）、見せ方だけ変えた |
| 規約の無い拡張子の改行 | すべて LF を要求 | **改行を定めた拡張子だけ見る。**`txt` ・ `log` ・ `csv` は問わない。ただし**混在と単独 CR はどの拡張子でも違反**のまま |

> [!IMPORTANT]
> **3 点目は、手で CRLF にした `txt` が毎回違反に出るという指摘から。**`.gitattributes` の `* text=auto eol=lf` で git に入る時点で LF に正規化されるため、<strong>作業ツリーの改行まで縛る実益が薄い。</strong>縛ると本当の違反（`ps1` の BOM 落ち等）が埋もれる。**文字コードは git が変換しない**ので、そちらは拡張子によらず見る。

あわせて、あるべき組の呼び名を**拡張子そのもの**にした（`→ ts は utf8+lf`）。用途名の無い `ts` ・ `md` を「既定」と呼んでいて、何に対する規約か読めなかった。

テストは先に書いて 17 件落ちるのを見てから実装した。最終は **convert-encoding 140 件 ・ text 55 件すべて成功**。

> [!TIP]
> <strong>純 ASCII の扱いは 2 回目の検討。</strong>1 回目（i260908-05 ）では「`ascii` を組として導入するか」を検討して見送った。今回入れたのは**表示だけ**で、判定する組は増やしていない。見送りの理由だった「ascii と判定したファイルに日本語を足す `text edit` が止まる」は、表示だけなら起きない。
