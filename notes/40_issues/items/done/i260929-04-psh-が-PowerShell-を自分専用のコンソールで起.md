psh（TypeScript 版 ・ Rust 版とも）は、2026-09-29 から PowerShell を**自分専用のコンソール**（`CREATE_NO_WINDOW`。TypeScript 版は `windowsHide`）で起動し、最初の 1 行でそのコンソールを 65001 にしている。そのため ps1 は `-File` ではなく `-Command` の中から呼ぶ。

<strong>理由。</strong>PowerShell は ps1 の中で取り込んだ外部コマンドの出力を、自分のコンソールのコードページで文字列にする。呼び出し元の窓を引き継ぐと、呼び元しだいで 65001（bun が窓を変える）にも 932 にもなり、結果が揃わなかった。UTF-8 に固定することは利用者が決めた（計画 [p260929-01](../10_plan/p260929-01-psh-rust.md)）。

**引き換えになること。**

- SJIS を出すもの（SJIS の cmd 等）を ps1 の中で取り込むと化ける
- `exit` を書かない ps1 の最後で外部コマンドが失敗すると、`-File` の 0 ではなく、その終了コードが返る
- PowerShell が窓を持たないため、窓の大きさを調べる ps1（`$Host.UI.RawUI.WindowSize` 等）は既定の値を返すと思われる（未確認）
- プロセスが 1 つ増える（`conhost`。約 4 MB）

決めること: 別のコンソールで起動しない ・ `-File` のまま使える方法を探すか、いまの形を続けるか。**いったん今の形にすることは利用者が決めた（2026-09-29）。**

**2026-10-03 から、出力先が窓（端末）のときは当たらない**（i260927-03）。そのときは PowerShell を同じ窓で `-File` のまま起動し、コードページも変えない。この課題が残るのは、出力先がパイプやファイルのときだけ。

✅ **済** <strong>2026-11-01、70-A (利用者の判断)。</strong>いまの形を続け、上の引き換えを許容して閉じる。`-File` のまま使える別の方法は探さない。引き換えは、出力先がパイプやファイルのときだけに限られる (窓の大きさの件は、未確認のまま)。実装は変えない。
