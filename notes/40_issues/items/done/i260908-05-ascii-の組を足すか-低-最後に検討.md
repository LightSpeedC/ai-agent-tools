0x20〜0x7e と改行だけで構成されるファイルは、自動判定で `utf8` になる（`sjis` にはならない）。純 ASCII は UTF-8・SJIS のどちらでもバイトが同じなので実害は無いが、**cmd でも `sjis` と出ない**のが直感に合わない場面がある。

**案**: `ascii` の組を設け、純 ASCII のファイルは `ascii` と表示・扱う。read/find のヘッダー表記や、cmd 判定の分かりやすさが上がるか検討する。

✅ **済** 2026-09-08 に<strong>やらないと決めて閉じた。</strong>ascii は機能的に UTF-8・SJIS と等価なので、足しても読み・書き・編集の結果は変わらない。「cmd が sjis と出ない」問題も、内容だけからは解決できない（拡張子を見ない限り原理的に判定不能）。**むしろ ascii を組として本格導入すると、ascii 判定のファイルに日本語を足す edit で exit 5 になる縁が増える**。表示だけ ascii にする案（判定は utf8 のまま）も検討したが、得るのは表示の正直さだけで見送った。
