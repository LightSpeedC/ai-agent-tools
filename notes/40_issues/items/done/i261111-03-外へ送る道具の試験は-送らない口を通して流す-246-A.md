振り返り r261111-01 の候補 246。check-markdown の試験で Red を見た 1 回に、材料の md 2 つを GitHub の API に送った。直す: check-markdown に、送り先を差し替える (または送らずに止める) 環境変数を作り、試験はそれを通して流す。共通ルール「テストのルール」に 1 行足す案を出す (書き込みは利用者の指示を待つ)。

今ある動き: check-markdown は md を `https://api.github.com/markdown` に POST し、返る HTML の `**` を数える (OK なら終了 0、`**` が残れば 1、送れなければ「検証できません」で 2)。トークンは環境変数 `GITHUB_TOKEN` ・ `GH_TOKEN` か `gh auth token` から読み、引数では受けない。`.gitignore` で外した md は送らない。試験 `run-check-markdown-tests` はトークンの受け方と `.gitignore` の分だけを守り、送る経路 (OK ・ `**` が残る ・ HTTP エラー) は守れていなかった。未設定なら、これまでどおり GitHub に送る。

決定: i261111-03-d2 (265-A 環境変数 `CHECK_MARKDOWN_ENDPOINT` で送り先を差し替える。ローカルだけ許し、トークンは付けない)。

## やること

- [済] `CHECK_MARKDOWN_ENDPOINT` を実装し、使い方の文 ・ TOOLS-USAGE を更新
- [済] 共通ルール「テストのルール」に足す 1 行の案を出す
- [済] 共通ルール「テストのルール」へ反映する (利用者の指示を待つ)
