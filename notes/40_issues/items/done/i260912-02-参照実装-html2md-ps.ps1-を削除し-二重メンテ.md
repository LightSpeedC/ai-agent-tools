| やったこと | 内容 |
|---|---|
| 照合の置き換え | **消す前に、exe と ps1 が 15 ケースすべてで一致していることを確認**し、その出力を `tests/golden/` に固定した。出力そのものに加えて、終了コードと検査の指摘（★ の行）も固定している |
| 期待値の作り直し | `run-tests.ps1 -UpdateGolden` を足した。**出力を変える修正を入れたら、差分を目で確かめてから更新する** |

| テストの手当て | `run-tests.ps1` から ps1 の実行と比較を外した。`run-convert-encoding-tests.ps1` の往復変換の対象を `run-tests.ps1` に差し替えた |
| 資料 | README ・ USAGE から参照実装の記述を外し、期待値による担保の説明に置き換えた |

全テスト成功（html2md 15 ・ convert-encoding 102 ・ text 53）。

> [!IMPORTANT]
> <strong>担保の形が変わった。</strong>これまでは「2 本の独立した実装が同じ出力を出す」ことで守っていたが、いまは「1 本の出力が、固定した期待値と同じ」になる。<strong>期待値は exe 自身の出力から作っているので、exe の誤りは期待値にも写る。</strong>出力を変える修正のときに差分を目で確かめることが、唯一の関門になる。

### もとの記録

2026-09-12 の方針。**`html2md-ps.ps1` を削除し、実装を exe の 1 本にする。**

### なぜ

[html2md のベンチ](../../tools/90_misc/bench-html2md/処理系比較-html2md.md)で、**実際の資料 9 ファイルの変換に 29.6 秒**かかることが分かった。exe の 67 倍、Bun へ移した版の 370 倍。**参照実装として置いていたが、この速さでは道具として使えない。**

もう一方の代償が二重メンテ。<strong>変換の修正はすべて 2 箇所へ入れている。</strong>2026-09-11 から 09-12 だけでも次のとおり。

- md-skip の残る 3 経路（i260911-01 の medium 1）
- summary の強調・`span.no` ・ `md-flat`（タグ対応仕様の決着 12）
- 生成物の改行を LF にする（i260911-01 の medium 11）
- リンク解決の食い違い（i260911-02 の 6）

> [!WARNING]
> **ただし ps1 は、テストが exe を照合する相手でもある。**`run-tests.ps1` は 15 ケースすべてで<strong>「exe と ps1 の出力が完全に一致すること」</strong>を確かめており、これが変換の品質を担保する要になっている。**消すと、その担保が無くなる。**

### 決めること

| # | 決めること | 案 |
|---|---|---|
| 1 | **照合の相手をどうするか** | 期待する Markdown をファイルとして `tests/` に置き、それと突き合わせる（ゴールデンファイル）。**2 本の実装を比べる形から、1 本と期待値を比べる形へ変わる** |
| 2 | 消す前にゴールデンを作るか | <strong>作る。</strong>いまの ps1 と exe が一致している状態で固定すれば、期待値の正しさを 2 本で裏取りできる。消してからでは取れない |
| 3 | Bun へ移す計画と、どちらを先にするか | i260912-01 の結論次第。**exe を Bun へ移すなら、ps1 を消す前にゴールデンを作っておくと移行の照合にも使える** |

### やること

1. ゴールデンファイルの仕組みを `run-tests.ps1` に足し、いまの出力で固定する
2. `html2md-ps.ps1` ・ `html2md-ps.cmd` を削除する
3. `run-tests.ps1` から ps1 の実行と出力比較を外す
4. `run-convert-encoding-tests.ps1` が `html2md-ps.ps1` を往復変換の対象にしているので、別のファイルに差し替える
5. README ・ USAGE ・ 共通化計画から参照実装の記述を外す

> [!IMPORTANT]
> <strong>削除は最後にする。</strong>ゴールデンの仕組みが動いてから消す。順序を逆にすると、担保が無い期間ができる。
