2026-09-27、ai-chat-lite で共通ルール更新の周知（public ルーム #1238、`20260726-claude-move-folder` より）。「標準出力は UTF-8 に揃える」が<strong>「コンソールのコードページを変更しない」に置き換わり、`chcp`・`[Console]::OutputEncoding`・`Console.OutputEncoding`・`SetConsoleOutputCP`／`SetConsoleCP`（FFI・P/Invoke 経由も含む）の使用がすべて禁止</strong>になった。新ルールは代わりに、**リダイレクトされている分だけ自分の読み書きを個別に差し替える**方式（C# の `Console.SetOut` 例が本文に載っている）を求めている。周知本文に「既存の ps1・C# に該当箇所があれば見直しが必要」と明記されていたため、このプロジェクト自身の使用箇所を調査した。

### 調査結果

`text find --recurse` で `OutputEncoding`・`SetConsoleOutputCP`・`SetConsoleCP`・`chcp` を検索。

| 言語 | 該当箇所 | 形 |
|---|---|---|
| PowerShell（ps1） | 10 ファイル（`bin/codex-trusted.ps1`、`tools/40_test/` 5 本、`tools/60_release/build-release.ps1`、`tools/90_misc/check-markdown-ps.ps1`、`tools/90_misc/bench-*/run-bench.ps1` 2 本） | `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` を param 直後に置く形 |
| C# | 3 ファイル（`src/ConvertEncodingCs/Program.cs`・`src/Html2MdCs/Program.cs`・`src/TextCs/Program.cs`） | `Console.OutputEncoding = Encoding.UTF8;` を `Main` 先頭に置く形 |
| TypeScript（bun/node） | 0 件 | `SetConsoleOutputCP` は `src/lib/win-console.ts` のコメントに言及があるのみで、**実装としては呼んでいない**（下記参照） |

> [!IMPORTANT]
> <strong>課題 i260917-01 の記録と現物が食い違っていた。</strong>記録には「`SetConsoleOutputCP(65001)` を明示的に呼んで修正」とあるが、現在の `src/lib/win-console.ts` は逆に「**コードページはここでは扱わない。呼んでも `chcp` で見える値が変わらないことを実機で確認したため、効かない API として扱っている**」とコメントしている。実装がのちに直され、記録側が古いまま残っていたと見られる。`less`・`psls` の日本語表示は VT100 有効化（`ENABLE_VIRTUAL_TERMINAL_PROCESSING`）によるもので、コードページ変更には依っていない。**TypeScript 側は既に新ルールに沿っている。**

### 外部の調査資料（ai-agent-rules 側）による裏付け

利用者の指示で `ai-agent-rules` の `notes/01_research/r260927-01-コンソールのコードページ問題.html`（このプロジェクトの外のため、詳細は直接参照しない）を確認した。実機検証（cmd の窓・Bash 経由・パイプでの同時実行・Ctrl+C 等）に基づく調査で、新ルールの根拠になっている。要点:

- **出力コードページの変更はプロセスが終わっても窓に残り、隣の SJIS の cmd・.NET Framework の exe を化けさせる**（実測）。`finally` で戻す方式も、Ctrl+C・強制終了・パイプでの同時実行では戻せないことがある（後から始めた側が先の側の変更後の値を「元の値」として控えてしまうため）
- **推奨は「窓に触らず、リダイレクトされている分だけ個別に差し替える」方式（新ルール本文の案 A）**。標準出力・標準エラー・標準入力の 3 本は別々に検知・差し替えが要る（`IsOutputRedirected`／`IsErrorRedirected`／`IsInputRedirected` と、対応する `SetOut`／`SetError`／`SetIn`）。**標準エラーだけ差し替え忘れると `2>&1` で化ける**という実測結果あり
- **ps1（5.1・7 とも）も C# と同じ API で書ける**（`[Console]::IsOutputRedirected`・`[Console]::SetOut` 等）。Bash から実測して 3 本とも化けないことを確認済みとのこと（窓での確認は未了、と資料に明記）
- <strong>node は窓に触らない（bun は動いている間だけ窓を変え、終了時に戻す）</strong>ため、`less`（node 専用ランチャー）はこの問題の対象外。`psh` はソース自体は窓に触らないが、bun 優先で動くランチャーのため bun 実行時は窓に触れる

### 決定・実装（2026-09-27）

利用者の判断: **C# は資料どおり、PowerShell は案 A（`IsOutputRedirected` 等を見て個別に差し替える）**。

✅ **済** C#（3 ファイル）: `Main` 先頭の `Console.OutputEncoding = Encoding.UTF8;` を、資料のコードそのまま（`IsOutputRedirected`／`IsErrorRedirected`／`IsInputRedirected` を見て `SetOut`／`SetError`／`SetIn` を UTF-8 の `StreamWriter`／`StreamReader` に差し替える）に置き換えた。3 本ともビルドが通り、Bash から `--help` を呼んで日本語が化けないことを実測で確認した。

✅ **済** PowerShell（10 ファイル）: `[Console]::OutputEncoding = UTF8` の 1 行を、`[Console]::IsOutputRedirected`／`IsErrorRedirected`／`IsInputRedirected` を見て `[Console]::SetOut`／`SetError`／`SetIn` を UTF-8 の `StreamWriter`／`StreamReader` に差し替える形に置き換えた。**調査時点では 11 ファイルと数えていたが、実装時に数え直したところ 10 ファイルだった**（件数の訂正）。

✅ **済** 全体テスト（bun・node）・型チェック・文字コード検査、いずれも規約どおりで成功。`text` の C# 版で 6 件失敗が出たが、**変更前のコードに戻して同じ失敗が再現することを確認済み**（`find` の既定除外フォルダ・`edit` の読めないバイト拒否が TypeScript 版と食い違う、今回の変更とは無関係の既存の乖離）。`check-markdown-ps.ps1`・`build-release.ps1` も個別に実行し、Bash から日本語が化けないことを確認した。
