変換仕様の未決事項

タグ対応仕様の第 5 章に挙げた論点のうち、まだ決まっていないもの。実装を変えるときは先に方針を決める。

済20260830-01caption が出力されない

<table> の中にある <caption> が Markdown に出ない。表の処理が thead と tbody しか見ていないため、caption に到達しない。

36 ケースの実測で唯一残った欠落。Markdown のテーブルにキャプションの記法が無いので、表の直前か直後の段落にする必要がある。どちらに置くかを決める。

済2026-09-01 に対処。表の直前の段落にした。見出しとして読めるのは前に置いたときなので、figure の figcaption と同じ形に揃えた。

着手20260830-02ブロックとして扱っていないタグの構造が失われる

次のタグは BlockTags に無いため、中身が地の文として 1 つに連結される。テキストは消えないが構造は失われる。

タグいまの出力本来あるべき形
main article aside header5 つが 1 段落に連結されるdiv と同じ「中身を処理する」扱い
dl dt dddt と dd が連結されるMarkdown に定義リストは無い。箇条書きか表に落とす
details summary連結されるGitHub は HTML のまま解釈するので、そのまま残す手もある
hr消える---。ただし記号を足さない方針との兼ね合いがある

main 系の 4 つは BlockTags に足すだけで済む。dl と details は落とし方を決める必要がある。

済2026-09-01 にテキストを落とさない対処を入れた。hr を除くすべてを走査の対象に加え、dt dd summary も個別に挙げて項目ごとの段落にした。address と caption も同時に対応した。

未構造そのものは捨てたままにしている。定義リストを箇条書きか表に落とすか、details をタグのまま残すかは決めていない。テキストが読めるようになったので急がない。

未hr は対象外。テキストを持たないため「中身を落とさない」の対象にならず、--- を出すのは記号を足さない方針に触れる。

済20260830-03章の外で見出しの段が飛ぶ

章（section）の外に h2 と h3 を並べると ### が抜ける。

入力章の中章の外
h2#####
h3########

h2 だけが章の内外で段を変え、h3 は変えていない。章の外の h3 を ### にするか、h2 を章の中と同じ ### に統一するかを決める。

済2026-09-01 に対処。章の外の h3 以下も 1 段上げる形にした。章の外の見出しは章と同じ立場なので、h2 を ## にする判断を残し、同じ調整を h3 以下に通した。調整は 1 か所に寄せ、h2 だけが持っていた分岐は消した。

済20260830-04意味を持つインラインタグが平文になる

del ins sup sub mark kbd abbr small q cite time はタグが消えて中身のテキストだけが残る。取り消し線や上付きの区別は Markdown に出ない。

GitHub は ~~取り消し線~~ を解釈するので del は記法にできる。sup sub kbd は HTML のまま残す手もある。どこまで対応するかを決める。

済2026-09-01 に対処。del は ~~、GitHub で生き残るタグ（ins sup sub mark kbd q）はタグのまま残す。~~ も ** と同じ前後判定を受けるため、強調と同じセンチネル方式に載せた。成立しない位置では <del> で出る。

どのタグが残るかは実測で決めた。11 個すべてタグで出す実装にしたあと api.github.com/markdown へ投げたところ、abbr small cite time の 4 個は除去された（中身のテキストは残る）。表示に効かないため平文に落とすことにした。

この対応で退避の仕組みに潜んでいた欠陥が表面化した。キーの両端が同じ制御文字だったため、2<sup>10</sup> のように数字が隣接すると偽のキーができ、別の退避内容に置き換わっていた。両端を別の文字にして直した。

PowerShell 学習資料からの要求

N:\2026\20260822-powershell-pwsh-learn からの要求。詳細は root の req-01-from-powershell.md にある。優先度は要求元が付けたもの。

未20260830-05章カード（.chapters）を表にする ［高］

<ul class="chapters"> の中の span 3 つが連結され、リンクのラベルが 1 本の長い文字列になる。

- [第1部 基礎編 01. PowerShell の生まれた経緯 DOS・Bash・Node.js と比較しながら、…](docs/01-背景.md)

要求は 3 列の表にすること。ヘッダ行の「章」「タイトル」「内容」が HTML のどこにも無いのが論点で、そのまま実装すると html2md 自身の「HTML に無い文言」検査に毎回引っかかる。

案は 4 つある。HTML 側にヘッダを持たせる（data-columns）／ HTML 側を最初から表にして CSS でカード表示にする／表にせず区切りを入れた箇条書きにする／固定文言を足して検査の対象外にする。HTML 側を表にする案が最も筋が良いと考えている。変換器・検査・ルールのどれにも手を入れずに済むため。

済20260830-06.html → .md の書き換えを変換対象だけに絞る ［高］

いまは相対リンクの .html をすべて .md に置き換えている。変換対象でない HTML へのリンクまで書き換わり、存在しないファイルを指す。

変換対象のファイル一覧は既に持っているので、その集合に含まれるものだけを書き換えるようにする。

済md-skip のページの分は 2026-09-01 に対処した。変換より先に md-skip のページを洗い出し、その一覧にあるリンクは .html のまま残す形にした。

済2026-09-02 に残りも対処した。判定を裏返して「この実行で .md ができるページの一覧」を持つ形にした。一覧にあるものだけ置き換え、無いものは .html のまま残す。md-skip のページも探索フォルダの外も、同じ 1 つの判定で片付く。

未20260830-07他ファイルへのアンカーをスラッグに変換 ［高］

同一ファイル内の #chNN は見出しアンカーに張り替えているが、他ファイルへのリンクのアンカー部分は変換していない。

[03.2 実行ポリシー](docs/03-実行環境.html#ch02)
  ↓ いま
[03.2 実行ポリシー](docs/03-実行環境.md#ch02)     ← 飛ばない
  ↓ あるべき
[03.2 実行ポリシー](docs/03-実行環境.md#032-実行ポリシー--なぜ動かないのか)

変換対象すべてのアンカーマップを先に作り、リンク先のファイルのマップを引く形にする必要がある。いまはファイルごとに独立して変換しているため、構造を変えることになる。

未20260830-08画像の相対パスを出力位置から計算 ［中］

いまは切り出した SVG を images/ 固定で参照している。画像を 1 か所に集約する構成では、出力先の階層によって相対パスが変わる。

md の位置画像への相対パス
README.mddocs/images/
docs/01-背景.mdimages/
docs/plan/構成案.md../images/

要求元は「ルート直下か否か」の 2 分岐で書いて 3 階層目で壊れた経験がある。出力先からの相対パスを毎回計算する。

未20260830-09章間ナビを冒頭にも出す ［中］

<footer> の内容は末尾に出るが、冒頭には出ない。900 行を超える章があり、次の章へ行くのに末尾までスクロールすることになる。

ナビを持たないページ（README）には出さない判定が要る。要求元は「前章」「次章」「目次に戻る」を含むかで判定している。

済20260830-10SVG 切り出し時に CSS 変数を解決する

デザインルールは stop-color="var(--accent)" の書き方を前提にしているが、SVG を単体ファイルに切り出すと変数が解決されず色が失われる。

<section class="ch03">
	<svg><linearGradient id="g-03-1a">
		<stop stop-color="var(--accent)"/>    ← .ch03 の定義が要る
	</linearGradient></svg>
</section>

<style> から .chNN { --accent: … } を読み、切り出す svg の祖先 section のクラスと突き合わせれば静的に解決できる。@media と JS による上書きは対象外とする。

ルールに従って書いた HTML ほどこの問題を踏む。この html2md 自身の図はリテラルの hsl() で書いていたため表面化していなかった。

済2026-09-02 に対処。上の方針どおり実装した。定義も既定値も無いものは書き換えずに残す（消すと図が壊れるより、そのままのほうが気づける）。@media の中はブロックごと落としてから読む。

フォールバックの取り出しは括弧を数えている。var(--x, hsl(280,78%,25%)) のように既定値の中に括弧が入ると [^)]* では途中で切れて壊れる。

あわせて、テストが .md しか比べていなかったのを直し、切り出した .svg も exe と ps1 で突き合わせるようにした。既存 6 プロジェクトの SVG に var( を含むものは無く、影響は出ていなかった。

済20260830-16exe を git に含めるか

いまは .gitignore の *.exe で除外している。ビルド後にサイズを測り、小さければ含める方向で再検討すると決めていた。

現在のサイズは 35 KB 程度。含めれば clone 直後にビルドせずに使える。含めなければ差分の読めないものが履歴に残らない。

済2026-09-02 に含めないことに決めた。.gitignore の *.exe をそのまま残す。

サイズは小さいまま（実測 40 KB）だが、変えるたびに差分の読めないものが履歴に積む。build.cmd を 1 回実行すれば作れるので、clone 直後に使えないことの不便は小さい。

一度も追跡していないため、履歴の書き換えは要らない。.gitignore に書くだけでは追跡済みのファイルは外れないが、この exe は最初から対象外だった。

未20260830-18PowerShell の配列の受け取り方をルールに追記

CLAUDE.md の「PowerShellの落とし穴」には「関数から配列を返すときは return ,$array」とあるが、受け取り側の書き方が規定されていない。そこで踏んだ。

// 誤り1: foreach に直接渡すと、配列そのものが 1 要素として来る
foreach ($b in (Convert-Blocks ... )) { }

// 誤り2: @() で包むと外側が剥がれず、1 要素の配列（中身が配列）になる
$blocks = @(Convert-Blocks $body $ctx)

// 正しい: 代入だけにすると外側が外れる
$sub = Convert-Blocks ...

ps1 が出力 System.Object[] の 1 行だけになる、という形で表面化した。ルールに 1 行足す案を出したが、まだ提示していない。
