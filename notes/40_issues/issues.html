済i260912-03文字コードと改行の違反を、人が気づく前に落とす

済2026-09-12 に実施した。convert-encoding に --check を足し、--info がフォルダを受けるようにした。

なぜ

道具を作ったのに、同じ話（BOM が落ちた・改行が LF になった）を何度も繰り返していた。気づく手段が人の目しか無く、.gitattributes の正規化のせいで git status にも git diff にも出ない場面がある。見つける側を機械に寄せた。

足したもの内容
--check規約に合わないものだけを出す。1 件でもあれば終了コード 1
--info の拡張フォルダを受け、その下を再帰して全件出す。終了コードは常に 0
絞り込み--include ・ --exclude ・ --exclude-dir（カンマ区切り可）。既定の除外に足す
全テストへの組み込みrun-all-tests.ps1 の最後で --check を回す。違反があれば全体を失敗にする

あるべき組は拡張子で決まる。表に無い拡張子はすべて「BOM 無し UTF-8 ＋ LF」として見るので、今後 ts ・ js ・ mjs ・ json が増えても表を直さずに済む。仕様は convert-encoding の計画に書いた。

テストを先に書いてから実装した（8 件が落ちる状態を作ってから着手）。最終は 123 件すべて成功。

件数中身原因

同じ日に、表示と判定の作りを見直した。どれも「検査が誤解を招く／誤検知する」たぐいで、放っておくと検査そのものが信用されなくなる。
