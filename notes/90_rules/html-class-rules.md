## 1. この文書の使い方

html2md は HTML のクラス名を見て変換方法を決める。その名前をここで 1 つに固定する。変換側に設定ファイルを持たせて名前の違いを吸収する案は採らなかった。設定を用意すると、プロジェクトごとに名前が違う状態が固定されるためだ。

### 名前の決め方

<strong>読んで役割が分かる語を選ぶ。</strong>既存の採用数では決めない。

最初は 6 プロジェクトの集計で多数派を採る方針にしていたが、それでは名前が意味を伝えるかを見ないことになる。実際、数だけで決めた結果 `nw`（2 文字で何の略か追えない）・`sub`（subtitle とも subsection とも読める）・`meta`（範囲が広く、日付を指すと分からない）が残っていた。この 3 つは `nowrap` ・ `lead` ・ `date` に改めている。

ただし `badge` と `b-` シリーズは変えない。`b-ng` の NG は和製英語で、`b-` が何の略かも名前からは追えないが、6 プロジェクトすべてで定着しており、書き換えの量に見合わない。**意味で決めるのが原則、定着しているものは例外**という線引きになる。

集計の数値は第 8 章に載せた。移行の優先度を決める材料として使う。

> [!NOTE]
> <strong>ここに無いクラス名は変換に影響しない。</strong>装飾のためのクラスは自由に付けてよい。html2md はこの文書に出てくる名前だけを見て、それ以外は中身のテキストだけを拾う。

### 変換側が名前を見ない箇所

次の 2 つは、クラス名ではなく要素の構造で判断する。名前を揃える必要はあるが、変換の動作はクラス名に依存しない。

- 表の横スクロール用ラッパー。`div` の中に `table` があれば表として扱う。
- `div class="wrap"` や `div class="inner"` のような、位置合わせだけのラッパー。中身をそのまま処理する。

## 2. タイトルバー

ページ最上部の紺色の帯。文書のタイトルと補足、作成日・更新日を入れる。

```
<div class="titlebar">
	<div class="inner">
		<h1>文書のタイトル</h1>
		<p class="lead">何を書いた文書かの補足</p>
		<p class="date">📅 作成: 2026-08-29 / 更新: 2026-08-29</p>
	</div>
</div>
```

| クラス | 役割 | Markdown の出力 |
|---|---|---|
| `titlebar` | 帯そのもの | 中身を出す。帯自体は記法にならない |
| `inner` | 幅を揃えるためのラッパー | 中身をそのまま処理する |
| `lead` | タイトルの補足文（リード文） | 通常の段落 |
| `date` | 作成日・更新日 | `> 📅 作成: ... / 更新: ...` の引用行 |

タイトルバーの中の `h1` だけが `#` になる。章の `h1` は第 3 章のとおり 1 段下がる。

### 本文先頭の戻るリンク

`docs\` 配下の文書は、本文の先頭とフッターの両方にルートの `README.html` への戻るリンクを置く。帯の中には入れない。

```
<p class="backlink"><a href="../README.html">← 目次に戻る</a></p>
```

リンク先は常に `.html` と書く。`.md` への置き換えは html2md が行う。HTML 側で先に `.md` と書くと、HTML のリンクが壊れたまま Markdown 側だけ正しくなるので気づけない。

## 3. 章と見出し

章は `section` で囲み、`class` と `id` に同じ章番号を書く。番号はゼロ埋め 2 桁。

```
<section class="ch01" id="ch01">
	<h1>章のタイトル</h1>
	<h2>節</h2>
	<h3>小見出し</h3>
</section>
```

| HTML | Markdown | 備考 |
|---|---|---|
| `.titlebar h1` | `# タイトル` | 文書に 1 つだけ |
| `section > h1` | `## 1. 章名` | 連番が付く。番号は HTML に書かない |
| `h2` | `### 節名` | 章の外にある `h2` は `##` になる |
| `h3` | `#### 小見出し` |  |
| `h4` | `##### …` |  |

章の連番は html2md が `section` の出現順に振る。HTML 側に番号を書くと二重になる。

### ミニタイトルバー

章が 2 個以下になる構成では、紺色のミニタイトルバーを区切りに使い、その配下の項目見出しを `h1` にする。

```
<div class="minibar">第 1 部 基礎</div>
```

この形の文書では、見出しが全体で 1 段深くなる。`minibar` が `##` になり、配下の `h1` は `###`、`h2` は `####` になる。`minibar` が 1 つでもあれば文書全体でこの扱いになる。

## 4. 目次

目次は `div class="toc"` で囲み、中に `h2` と `ol` を置く。各項目は章の `id` へのページ内リンクにし、`li` に章と同じクラスを付ける（バッジの色を章に合わせるため）。

```
<div class="toc">
	<h2>目次</h2>
	<ol>
		<li class="ch01"><a href="#ch01">章のタイトル</a></li>
		<li class="ch02"><a href="#ch02">次の章</a></li>
	</ol>
</div>
```

Markdown では番号付きリストになり、リンク先は生成後の見出しアンカーに張り替えられる。`#ch01` は `#1-章のタイトル` のような形になる。番号は CSS カウンタと Markdown の両方で自動採番されるので、HTML には書かない。

> [!NOTE]
> **章の `id` は目次のために必要。**`id` が無い `section` は目次から張り替えられず、リンクが `#ch01` のまま残ってアンカー切れになる。

## 5. バッジ

バッジは `span` に `badge` と種別クラスを付ける。色でしか区別していない情報なので、Markdown では記号と太字の文字情報に落とす。

```
<span class="badge b-ok">完了</span>
<span class="badge b-ng">未対応</span>
```

### 状態を表すバッジ

| クラス | 見え方 | 意味 | Markdown の出力 |
|---|---|---|---|
| `badge b-ok` | ✅ **完了** | 良い・完了・可 | `✅ **完了**` |
| `badge b-ng` | ❌ **未対応** | 悪い・リスク・不可 | `❌ **未対応**` |
| `badge b-warn` | ⚠ **要注意** | 警告・注意 | `⚠ **要注意**` |
| `badge b-none` | **未実施** | 未実施・対象外・該当なし | `**未実施**` |

**記号は太字の外に置く。**`**✅ 完了**` と書くと、強調の内側の先頭が記号になる。`✅` は Unicode の記号カテゴリで、CommonMark は句読点として扱うため、手前が通常文字だと `**` が開き記号にならず記号のまま表示される。外に出せばこの並びを作らない。

`b-none` に記号を付けないのは、灰色＝未実施が「強調しない状態そのもの」だからだ。太字だけを残してバッジであることを示す。

`⚠` は異体字セレクタを付けない `U+26A0` 単体を使う。`⚠️`（`U+26A0 U+FE0F`）と混在すると、文言の突き合わせで別の文字列になる。

### 種類を表すバッジ

良い・悪いではなく、対象の種類を色で示すバッジもある。`b-ok` などに当てはまらない `b-` 付きのクラスはすべてこちらとして扱い、**記号を付けず太字だけにする**。

```
<span class="badge b-esm">ESM</span>
<span class="badge b-cjs">CommonJS</span>
```

この 2 つは `**ESM**` `**CommonJS**` になる。色は CSS 側で自由に定義してよい。html2md は種別が分からないので記号を選べないが、太字にすればバッジだったことは残る。

> [!NOTE]
> **状態と種類で名前空間を分けていない。**`b-ok` `b-ng` `b-warn` `b-none` の 4 つだけが予約語で、それ以外は種類として扱われる。状態を表す新しい名前を増やすときは、この文書に追記して予約語に加える。

## 6. callout

警告・注意・落とし穴・補足は `div class="callout"` で囲む。種別は `callout-` で始まるクラスを併記して指定する。

```
<div class="callout callout-warning">
	<p>本文</p>
</div>
```

| クラス | Markdown の出力 | 使いどころ |
|---|---|---|
| `callout` | `> [!NOTE]` | 補足。種別を書かない場合の既定 |
| `callout callout-tip` | `> [!TIP]` | 知っていると楽になること |
| `callout callout-important` | `> [!IMPORTANT]` | 読み飛ばすと困ること |
| `callout callout-warning` | `> [!WARNING]` | 踏むと壊れること |
| `callout callout-caution` | `> [!CAUTION]` | 取り返しがつかないこと |

種別を `callout-` 付きの名前にしているのは、`important` や `warning` のような汎用的な名前を単独で使うと、他の用途のクラスとぶつかるため。

### 種別の選び方

**読み手がその内容を知らずに進むと、何が起きるか**で決める。文章の強さや語調では決めない。

| 種別 | 知らずに進むと | 例 |
|---|---|---|
| NOTE | 何も起きない。背景を知らないだけ | 調査の手順、価格差の内訳の説明 |
| TIP | 損をする。知っていれば得だった | 学割で 16 万円安くなる |
| IMPORTANT | 選択を誤る。制約や数値の意味を知らずに決めてしまう | メモリスロットが埋まっていて増設できない／その数値は別の指標を指している |
| WARNING | 損害が出る。ただし取り返しはつく | 見積の期限切れ、出典が不確かな数値をそのまま採用 |
| CAUTION | 取り返しがつかない | データの消失、契約の確定 |

- 迷ったら NOTE にする。種別を書かなければ NOTE になる。
- <strong>本文の語で機械的に決めない。</strong>同じ語でも重さが違う。

最後の 1 行は実例がある。ある版は `/注意|失効|期限|限定|リスク|壁/` に一致すれば WARNING という実装だったため、「価格差 87 万円は保証と流通経路の差です」という単なる解説まで WARNING になっていた。逆に「メモリスロットが 2 つとも埋まっている」という制約は、どの語にも当たらないので NOTE のままだった。

内容から種別を推測する実装は採らない。HTML に書いていないことを推測すると結果が読めなくなる。種別は HTML 側で明示する。

> [!IMPORTANT]
> <strong>callout の中身はブロックとして変換される。</strong>段落・リスト・表を入れると、それぞれが `>` の付いた行になる。本文で述べた結論を callout で言い直さない、という決まりはそのまま適用される。

## 7. 表・コード・図・除外

### 表

表は横スクロールできるラッパーで包む。クラス名は `tablewrap` に揃える。

```
<div class="tablewrap">
<table>
	<thead><tr><th>項目</th><th>件数</th></tr></thead>
	<tbody>
		<tr><td class="nowrap">折り返さない値</td><td class="num">123</td></tr>
	</tbody>
</table>
</div>
```

| クラス | HTML での効果 | Markdown の出力 |
|---|---|---|
| `tablewrap` | 横スクロールさせる | 影響しない（構造で表と判断する） |
| `num` | 右寄せ・折り返さない | 列全体が `num` なら区切り行が `---:` になる |
| `nowrap` | 折り返さない | 影響しない |

`rowspan` と `colspan` は展開される。Markdown のテーブルにセル結合が無いため、結合元のセルに文字を置き、残りを空欄にする。セル内の `|` は `\|` にエスケープされ、`<br>` はそのまま残る。

### chapters（章一覧を表にする）

カード風に並べた章一覧を、Markdown では 3 列の表にする。`ul` に `chapters`、各 `li`（`a` の中）に `part` `ttl` `desc` の `span` を置く。

```
<ul class="chapters" data-columns="部,タイトル,内容">
	<li><a href="docs/01-背景.html">
		<span class="part">第1部 基礎編</span>
		<span class="ttl">01. PowerShell の生まれた経緯</span>
		<span class="desc">DOS・Bash・Node.js と比較しながら、何を解決する道具なのかを掴む</span>
	</a></li>
</ul>
```

```markdown
| 部 | タイトル | 内容 |
|---|---|---|
| 第1部 基礎編 | [01. PowerShell の生まれた経緯](docs/01-背景.md) | DOS・Bash・Node.js と比較しながら、何を解決する道具なのかを掴む |
```

| クラス・属性 | 置き場所 | 役割 |
|---|---|---|
| `chapters` | `ul` | 章一覧の入れ物。表に変換する目印 |
| `data-columns` | `ul` の属性 | 表のヘッダ 3 列をカンマ区切りで持つ。**必須。無いと変換が止まる**（表の見出しは HTML に書かれた文言しか使えないため） |
| `part` | `span` | 1 列目（部・グループ）。行ごとに省略できる |
| `ttl` | `span` | 2 列目（タイトル）。`a` の中にあれば、その `href` でリンクにする |
| `desc` | `span` | 3 列目（内容）。行ごとに省略できる |

> [!WARNING]
> <strong>`no` ではなく `part` を使う。</strong>課題一覧（`issues.html`）が課題番号に `no` を使っており、章番号と意味が違う同名クラスになるため避けている。

### コードブロック

言語は `code` の `language-` 付きクラスで指定する。

```
<pre><code class="language-powershell">Get-ChildItem</code></pre>
```

これが ````powershell` のフェンスになる。`language-` を書かなければ言語指定なしのフェンスになる。中身から言語を推測する実装は採らない。

### 図

インライン SVG は独立ファイルに切り出して画像参照にする。GitHub は Markdown 内のインライン SVG をサニタイズで除去するためだ。切り出し先のファイル名は `svg` の `id` から決まる。

```
<svg id="fig-flow" viewBox="0 0 1000 300" role="img" aria-label="図の説明">
	…
</svg>
```

| 属性 | 役割 | 無いとどうなるか |
|---|---|---|
| `id` | 切り出し先が `images/<id>.svg` になる | `<ファイル名>-figNN.svg` の連番になる |
| `viewBox` | `width` / `height` の算出元 | 寸法の付かない SVG になり、単体で開いたときの大きさが決まらない |
| `aria-label` | 画像の `alt` になる | `alt` が空になる |

切り出すときに白背景の矩形が先頭に入る。透過のままだとダークモードで文字が読めなくなるためだ。SVG 内の `id` はファイル単位で一意にすればよいので、`i1` `i2` のような短い名前に振り直される。`figure` と `figcaption` で囲んだ形も扱える。`figcaption` は図の直後の段落になる。

### Markdown に出さない要素

HTML でだけ見せたい要素には `md-skip` を付ける。

```
<p class="md-skip">この段落は Markdown に出ない</p>
```

その要素と中身がまとめて出力から外れる。使うのは、HTML の見た目のためだけに置いた要素に限る。文言そのものを Markdown から落とすと、HTML と内容が食い違う。

### 折りたたみを見出しに展開する

`details` は既定でタグのまま出る。GitHub が解釈するので畳みが効く。**畳むより見出しが要る資料には `md-flat` を付ける。**

```
<details class="md-flat">
	<summary><span class="badge b-warn">着手</span><span class="no">i260830-01</span>件名</summary>
	<p>本文</p>
</details>
```

`summary` がその位置の `h2` と同じ段の見出しになり、中身はその配下の本文になる。畳めなくなる代わりに、GitHub の目次に 1 件ずつ並び、アンカーで参照できる。課題の一覧のように 1 件ずつ引く資料に向く。

課題番号は `no` で囲む。<strong>CSS の余白は Markdown に持ち込めないため、html2md が空白 1 個を補って件名と分ける。</strong>囲まないと番号と件名がくっつく。

### 強調

`strong` と `em` をそのまま書く。`**` で書けるかタグのまま出すかは html2md が判定する。書き手が意識する必要はない。判定の内容は計画の第 5 章に書いた。

## 8. 既存プロジェクトの移行

6 プロジェクトの HTML（計 26 ファイル）で使われているクラス名を集計した。統一先は、この集計で採用数の多いほうを選んでいる。

### 集計結果と統一先

| 用途 | 使われている名前と採用プロジェクト数 | 統一先 |
|---|---|---|
| バッジの基底 | `badge`（5） / `b`（1） | `badge` |
| 良い | `b-ok`（5） / `b-good`（1） | `b-ok` |
| 悪い | `b-ng`（5） / `b-bad`（1） | `b-ng` |
| 警告 | `b-warn`（6） | `b-warn` |
| 未実施 | `b-none`（3） / `b-non`（1） / `b-na`（1） / `b-todo`（1） | `b-none` |
| 表のラッパー | `tablewrap`（4） / `tw`（2） | `tablewrap` |
| 日付 | `meta`（3） / `date`（2） | `date` |
| タイトルの補足 | `sub`（2） / `lead`（1） | `lead` |
| 折り返さない | `nw`（6） | `nowrap` |
| callout の種別 | `callout-xxx`（1） / 種別なし（5） | `callout-xxx` |

<strong>下の 4 行は多数派を採っていない。</strong>名前は読んで役割が分かることが先で、数はその次だという理由による。

| 用途 | 多数派 | 統一先 | 多数派を採らなかった理由 |
|---|---|---|---|
| 日付 | `meta` | `date` | メタ情報は範囲が広く、日付を指すと読み取れない |
| タイトルの補足 | `sub` | `lead` | `sub` は接頭辞で、subtitle とも subsection とも読める |
| 折り返さない | `nw` | `nowrap` | 2 文字では何の略か追えない。CSS のプロパティ値と同じ語にする |
| callout の種別 | 種別なし | `callout-xxx` | `important` のような汎用語を単独で使うと他のクラスと衝突する |

### 急ぐものと急がないもの

名前が違っていても、変換結果が変わるとは限らない。html2md は予約語以外の `b-` 付きクラスもバッジとして拾うし、クラス名を見ずに構造で判断している箇所もある。**先に直すべきは「出力が壊れているもの」だけ**で、残りは見た目を揃えるための整理になる。

| 分類 | 対象 | なぜそうなるか |
|---|---|---|
| ❌ **出力が壊れる** | `b-good` `b-bad` | 予約語でないため記号が付かず、色分けの情報が Markdown で失われる |
| **出力は同じ** | `b-none` `b-non` `b-na` `b-todo` | どれも記号なしの太字になる。未実施は記号を付けない決まりなので結果が一致する |
| **出力は同じ** | `tablewrap` `tw` | クラス名を見ず、`div` の中に `table` があるかで判断している |
| **出力は同じ** | `meta` `date` ／ `sub` `lead` | html2md がどちらの名前も同じ扱いにしている |

### 各プロジェクトでの直し方

書き換えはそのプロジェクトの側で行う。共通ツールのリポジトリから他のプロジェクトのファイルを触らない。

1. `html2md.exe --root . --dry-run` を流し、指摘と警告を確認する。
2. 上の「急ぐものと急がないもの」で ❌ **出力が壊れる** に当たるクラス名を直す。<strong>HTML と CSS の両方を直す。</strong>片方だけだと色が消える。
3. `callout` に種別が付いていないものを、第 6 章の「種別の選び方」に従って分類する。**1 件ずつ内容を読んで判断する。**
4. 章の `h1` に番号を書いていたら消す。html2md が連番を振るため二重になる。
5. 再変換して指摘 0 件を確認し、生成された Markdown の差分を目で見る。

> [!IMPORTANT]
> 手順 3 は機械的に決められない。同じ「期限」という語でも、単なる補足のこともあれば損害に直結することもある。**語句での自動判定は入れない方針なので、人が読んで決める。**
