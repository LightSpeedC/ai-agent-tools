# 応答の言語の検査 計画（英語の文をフックで止める）

AI エージェントの応答に、日本語の無い英語の文が混ざったら、Claude Code のフックで差し戻す共有コマンド `check-reply-language` を足す。

## 1. 背景

2026-10-14、history2html を作るセッションで、ツールを続けて呼ぶ間の短い一言が英語になった。<strong>利用者に指摘されたあとにも、もう 1 度出た。</strong>応答の言語は設定と共通ルール「AIエージェント応答の言語」で日本語と決まっているが、守るかどうかは AI の注意だけに頼っている。

注意では防げないので、**機械で止める**（2026-10-14、利用者の判断。28-A）。どの時点で見るかは 29-A、置き場は 30-A に決めた。

## 2. フックの仕組み（資料で確かめたこと）

Claude Code の公式資料（[Hooks reference](https://code.claude.com/docs/en/hooks)）で確かめた。2026-10-14 時点。

| 事象 | 受け取るもの | 差し戻し方 |
|---|---|---|
| PostToolUse（ツールを呼ぶたび） | `transcript_path`（会話ログ）・ `tool_name` ・ `tool_input` ・ `tool_response` 等 | 終了コード 2 で、標準エラーがツールの結果に添えて AI に届く。ツールは止まらない |
| Stop（応答の最後） | **`last_assistant_message`（最後の応答の本文）**・ `stop_hook_active` | 終了コード 2 で、終わらずに続ける。標準エラーが続ける理由として AI に届く。連続 8 回まで |

> [!IMPORTANT]
> **会話ログは非同期に書かれ、最新の発言がまだ入っていないことがある**（資料に明記）。途中の一言を、ツールの時点で確実に読む方法は無い。**確実なのは Stop の `last_assistant_message` だけ。**

- Windows のフックは Git Bash で動く（無ければ PowerShell）。既定の時間切れは 600 秒
- いま登録してあるフック（SessionStart ・ Stop）は、ai-agent-rules の `tools/80_ops/claude-hooks/` を node で呼ぶ形

## 3. 判定とコマンド

```text
check-reply-language --event post   # PostToolUse から呼ぶ
check-reply-language --event stop   # Stop から呼ぶ
```

フックの入力（JSON）を標準入力で受ける。

### 何を見るか（29-A）

- **post**: 会話ログの末尾だけ（256 KB まで）を読み、最後の人の発言 ・ ツールの結果より後に書かれた AI の文を見る。**読めた分だけを見る**（まだ書かれていなければ取りこぼす）
- **stop**: `last_assistant_message` を必ず見る。あわせて、そのターン（最後の人の発言より後）の AI の文を会話ログから見直し、post で取りこぼした分を拾う
- `stop_hook_active` が真（差し戻しで続けている最中）のときは、最後の応答だけを見る。止まらない状態を作らない

### 英語の文とみなす条件

1. コードブロック ・ ``…`` で囲んだ部分 ・ URL ・ パスを除く
2. 段落（空行で区切る）ごとに見る
3. **英字が 20 字以上あり、ひらがな ・ カタカナ ・ 漢字が 1 字も無い**段落を、英語の文とみなす

英語の用語やコマンドを混ぜた日本語の文は通る。表の行やログの貼り付けのように、日本語が無くても文でないものは、コードブロックに入れて書く前提にする。

### 当たったとき

- 終了コード 2 で、標準エラーに次を書く。**当たった段落の先頭 60 字だけ**を添える `英語の文がありました。日本語で書き直し、利用者に訳を示してください:   "Now remove the parts that moved to the shared ..."`
- 当たらなければ、何も出さず終了コード 0
- 読めない入力 ・ 会話ログが無いときも 0（フックの失敗で作業を止めない）。理由は標準エラーに 1 行だけ

#### 35. 同じ文を 2 度言わないための記録

post で一度指摘した文を、stop の見直しでもう一度指摘しないための決め。

- **35-A（推奨）**: 指摘した段落の指紋（SHA-256 の先頭）を、セッションごとに一時フォルダ（OS の一時フォルダの下）へ書いて、2 度目は言わない。推す理由: 訳を示したあとに同じ文で何度も差し戻されると、作業が進まない
- **35-B**: 記録しない。stop は最後の応答だけを見る（見直しをやめる）。単純だが、post で取りこぼした途中の一言は拾えない

<strong>決めたこと（2026-10-17、利用者の判断）。</strong>35-A。

## 4. 置き場 ・ 登録 ・ 進め方

| もの | 置き場 |
|---|---|
| 本体（TypeScript） | `src/check-reply-language/main.ts` |
| 入口 | `bin/check-reply-language` ・ `bin/check-reply-language.cmd` |
| テスト | `tools/40_test/run-check-reply-language-tests.ts` |

### 登録（`~/.claude/settings.json`）

<strong>個人の設定なので、AI は書き換えない。</strong>利用者が足す。足すのは次の 2 つ（既存の Stop の登録には、2 つ目のフックとして並べる）。

```json
"PostToolUse": [{ "hooks": [{ "type": "command", "command": "check-reply-language --event post", "timeout": 15 }] }],
"Stop":        [{ "hooks": [{ "type": "command", "command": "check-reply-language --event stop", "timeout": 15 }] }]
```

- `bin/` は PATH に入っているので、名前だけで呼べる（Git Bash からは sh の入口が動く）
- ツールを呼ぶたびに走るので、**1 回 0.3 秒以内**を目安にする。会話ログは末尾だけを読む

### 進め方

1. この計画の承認を得る（35 を決める）
2. テストを先に書く。合成したフックの入力と会話ログで、当たる ・ 当たらない ・ 2 度言わない ・ 入力が壊れていても 0、を見る。落ちるのを見てから実装する
3. 実装する。1 回にかかる時間を測る
4. TOOLS-USAGE に使い方と登録の文面を書く。README の一覧に足す
5. 利用者が `settings.json` に登録し、実際のセッションで英語の文を書いて差し戻されることを確かめる。**実環境で動くのを見るまで「済」にしない**（共通ルール「修正は1点ずつ、確認を重視」の自動実行の項）
