# ag.cmd と起動の共通部 計画 (i261101-02)

`agy` を起こす `ag.cmd` を足し、`cc` ・ `cx` ・ `ag` の「フォルダを決めて、履歴があれば続きで起動する」処理を、1 本の共通部にまとめる。

> 📅 作成: 2026-11-01 / 更新: 2026-11-01

[^^](../../README.md)

**対象 ・ 入力 ・ 出力**: 対象は ai-agent-tools の `bin/` (`cc.cmd` ・ `cx.cmd` ・ `ag.cmd` ・ `ag-trusted.cmd`) と、`src/` の起動の共通部 ・ `ag-trusted`。入力は、プロジェクト名の一部 (省略可) と、各エージェントの履歴の置き場 (読み取りのみ)。出力は、決めたフォルダで新しい窓に起動したエージェントと、`agy` の `settings.json` への信頼の書き足し (`ag-trusted` だけ)。

> [!IMPORTANT]
> <strong>実装した (2026-11-01、「cc ・ cx ・ ag関連を実装して」「続けて」の指示)。</strong>残るのは、お手元での確認 (第 5 章)。現在の姿は [cc ・ cx ・ ag の起動の仕様](../50_spec/起動の共通部.md) にある。**計画から変えた点が 3 つ。**(1) 番人への入力は、引数ではなく環境変数 (`KEEPER_*`) で渡し、番人が起こす行の中で消す (日本語や引用符を含む引数を、引数のままでは壊さずに渡せないため)。(2) 番人は、エージェントを `call` で呼ぶ (`codex-trusted` ・ `ag-trusted` は cmd で、`call` が無いと、終わっても戻ってこないため。試験で見つかった)。(3) 試験の非表示のために、`AGENT_LAUNCH_TEST_HIDE` と `KEEPER_NOASK` を足した (`detached` の窓では、`choice` が答えを待ち続けて残るため。実測)。

## 2. 変える動き

### 共通部 (`src/agent-launch/main.ts`)

呼び方は `main.ts <エージェント> [<名前>]`。エージェントは `cc` ・ `cx` ・ `ag`。いまの `cc.cmd` ・ `cx.cmd` の動きを、そのまま 1 本に寄せる。

1. **置き場** (`CC_ROOT`。未設定のとき `W:\`) があるか確かめる。無ければ `[NG]` を出して終了コード 1
2. **年のフォルダ** (`W:\<yyyy>`) を、無ければ作る
3. **名前が無いとき**は、`[NG]` のメッセージを出して終了する (86-A)
4. <strong>探す。</strong>置き場の直下で `*<名前>*` に当たるフォルダ → 年のフォルダの中で当たるフォルダ → どちらも無ければ、年のフォルダの中に `<yyyymmdd>-<名前>` を作る。複数に当たったときの選び方は、いまの動きを試験で固定してから、そのまま揃える
5. **そのエージェントの履歴を見る** (下の表)。あれば続き、無ければ新規
6. **起こす** (下の表)

#### 履歴の判定

| エージェント | 見る場所 | 履歴ありの条件 | 状態 |
|---|---|---|---|
| `cc` (`claude`) | `~/.claude/projects/<符号化したパス>/` | `*.jsonl` が 1 つ以上。符号化は `W:\2026\<名前>` → `W--2026-<名前>` (`:` と `\` が `-` になる)。**フォルダだけあって `*.jsonl` が 0 個のものがある**ので、ファイルを数える | 実測済み |
| `ag` (`agy`) | `~/.gemini/antigravity-cli/cache/last_conversations.json` | そのフォルダのパスがキーにある。会話の `.db` (`conversations/<ID>.db`) も在れば確実 | 構造は実測済み。会話を消したときにキーが消えるかは未確認 |
| `cx` (`codex`) | `~/.codex/state_5.sqlite` の `threads` 表 | `cwd` がそのフォルダで、`archived = 0` の行が 1 件以上 | 表の定義は実測済み。**`cwd` の書式と `has_user_event` の意味は未確認** (実装の最初に、件数と形だけ確かめる) |

- 3 つとも**読み取りのみ**。`sqlite` は `node:sqlite` の読み取り専用で開く。会話の中身は読まない
- 判定の関数は、ホームのフォルダを**引数で受ける** (試験が一時のフォルダを渡せる)

#### 起こし方

| エージェント | 起こすコマンド (新しい窓) | 環境 |
|---|---|---|
| `cc` | 先に `cc-register` でフォルダを登録 (失敗しても起動する)。`start <フォルダ名> claude.exe [-c] -n "<フォルダ名> <月/日> <時:分>"` | `CLAUDE` で始まる変数を、`CLAUDE_CODE_USE_POWERSHELL_TOOL` 以外すべて外して渡す (いまの動き) |
| `cx` | `start "codex" codex-trusted [resume]` (続きなら `resume`) | 呼んだ窓の環境のまま |
| `ag` | `start "agy" ag-trusted --dangerously-skip-permissions --mode auto [-c]` (続きなら `-c`) | 呼んだ窓の環境のまま |

起こすときのフォルダ (カレント) は、**共通部が子プロセスの設定で渡す**。呼んだ窓のカレントは動かさない。

**窓のタイトル**は、3 本とも `start "<エージェント名> <フォルダ名>" …` の形にする。`start` は最初の引用符つきの引数をタイトルとして扱うので、**タイトルは必ず引用符で囲む** (空白や日本語を含んでも、コマンドと取り違えない)。エージェント名は `cc` ・ `cx` ・ `ag` (87-B)。例: `start "cc 20261101-foo" …`

### 窓の番人 (終了のあとの再起動)

3 本とも、新しい窓の中で動くのは、エージェントそのものではなく、**cmd の番人** (`src/agent-launch/keeper.cmd`。SJIS ＋ CRLF)。90-A に従い、常駐も node ・ bun の番人も作らない。

1. 共通部 (短命の node) が、フォルダ ・ 履歴 ・ 引数 ・ 環境を決め、`start "<タイトル>" cmd /d /c keeper.cmd …` で番人の窓を開けて、**すぐ終わる**
2. 番人が、エージェントを起動する (最初の引数は、共通部が決めたもの)
3. エージェントが終わったら (ctrl-c を 2 回押した終了も、ふつうの終了も、終了コードによらず)、`choice` で **`R` (再起動) か `Q` (終了)** を尋ねる
4. `R` なら、**続きの引数を付けて**起動し直す (`cc` は `-c`、`cx` は `resume`、`ag` は `-c`)。履歴の判定は繰り返さない (起動した時点で、履歴ができているため)。起動のたびに PATH から探すので、新しく入れたエージェントが使われる
5. `Q` なら、番人が終わり、窓が閉じる。尋ねている画面で ctrl-c を押したときも、窓が閉じる

エージェントの環境 (`cc` は `CLAUDE` で始まる変数を外す等) は、共通部が番人の窓を開けるときの環境で決める。番人は、受けた環境のまま起動し直す。

### 入口の cmd

- `cc.cmd` ・ `cx.cmd` ・ `ag.cmd` は、`node "%~dp0..\src\agent-launch\main.ts" <エージェント> %*` の 1 行 (`cx.cmd` の画面消去 `cls` は cmd 側に残す)
- 作業用の変数 (`YMD` ・ `Y` ・ `XMD` ・ `HMSC` ・ `XHM`) と、`CC_ROOT` の設定を、cmd からなくす。**窓の環境変数とカレントは、前後で変わらない** (80-A。85-A に決まったので、作りとして満たされる)
- 置き換えるときに、古い処理を cmd から**削除する** (置き換えの手順に入れる)

### `ag-trusted` (`bin/ag-trusted.cmd` と `src/ag-trusted/main.ts`)

`codex-trusted` と同じ形。`ag-trusted [<agy の引数>…]` で、現在のフォルダを信頼として書き足し、`agy` を引数つきで起動する。

- **書く先**は `~/.gemini/antigravity-cli/settings.json`。BOM なし ・ LF ・ インデント 2 つの空白 (実測)
- **書き方は、文字列としての挿入。**`trustedWorkspaces` の配列に 1 行だけ足す。**許可リスト (`permissions.allow`) などの、ほかの部分は 1 バイトも変えない** (試験で、挿入の前後を比べる)。`agy` 自身がこのファイルを書き換えるため、JSON を作り直して書き戻す形にはしない
- **書く前に控えを取る** (`settings.json.backup-<日時>`)。書くのは、フォルダが未登録のときだけ。判定は、パスの完全一致 (大小を区別する。`agy` が完全一致で見るとされているため。未確認)
- <strong>起動中の書き込みとの衝突を避ける。</strong>読んだときの更新日時とサイズを覚え、書く直前に見直す。変わっていれば読み直して、最大 3 回までやり直す。それでも変わるなら、書かずに止める
- `trustedWorkspaces` が無ければ、末尾の `}` の前にキーごと足す。空の配列 (`[]`) も扱う
- `settings.json` が無い、または JSON として読めないときは、**書かずに**そう表示して止める (終了コード 3)。`agy` の初回の設定を邪魔しない
- 引数の誤りは終了コード 2。それ以外の終了コードは `agy` のものをそのまま返す

## 5. 決める点と、確かめること

### 85: 共通部が、どこまでを受け持つか (2026-11-01、85-A に決定)

履歴の判定は、JSON や `sqlite` を読む。結果 (フォルダ ・ 続きか新規か) を cmd に返す形にすると、**日本語のフォルダ名が文字化けする**おそれがある。共通部が出す文字は UTF-8 で、cmd の `for /f` は窓のコードページで読むため。コードページは変えない決まり (共通ルール「コンソールのコードページを変更しない」)。

| 案 | 内容 | 恒久 / 暫定 |
|---|---|---|
| **85-A (推奨)** | 共通部が、決めて、**起こすところまで**行う。環境の整理 (`CLAUDE` で始まる変数を外す等) も、子プロセスの設定で行う。cmd は 1 行。文字を cmd に返さないので、化けない。窓の環境変数とカレントは、作りとして変わらない (80-A) | 恒久 |
| 85-B | 共通部は**決めるだけ**。結果を cmd に返し、cmd が `setlocal` の中で起こす。80-A は `setlocal` と後始末で満たす。日本語のフォルダ名を cmd に渡す道 (一時ファイル経由等) を別に作る必要がある | 恒久 |

**推す理由**: 化ける道を作らず、80-A を作りとして満たせる。cmd が薄くなる。**弱点**は、新しい窓の起こし方 (`start` の引数の引用) を、node から再現する作業が増えること。代役で試験する。

### 86: 名前を渡さずに呼んだとき (2026-11-01、86-A に決定)

いまは、`cc` が `[NG] プロジェクトはありません。` を出して終わる。`cx` は何も言わず終わる (年のフォルダへ移るだけ)。

| 案 | 内容 | 恒久 / 暫定 |
|---|---|---|
| **86-A (推奨)** | 3 本とも、`[NG]` のメッセージを出して終了する (`cc` の動きに揃える)。`cx` は、無言で終わらなくなる (仕様の変更) | 恒久 |
| 86-B | `cc` は `[NG]`、`cx` ・ `ag` は無言で終わる (いまの動きを共通部に持ち込む)。共通部に、エージェントごとの分岐が 1 つ残る | 恒久 |

**推す理由**: 無言で終わると、打ち間違いに気づけない。3 本で動きが揃う。

### 87: 窓のタイトルの「エージェント名」の表記 (2026-11-01、87-B に決定)

タイトルの形は `<エージェント名> <フォルダ名>` に決まった (利用者の判断)。名前の表記が 2 通りある。

| 案 | 内容 | 恒久 / 暫定 |
|---|---|---|
| **87-A (推奨)** | 起こす相手の名前: `claude` ・ `codex` ・ `agy`。例: `claude 20261101-foo` | 恒久 |
| 87-B | 入口のコマンド名: `cc` ・ `cx` ・ `ag`。例: `cc 20261101-foo` | 恒久 |

**推す理由**: いまの `cx` のタイトル (`codex`) と同じ系統で、窓を見て、起動している相手がすぐ分かる。`cc` ・ `cx` ・ `ag` は、打ちやすくした略で、窓の一覧では何のことか分かりにくい。**87-B の利点**は、短く、打ったコマンドと一致すること。

### 利用者の手元で確かめること (実装の後)

- `ag` で、新しいフォルダが**信頼の確認を出さずに**起動する。`trustedWorkspaces` の完全一致 (大小 ・ 区切り) が合っている証拠になる
- `ag` で、既存のフォルダが `-c` で**そのフォルダの直前の会話**を続ける (全体の直前ではない)
- 別のエージェントが先に作ったフォルダで、`cc` ・ `cx` ・ `ag` を使い、履歴が無いほうが**新規**で起動する
- 窓から `cc` ・ `cx` ・ `ag` を使ったあと、**窓のカレントと環境変数が変わらない**

### まだ確かめていないこと

- `agy` の信頼が、パスの完全一致 (大小を含む) か。第三者の資料にあるだけ
- `codex` の `threads.cwd` の書式と、`has_user_event` の意味 (進め方の 3 で確かめる)
- `agy` が、会話を消したときに `last_conversations.json` のキーを消すか
- `start` の引数 (窓の題 ・ セッション名に空白や `/` を含む) を、node の子プロセスでいまの cmd と同じに渡せるか (代役を使った試験で確かめる)
- `cx.cmd` の動き (窓への漏れ ・ カレント) は、いまの試験が無いので、実測していない
- 起こした `claude` ・ `codex` ・ `agy` が、起動したあとで、自分で窓のタイトルを書き換えるか。書き換えるなら、`start` で付けたタイトルは、起動直後だけになる
- ctrl-c を 2 回押して終了したとき、`claude` が返す終了コード (番人は、終了コードによらず尋ねる作りにする)
- `choice` が、標準入力から答えを読めるか (試験の作りに関わる)。cmd の番人 (`cmd.exe`) が窓ごとに 1 つ増えるメモリは、待機のものを 1 回測っただけで、実際に 5 本開いたときの合計は測っていない
