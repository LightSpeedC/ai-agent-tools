この文書について

html2md には仕様書が無く、src/Html2Md/Converter.cs の実装が唯一の仕様になっていた。そのため「div に直接書いたテキストが Markdown から消える」ことに、実際に変換するまで気づけなかった。

この文書は実測した結果を記録する。36 ケースのタグを含む HTML を変換し、出力を 1 件ずつ確認した。推測ではない。

ここに書いた内容は現状であって、あるべき姿ではない。直すべきものは第 5 章に論点として挙げてある。実装を変えたらこの文書も更新する。

検証の方法

ここに書いた挙動は tests/cases/ のテストケースで固定してある。tools/40_test/run-tests.cmd を実行すると、exe と ps1 の両方で変換し、出力が一致することと、出ているべき文字列がすべて出ていることを確かめる。

参照実装の ps1 と本実装の exe が食い違ったら、どちらかに入れ忘れた修正がある。実際、この仕組みを入れた時点で ps1 側に 6 件の入れ忘れが見つかった。

テキストが消える 17 ケース

36 ケースを含む HTML を変換したところ、17 件のテキストが出力に現れなかった。原因は 2 つに分かれる。

この章は 2026-08-30 に対処済み。17 件のうち 16 件が出るようになった。残るのは caption の 1 件。以下は何が起きていたかの記録として残す。

原因 1 — ブロック要素の中の地の文

html2md はブロックタグを見つけて飛び移る走査をしている。その隙間にある地の文を拾っていない。

入力出力
<div>テキスト</div>消える
<blockquote>テキスト</blockquote>消える
<nav>テキスト</nav>消える
<footer>テキスト</footer>消える
<div class="callout">テキスト</div>> [!NOTE] だけ残り中身が消える
<div>前<p>段落</p>後</div>「前」と「後」が消える

いずれも <p> で囲めば出る。囲み忘れると警告も出ずに消えるのが問題で、検査もこれを検出しない（Markdown 側にしか無い文言は調べるが、HTML 側にしか無い文言は調べていない）。

原因 2 — ブロックとして扱っていないタグ

この節は 2026-09-01 に対処済み。hr を除くすべてを走査の対象に加えた。決着は決着 4にある。以下は何が起きていたかの記録。

BlockTags に無いタグは走査の対象外なので、中身ごと飛ばされる。

決着と残る論点

決着 1 — 地の文を拾う 対処済み

ブロック要素の中の地の文を段落として出すようにした。書いたものが黙って消えるより、余分な段落が出るほうが気づけるため。既存 6 プロジェクトで確かめたところ、出力が変わったところは無かった（空白だけの隙間は段落にならない）。

決着 2 — ブロックの終端を 1 か所で決める 対処済み

地の文の対処では足りず、より深いところに原因があった。GetTagBlock（ブロック全体を返す）と GetInnerHtml（中身を探し直す）が同じブロックについて別々に終端を判断していた。

// GetTagBlock: depth を数えて終端を知っている
if (nc < 0) return html.Substring(start);      // 閉じタグが無いと分かっている

// GetInnerHtml: その情報を捨てて、独立に探し直す
int j = block.LastIndexOf("</" + tag + ">");   // 子要素の閉じタグを拾ってしまう

ブロックの終端という既に判明している情報が受け渡されていないのが原因で、閉じタグの有無に関わらず誤りうる構造だった。書き込み途中のログ HTML（<div class="log"> を閉じない形式）で最後の 1 行が必ず落ちる、という形で表面化した。

GetBlock がブロック全体（Outer）と中身（Inner）を一度に返す形に変え、呼び出し側が閉じタグを探し直す余地をなくした。

この修正で callout の中身が正しく取れるようになった結果、検査側の穴が露出した。callout 内のコードフェンスは > ``` の形になるが、検査は行頭の ``` しか見ていなかった。引用記号を外してから判定するよう直している。

決着 3 — md-skip ページへのリンクは .html のまま残す 対処済み

<meta name="md-skip"> を付けたページは Markdown を生成しない。にもかかわらず、そのページを参照する側のリンクは .md に置き換えられていた。存在しないファイルを指すため、検査が必ずリンク切れを報告する。ai-chat-lite で 8 件が出た。

★Markdown 側: リンク切れ: ../40_issues/issues.md
★Markdown 側: リンク切れ: ../40_issues/issues.md#i260830-13

置換は HtmlUtil.ConvertLinkTarget の 1 箇所で行うが、この関数は href の文字列だけを受け取る。リンク先が md-skip かどうかを知る手立てが無いのが原因だった。加えて md-skip のページは変換結果の一覧に入らないため、--dry-run のときに生成予定ファイルを実在扱いする仕組み（expected）にも入らない。

採らなかった案

リンクを外して文字だけ残す案もあった。404 にはならず、「HTML からは HTML、Markdown からは Markdown を参照する」という取り決めにも反しない。ただし読み手が Markdown 側から到達できなくなる。課題一覧のように参照される前提のページで、行き先を失うほうが困る。

採った案

md-skip のページへのリンクだけ .html のまま残す。到達できることを優先した。

[課題](../40_issues/issues.html)

GitHub はリポジトリ内の .html をレンダリングしない。クリックするとソース表示になり、details の畳みは効かずタグが並んだ状態で読むことになる。それでも中身には到達できる。

この案は「同じ種類同士でリンクし、混在させない」という取り決めの例外になる。Markdown 側から .html を指す形が正当な場合として残るため、取り決め側にも md-skip の例外を書き足す必要がある。

実装

変換の前に md-skip のページを洗い出し、その一覧を置換の判定に渡す。

箇所変更
Program.cs変換前に全対象を先読みし、md-skip ページの絶対パスの集合を作る
Converter集合を受け取り、InlineConverter と基準ディレクトリを渡す
HtmlUtil.ConvertLinkTargetアンカーとクエリを分けてパスを解決し、集合に含まれるなら置換しない
html2md.ps1同じ処理を入れる。exe との出力一致をテストで見ているため

集合に無いリンクは従来どおり .md に置き換える。Checks 側は変更しない。.html は実在するファイルを指すため、そのままで検査を通る。

決着 4 — 未対応タグは中身のテキストを落とさない 対処済み

ブロックとして扱っていなかったタグを走査の対象に加えた。構造を保つことより、書いたテキストが消えないことを先にした。

タグ扱い
main article aside header address中身を処理する（div と同じ）
details summary畳みを解いて、中身を段落として出す
dl dt dd項目ごとの段落にする
caption表の直前の段落にする

dt dd summary を個別に挙げているのは、親（dl details）だけを挙げると中身がまとめて 1 段落になり、項目の境目が消えるため。

hr は対象外。テキストを持たないため「中身を落とさない」の対象にならず、--- を出すのは記号を足さない方針に触れる。この判断は決着 9で改めた。

決着 5 — 章の外の見出しも段を詰める 対処済み

章の外では h2 だけが 1 段上がり、h3 以下は上がっていなかった。## の次が #### になり ### が抜ける。

章の外の見出しは章と同じ立場（目次・関連文書など文書全体に対する見出し）なので、h2 を ## にする判断はそのまま残し、同じ調整を h3 以下にも通した。

入力章の中章の外（旧）章の外（新）
h2#######
h3###########
h4##############

調整は HeadingMark の 1 か所に寄せ、h2 だけが持っていた分岐は消した。

決着 6 — 取り消し線は記法、他はタグで残す 対処済み

del は ~~取り消し線~~ にする。ただし ~~ も ** と同じ前後判定を受ける。成立しない位置では <del> で出すため、強調と同じセンチネル方式に載せた。

取り消し線は ~~この部分~~ が対象。
閉じの直前が句読点だと記法が成立しない: <del>やめました。</del>次の文へ続く。

それ以外の意味を持つタグは、GitHub のレンダラで実際に生き残るものだけタグのまま残す。開きタグと閉じタグだけを退避し、中身は通常の変換を通すので、<kbd><strong>Ctrl</strong></kbd> のような入れ子でも中身が変換される。

どのタグが残るかは実測で決めた

「GitHub は HTML を解釈するのでタグのまま残せる」という見込みで 11 個を並べたが、実際に api.github.com/markdown へ投げると 4 個は除去された。

タグGitHub扱い
sup sub kbd mark ins q残るタグのまま出す
abbr small cite time除去される平文に落とす
del残る~~ にする（前後判定で成立しないときはタグ）

除去されるものは中身のテキストだけが残る。タグで出しても表示に効かないため、平文にした。

タグが生き残るかを確かめる仕組みは無い。check-markdown は ** が記号のまま残っていないかだけを見ている。上の表は手で投げて確かめた結果で、GitHub 側のサニタイズが変われば古くなる。

この対応で退避の仕組みに潜んでいた欠陥が表面化した。キーが「制御文字＋連番＋同じ制御文字」の形だったため、あるキーの閉じ・本文の数字・次のキーの開きが並ぶと偽のキーができる。2<sup>10</sup> が別の退避内容に置き換わっていた。コードスパンだけを退避していた頃から潜んでいたもので、両端を別の文字にして直した。

センチネルに使えるのは \s にマッチしない制御文字だけ。本文は最後に空白をまとめるため、\t \n \v \f \r（0x09〜0x0D）を使うとキーが空白に置き換わって壊れる。最初に選んだ \v（0x0B）でこれを踏んだ。

決着 7 — 置き換えるのは変換されるページへのリンクだけ 対処済み

決着 3 で md-skip のページを除いたが、探索フォルダの外にある HTML へのリンクも .md に書き換わっていた。--dir に含めていない docs/ を参照すると、生成されない docs/…md を指すことになる。

判定を裏返して、この実行で .md ができるページの一覧を持つ形にした。一覧にあるものだけ置き換え、無いものは .html のまま残す。md-skip のページも探索フォルダの外も、同じ 1 つの判定で片付く。

リンク先出力
探索フォルダの中で、md-skip でない.md に置き換える
md-skip のページ.html のまま
探索フォルダの外.html のまま
実在しないファイル.html のまま（HTML 側の検査が拾う）

決着 8 — SVG の CSS 変数は切り出すときに埋める 対処済み

デザインの取り決めは stop-color="var(--accent)" の書き方を前提にしているが、単体ファイルに切り出すと変数が解決されず色が失われる。参照先の <style> が付いてこないためで、取り決めに従って書いた HTML ほどこれを踏む。

<style> から変数を読み、切り出すときに実際の値を埋める。章ごとに色が違うので、その図がどの章にあるかを見る必要がある。章の定義を先に引き、無ければ :root を引く。

書き方解決
var(--accent)（.ch02 の中）.ch02 の定義
var(--accent)（章の外）:root の定義
var(--x, #336699)（定義なし）既定値の #336699
var(--x)（定義も既定値もなし）そのまま残す

定義がある変数は、既定値が書かれていても定義の側を使う。ブラウザと同じ順序にした。解決できないものは書き換えずに残す。消すと図が壊れるより、そのままのほうが気づける。

@media の中は読まない。ダークモードの定義が通常の色を上書きしてしまうため、ブロックごと落としてから読む。入れ子があるので括弧を数えて終端を決めている。JS による上書きも対象外。

フォールバックの取り出しは正規表現ではなく括弧を数えている。var(--x, hsl(280,78%,25%)) のように既定値の中に括弧が入ると、[^)]* では途中で切れて壊れる。

既存 6 プロジェクトの SVG を調べたところ var( を含むものは無く、影響は出ていなかった。いずれもリテラルの hsl() で書かれていたため表面化していなかっただけで、取り決めに沿って書き直せば踏む。

決着 9 — dl は箇条書き、details はタグ、hr は区切り線 対処済み

決着 4 でテキストは落ちなくなったが、構造は捨てたままだった。3 つとも落とし先を決めた。

タグ出力決めた理由
dl dt dd箇条書き。dt が項目、dd は 4 字下げた入れ子表にすると列の意味を書き手が決められない。箇条書きなら足す記号が - だけで済む
details summaryタグのまま出すGitHub が解釈する。畳みが効き、元の構造がそのまま残る
hr---区切りという意味を持つ要素で、--- はその記法の対応物

dl の出力

- 用語
    - 説明
    - 2 つ目の説明

入れ子の字下げは ul ol と同じ 4 字にする。dt を太字にしない。** は HTML に無い装飾で、足すと文言の同一性から外れる。

details の出力

<details>
<summary>見出しの文</summary>

中身は Markdown に変換して入れる。

</details>

</summary> の後に空行を置く。空行が無いと GitHub は中身を HTML として読み、Markdown の記法が効かない。閉じる前にも空行を置く。

summary の中身はインラインだけ変換する。details の外に単独で置かれた summary は、これまでどおり段落として出す。

hr の実装

hr は閉じタグを持たない。GetBlock は閉じタグを探して見つからなければ末尾までを 1 ブロックとするため、そのまま渡すとhr より後ろが丸ごと飲み込まれる。空要素として開きタグだけを切り出す分岐を GetBlock に足す。

残る論点

del 以外に取り消し線を表すタグ（s strike）は対象にしていない。

← html2md
