この文書について

html2md には仕様書が無く、src/Html2Md/Converter.cs の実装が唯一の仕様になっていた。そのため「div に直接書いたテキストが Markdown から消える」ことに、実際に変換するまで気づけなかった。

この文書は実測した結果を記録する。36 ケースのタグを含む HTML を変換し、出力を 1 件ずつ確認した。推測ではない。

ここに書いた内容は現状であって、あるべき姿ではない。直すべきものは第 5 章に論点として挙げてある。実装を変えたらこの文書も更新する。

検証の方法

ここに書いた挙動は tests/cases/ のテストケースで固定してある。tools/40_test/run-tests.cmd を実行すると、exe と ps1 の両方で変換し、出力が一致することと、出ているべき文字列がすべて出ていることを確かめる。

参照実装の ps1 と本実装の exe が食い違ったら、どちらかに入れ忘れた修正がある。実際、この仕組みを入れた時点で ps1 側に 6 件の入れ忘れが見つかった。

ブロックの中で記法に置き換えるタグ。

タグMarkdown の出力備考

タグが消えて中身だけ残るもの

次のタグは記法に置き換えず、中身のテキストだけを残す。意味は失われる。

<del> <ins> <sup> <sub> <mark> <kbd> <abbr> <small> <q> <cite> <time>

取り消し線・上付き・キー表記といった区別は Markdown に出ない。GitHub は ~~取り消し線~~ を解釈するので del だけは記法にできるが、いまは対応していない。

テキストが消える 17 ケース

36 ケースを含む HTML を変換したところ、17 件のテキストが出力に現れなかった。原因は 2 つに分かれる。

この章は 2026-08-30 に対処済み。17 件のうち 16 件が出るようになった。残るのは caption の 1 件。以下は何が起きていたかの記録として残す。

原因 1 — ブロック要素の中の地の文

html2md はブロックタグを見つけて飛び移る走査をしている。その隙間にある地の文を拾っていない。

入力出力
<div>テキスト</div>消える
<blockquote>テキスト</blockquote>消える
<nav>テキスト</nav>消える
<footer>テキスト</footer>消える
<div class="callout">テキスト</div>> [!NOTE] だけ残り中身が消える
<div>前<p>段落</p>後</div>「前」と「後」が消える

いずれも <p> で囲めば出る。囲み忘れると警告も出ずに消えるのが問題で、検査もこれを検出しない（Markdown 側にしか無い文言は調べるが、HTML 側にしか無い文言は調べていない）。

原因 2 — ブロックとして扱っていないタグ

BlockTags に無いタグは走査の対象外なので、中身ごと飛ばされる。

タグ用途本来あるべき出力
dl dt dd定義リストMarkdown に定義リストは無い。箇条書きか表に落とす
details summary折りたたみGitHub は HTML のまま解釈する。そのまま残す手もある
caption表の見出し表の直前か直後の段落
main article aside header文書構造中身を処理する（div と同じ扱い）
address連絡先段落
hr区切り線---。ただし記号を足さない方針との兼ね合いがある
spanブロックの外に単独で置いた場合段落

見出しの段が飛ぶ

章の外に h2 と h3 を並べると、## の次が #### になり ### が抜ける。

入力章の中章の外
h2#####
h3########

h2 だけが章の内外で段を変え、h3 は変えていない。目次の生成には影響しないが、見出しの階層としては崩れている。

決着と残る論点

決着 1 — 地の文を拾う 対処済み

ブロック要素の中の地の文を段落として出すようにした。書いたものが黙って消えるより、余分な段落が出るほうが気づけるため。既存 6 プロジェクトで確かめたところ、出力が変わったところは無かった（空白だけの隙間は段落にならない）。

決着 2 — ブロックの終端を 1 か所で決める 対処済み

地の文の対処では足りず、より深いところに原因があった。GetTagBlock（ブロック全体を返す）と GetInnerHtml（中身を探し直す）が同じブロックについて別々に終端を判断していた。

// GetTagBlock: depth を数えて終端を知っている
if (nc < 0) return html.Substring(start);      // 閉じタグが無いと分かっている

// GetInnerHtml: その情報を捨てて、独立に探し直す
int j = block.LastIndexOf("</" + tag + ">");   // 子要素の閉じタグを拾ってしまう

ブロックの終端という既に判明している情報が受け渡されていないのが原因で、閉じタグの有無に関わらず誤りうる構造だった。書き込み途中のログ HTML（<div class="log"> を閉じない形式）で最後の 1 行が必ず落ちる、という形で表面化した。

GetBlock がブロック全体（Outer）と中身（Inner）を一度に返す形に変え、呼び出し側が閉じタグを探し直す余地をなくした。

この修正で callout の中身が正しく取れるようになった結果、検査側の穴が露出した。callout 内のコードフェンスは > ``` の形になるが、検査は行頭の ``` しか見ていなかった。引用記号を外してから判定するよう直している。

論点 3 — 未対応タグをどうするか

main article aside header は div と同じ「中身を処理する」扱いにすれば済む。dl と details は Markdown に対応する記法が無いため、落とし方を決める必要がある。

論点 4 — 見出しの段飛び

章の外の h3 を ### にするか、h2 を章の中と同じ ### に統一するか。

論点 5 — 意味を持つインラインタグ

del は ~~取り消し線~~ にできる。sup sub kbd は GitHub が HTML を解釈するのでタグのまま残す手もある。どこまで対応するかを決める。

論点 3 から 5 はまだ決まっていない。実装を変えるときは、先にここで方針を決めてから着手する。caption が出力されない件は論点 3 に含まれる。
