# xx コマンド 計画（引数を別プロセスで実行する）

引数のコマンドを別プロセスで実行し、出力の文字コードを判定して UTF-8 で返す内部ツール `xx` を、Rust で作る。

> 📅 作成: 2026-10-27 / 更新: 2026-10-27

[^^](../../README.md)

**対象 ・ 入力 ・ 出力**: 対象は ai-agent-tools。入力はコマンドラインの引数 (実行するコマンドと、その引数)。出力は、そのコマンドの標準出力 ・ 標準エラーを UTF-8 にしたものと、終了コード。

## 1. 目的と決めたこと

`xx <コマンド> [引数...]` で、そのコマンドを別プロセスで実行する。例は `xx psls a.exe`。**内部ツール**として、利用方法の資料 (TOOLS-USAGE) にも、共通ルールにも書かない。

決めたこと (2026-10-27、利用者の判断。73 〜 77 は、この計画のための通し番号)。

| 番号 | 決めたこと |
|---|---|
| 73-A | 子プロセスとして起動し、終わるまで待つ。終了コードをそのまま返す |
| 74-A | ソースは `src/` の下、入口は `bin/`。資料には書かない (実行ファイルの置き方は第 4 章) |
| 75-A | `.exe` ・ `.cmd` ・ `.bat` ・ `.ps1` を PATH から探して実行する |
| 76-A (置き換え) | コードページは変えない。子の出力は、判定して読み替える |
| 追加 | 子の標準入力は EOF にする |
| 77-A | 子の出力の文字コード (SJIS ・ UTF-8 ・ UTF-16) を判定し、常に UTF-8 で出す。判定が付かなければそのまま流す |

## 2. 動き

```text
xx psls a.exe
xx git status
```

1. **探す**: 最初の引数を、PATH から探す。拡張子が無ければ `.exe` → `.cmd` → `.bat` → `.ps1` の順に試す
2. **起動役を挟む**: `.exe` は直接。`.cmd` ・ `.bat` は `cmd /c`。`.ps1` は `powershell -NoProfile -ExecutionPolicy Bypass -File`
3. **入力**: 子の標準入力は、空のもの (EOF) にする。待たされて固まらない
4. **出力**: 子の標準出力 ・ 標準エラーを、それぞれ別に受ける。終わるまで待ち、第 3 章で UTF-8 にして、同じ側 (標準出力は標準出力、標準エラーは標準エラー) へ書く
5. **終了コード**: 子の終了コードをそのまま返す。起動できなかった (見つからない ・ 起動に失敗) ときは、理由を標準エラーに 1 行書き、127 を返す

> [!NOTE]
> **コードページは変えない** (共通ルール「コンソールのコードページを変更しない」)。自分の出力は、リダイレクトされていれば UTF-8 のバイト列で書く。窓に出すときは、窓のコードページに依らず UTF-8 の書き込みで出る形を、実機で確かめてから決める (第 5 章の 3)。

## 3. 出力の文字コードの判定

受けたバイト列の全体を見て、1 回で判定する。**ストリームの途中では切り替えない** (終わるまで待つ 73-A のため、全体を見られる)。

| 順 | 見るもの | 判定 |
|---|---|---|
| 1 | 先頭が BOM (`EF BB BF`) | UTF-8。BOM を除いて出す |
| 2 | 先頭が BOM (`FF FE` ・ `FE FF`) | UTF-16 (LE ・ BE)。UTF-8 にして出す |
| 3 | 全体が正しい UTF-8 として読める | UTF-8 (ASCII だけの場合も含む)。そのまま出す |
| 4 | 正しい UTF-8 ではなく、CP932 として読める | SJIS (CP932)。UTF-8 にして出す |
| 5 | どれでもない | 判定が付かない。そのまま流す |

- BOM の無い UTF-16 は判定しない (3 〜 5 に落ちる)。`00` の混ざり方で見分ける案は、必要が出たら足す
- 既存の判定 (`src/lib/detector.ts`) と同じ結果になることを、テストで突き合わせる (共通ルール「答え合わせの相手があれば突き合わせる」)。Rust では `encoding_rs` を使うか、自前で書くかを、実装の前に比べる (判断が要れば、案を出す)

## 4. 置き場 ・ ビルド ・ 入口

| もの | 置き場 |
|---|---|
| ソース (Rust) | `src/xx/` (Cargo のプロジェクト) |
| ビルドの出力 | `src/xx/target/` (git に含めない) |
| ビルド | `tools/20_build/build-xx.cmd` (`cargo build --release`) |
| 入口 | `bin/xx.cmd` |
| テスト | `tests/` と `tools/40_test/` の既存の形に合わせる |

- **exe を `bin/` に直接置かない**。`bin/` は git で管理し、exe は git に含めない。入口 `bin/xx.cmd` が、`src/xx/target/release/xx.exe` を呼ぶ (psh の Rust 版と同じ形)
- <strong>決めたこと 74-A の「実行ファイルを `bin/` に出す」は、この形に読み替える。</strong>exe そのものを `bin/` に置くと、git の管理と食い違うため。名前 `xx` だけで呼べることは変わらない
- **資料に書かない**: TOOLS-USAGE ・ 共通ルールには載せない。道具の一覧にも載せない。この計画書 (README からリンクする) と、ソース先頭のコメントだけが説明になる
- `.gitignore` に `target/` が無ければ足す (すでに psh の Rust 版のために足してあれば不要)

## 5. 進め方

1. この計画の承認を得る
2. status に着手を反映する
3. **窓に出すときの書き方を、実機で確かめる**。窓のコードページが 932 のままで、UTF-8 の文字が化けずに出るかを、リダイレクトの有無で見る。コードページを変えずに済む書き方を選ぶ (化けるなら、案を出して決める)
4. テストを先に書く。次を期待値に持ち、落ちる (❌Red) のを見てから実装する
    - 終了コードがそのまま返る (0 ・ 1 ・ 大きい値)
    - 見つからないとき 127 で、標準エラーに理由が出る
    - 標準入力が EOF (入力を待つコマンドが固まらない)
    - 標準出力と標準エラーが、別の側に出る
    - 出力が SJIS ・ UTF-8 ・ UTF-16 (BOM あり) ・ ASCII のみ ・ 判定不能 のとき、それぞれ期待どおりの UTF-8 になる
    - `.cmd` ・ `.bat` ・ `.ps1` が、拡張子なしの名前で見つかって動く
    - 空白を含む引数 ・ 日本語の引数が、そのまま子へ渡る
5. 実装する。ビルドして、テストを全件通す (✅Green)
6. 入口 `bin/xx.cmd` を作る (cmd は SJIS ＋ CRLF)。実機で `xx psls a.exe` を動かす
7. status と計画に結果を反映する。資料には載せない
