## 1. この文書について

html2md には仕様書が無く、`src/Html2Md/Converter.cs` の実装が唯一の仕様になっていた。そのため「`div` に直接書いたテキストが Markdown から消える」ことに、実際に変換するまで気づけなかった。

この文書は**実測した結果**を記録する。36 ケースのタグを含む HTML を変換し、出力を 1 件ずつ確認した。推測ではない。

> [!IMPORTANT]
> ここに書いた内容は**現状であって、あるべき姿ではない**。直すべきものは第 5 章に論点として挙げてある。実装を変えたらこの文書も更新する。

### 検証の方法

ここに書いた挙動は `tests/cases/` のテストケースで固定してある。`tools/40_test/run-tests.cmd` を実行すると、exe と ps1 の両方で変換し、**出力が一致することと、出ているべき文字列がすべて出ていること**を確かめる。

参照実装の ps1 と本実装の exe が食い違ったら、どちらかに入れ忘れた修正がある。実際、この仕組みを入れた時点で ps1 側に 6 件の入れ忘れが見つかった。

### 用語

| 語 | 意味 |
|---|---|
| ブロック要素 | html2md が走査の対象にするタグ。Markdown の行やブロックになる |
| インライン要素 | ブロックの中で記法に置き換えるタグ。行にはならない |
| 地の文 | ブロック要素で囲まれていない、剥き出しのテキスト |

## 2. ブロック要素

走査の対象にするタグ。実装では `Converter.cs` の `BlockTags` に列挙している。

| タグ | 条件 | Markdown の出力 |
|---|---|---|
| `section` | — | 中身を処理する。章の中であることを覚える |
| `h1` | タイトルバーの中 | `# タイトル` |
| `h1` | 章の中 | `## 1. 章名`（連番が付く） |
| `h2` | 章の中 | `### 節名` |
| `h2` | 章の外 | `## 節名` |
| `h3`〜`h6` | — | `####`〜`######` |
| `p` | — | 段落 |
| `p.date` `p.meta` | — | `> 📅 …` の引用行 |
| `div.titlebar` | — | 中身を処理する。中の `h1` が `#` になる |
| `div.callout` | — | `> [!NOTE]` 等。種別は追加クラスで決まる |
| `div.toc` | — | 見出し＋番号付きリスト。アンカーを張り替える |
| `div.minibar` | — | `## テキスト` |
| `div.date` `div.meta` | — | 引用行 |
| `div`（上記以外） | — | 中身を処理する。`div` 自体は行にならない |
| `ul` `ol` | — | 箇条書き／番号付きリスト。入れ子は 4 空白ずつ字下げ |
| `ol.toc` | — | 目次として扱い、アンカーを張り替える |
| `table` | — | Markdown テーブル。`rowspan` / `colspan` を展開する |
| `pre` | — | コードフェンス。言語は `code.language-xxx` から取る |
| `blockquote` | — | 中身の各ブロックに `> ` を付ける |
| `figure` | — | 中の `svg` を画像に、`figcaption` を段落にする |
| `svg` | — | `images/` に切り出して `![alt](images/x.svg)` |
| `footer` `nav` | — | 中身を処理する。タグ自体は行にならない |
| `a` | 段落の外に単独 | リンク 1 行 |
| `details` | `class="md-flat"` | 畳まず、`summary` を見出し・中身をその配下の本文にする（決着 12） |
| どれか | `class="md-skip"` | 要素ごと出力しない。`li`（`ol.toc` ・ `ul.chapters` を含む） ・ `td` `th` ・ `dt` `dd` ・ `span` も同じ。**落とした分は番号を消費しない**（`section` と同じ扱いで、目次と見出しの番号が揃う） |

## 3. インライン要素

ブロックの中で記法に置き換えるタグ。

| タグ | Markdown の出力 | 備考 |
|---|---|---|
| `a` | `[文字](リンク先)` | 拡張子を `.md` に、`#chNN` を見出しアンカーに置き換える。`md-skip` のページへのリンクは `.html` のまま残す |
| `code` | ``コード`` | 中身は他の変換の対象にしない |
| `strong` `b` | `**太字**` または `<strong>` | 前後の文字で判定する |
| `em` `i` | `*斜体*` または `<em>` | 同上 |
| `span.badge` | `✅ **完了**` | 記号は太字の外。予約語以外は記号なし |
| `span.no` | 中身＋空白 1 個 | 課題番号。CSS の余白は Markdown に持ち込めない（決着 12） |
| `span`（バッジ以外） | 中身だけ残る | 装飾目的とみなす |
| `img` | `![alt](src)` |  |
| `br` | `<br>` | 表の中と外で同じ |
| `del` | `~~取り消し線~~` または `<del>` | `**` と同じ前後判定を受ける |
| `ins` `sup` `sub` `mark` `kbd` `q` | タグのまま | GitHub で生き残ることを実測した |
| `abbr` `small` `cite` `time` | 中身だけ残る | GitHub が除去するため平文にする |

### タグのまま残すもの

次のタグは記法に置き換えず、<strong>タグのまま出す。</strong>GitHub のレンダラで生き残ることを実測で確かめたものだけを挙げている。

```text
ins sup sub mark kbd q
```

開きタグと閉じタグだけを退避し、中身は通常の変換を通す。`del` は `~~取り消し線~~` にする（成立しない位置ではタグで出す）。<strong>`abbr` `small` `cite` `time` は GitHub が除去するため平文に落とす。</strong>経緯は[決着 6](#5-決着と残る論点)にある。

## 4. テキストが消える 17 ケース

36 ケースを含む HTML を変換したところ、17 件のテキストが出力に現れなかった。原因は 2 つに分かれる。

> [!IMPORTANT]
> <strong>この章は 2026-08-30 に対処済み。</strong>17 件のうち 16 件が出るようになった。残るのは `caption` の 1 件。以下は何が起きていたかの記録として残す。

### 原因 1 — ブロック要素の中の地の文

html2md はブロックタグを見つけて飛び移る走査をしている。**その隙間にある地の文を拾っていない。**

| 入力 | 出力 |
|---|---|
| `<div>テキスト</div>` | 消える |
| `<blockquote>テキスト</blockquote>` | 消える |
| `<nav>テキスト</nav>` | 消える |
| `<footer>テキスト</footer>` | 消える |
| `<div class="callout">テキスト</div>` | `> [!NOTE]` だけ残り中身が消える |
| `<div>前<p>段落</p>後</div>` | 「前」と「後」が消える |

いずれも `<p>` で囲めば出る。囲み忘れると**警告も出ずに消える**のが問題で、検査もこれを検出しない（Markdown 側にしか無い文言は調べるが、HTML 側にしか無い文言は調べていない）。

### 原因 2 — ブロックとして扱っていないタグ

> [!IMPORTANT]
> **この節は 2026-09-01 に対処済み。**`hr` を除くすべてを走査の対象に加えた。決着は[決着 4](#5-決着と残る論点)にある。以下は何が起きていたかの記録。

`BlockTags` に無いタグは走査の対象外なので、中身ごと飛ばされる。

| タグ | 用途 | 本来あるべき出力 |
|---|---|---|
| `dl` `dt` `dd` | 定義リスト | Markdown に定義リストは無い。箇条書きか表に落とす |
| `details` `summary` | 折りたたみ | GitHub は HTML のまま解釈する。そのまま残す手もある |
| `caption` | 表の見出し | 表の直前か直後の段落 |
| `main` `article` `aside` `header` | 文書構造 | 中身を処理する（`div` と同じ扱い） |
| `address` | 連絡先 | 段落 |
| `hr` | 区切り線 | `---`。ただし記号を足さない方針との兼ね合いがある |
| `span` | ブロックの外に単独で置いた場合 | 段落 |

### 見出しの段が飛ぶ

> [!IMPORTANT]
> <strong>この節は 2026-09-01 に対処済み。</strong>決着は[決着 5](#5-決着と残る論点)にある。以下は何が起きていたかの記録。

章の外に `h2` と `h3` を並べると、`##` の次が `####` になり `###` が抜ける。

| 入力 | 章の中 | 章の外 |
|---|---|---|
| `h2` | `###` | `##` |
| `h3` | `####` | `####` |

`h2` だけが章の内外で段を変え、`h3` は変えていない。目次の生成には影響しないが、見出しの階層としては崩れている。

## 5. 決着と残る論点

### 決着 1 — 地の文を拾う ✅ **対処済み**

ブロック要素の中の地の文を段落として出すようにした。書いたものが黙って消えるより、余分な段落が出るほうが気づけるため。既存 6 プロジェクトで確かめたところ、出力が変わったところは無かった（空白だけの隙間は段落にならない）。

### 決着 2 — ブロックの終端を 1 か所で決める ✅ **対処済み**

地の文の対処では足りず、より深いところに原因があった。`GetTagBlock`（ブロック全体を返す）と `GetInnerHtml`（中身を探し直す）が**同じブロックについて別々に終端を判断していた**。

```
// GetTagBlock: depth を数えて終端を知っている
if (nc < 0) return html.Substring(start);      // 閉じタグが無いと分かっている

// GetInnerHtml: その情報を捨てて、独立に探し直す
int j = block.LastIndexOf("</" + tag + ">");   // 子要素の閉じタグを拾ってしまう
```

ブロックの終端という**既に判明している情報が受け渡されていない**のが原因で、閉じタグの有無に関わらず誤りうる構造だった。書き込み途中のログ HTML（`<div class="log">` を閉じない形式）で最後の 1 行が必ず落ちる、という形で表面化した。

`GetBlock` がブロック全体（`Outer`）と中身（`Inner`）を一度に返す形に変え、呼び出し側が閉じタグを探し直す余地をなくした。

> [!NOTE]
> この修正で callout の中身が正しく取れるようになった結果、**検査側の穴が露出した**。callout 内のコードフェンスは `> ```` の形になるが、検査は行頭の ````` しか見ていなかった。引用記号を外してから判定するよう直している。

### 決着 3 — md-skip ページへのリンクは .html のまま残す ✅ **対処済み**

`<meta name="md-skip">` を付けたページは Markdown を生成しない。にもかかわらず、そのページを参照する側のリンクは `.md` に置き換えられていた。<strong>存在しないファイルを指すため、検査が必ずリンク切れを報告する。</strong>ai-chat-lite で 8 件が出た。

```text
★Markdown 側: リンク切れ: ../40_issues/issues.md
★Markdown 側: リンク切れ: ../40_issues/issues.md#i260830-13
```

置換は `HtmlUtil.ConvertLinkTarget` の 1 箇所で行うが、この関数は `href` の文字列だけを受け取る。**リンク先が md-skip かどうかを知る手立てが無い**のが原因だった。加えて md-skip のページは変換結果の一覧に入らないため、`--dry-run` のときに生成予定ファイルを実在扱いする仕組み（`expected`）にも入らない。

#### 採らなかった案

リンクを外して文字だけ残す案もあった。404 にはならず、「HTML からは HTML、Markdown からは Markdown を参照する」という取り決めにも反しない。ただし**読み手が Markdown 側から到達できなくなる**。課題一覧のように参照される前提のページで、行き先を失うほうが困る。

#### 採った案

md-skip のページへのリンクだけ `.html` のまま残す。到達できることを優先した。

```markdown
[課題](../40_issues/issues.html)
```

> [!IMPORTANT]
> <strong>GitHub はリポジトリ内の `.html` をレンダリングしない。</strong>クリックするとソース表示になり、`details` の畳みは効かずタグが並んだ状態で読むことになる。それでも中身には到達できる。

> [!WARNING]
> この案は<strong>「同じ種類同士でリンクし、混在させない」という取り決めの例外</strong>になる。Markdown 側から `.html` を指す形が正当な場合として残るため、取り決め側にも md-skip の例外を書き足す必要がある。

#### 実装

変換の前に md-skip のページを洗い出し、その一覧を置換の判定に渡す。

| 箇所 | 変更 |
|---|---|
| `Program.cs` | 変換前に全対象を先読みし、md-skip ページの絶対パスの集合を作る |
| `Converter` | 集合を受け取り、`InlineConverter` と基準ディレクトリを渡す |
| `HtmlUtil.ConvertLinkTarget` | アンカーとクエリを分けてパスを解決し、集合に含まれるなら置換しない |
| `html2md.ps1` | 同じ処理を入れる。exe との出力一致をテストで見ているため |

集合に無いリンクは従来どおり `.md` に置き換える。`Checks` 側は変更しない。`.html` は実在するファイルを指すため、そのままで検査を通る。

### 決着 4 — 未対応タグは中身のテキストを落とさない ✅ **対処済み**

ブロックとして扱っていなかったタグを走査の対象に加えた。**構造を保つことより、書いたテキストが消えないことを先にした。**

| タグ | 扱い |
|---|---|
| `main` `article` `aside` `header` `address` | 中身を処理する（`div` と同じ） |
| `details` `summary` | 畳みを解いて、中身を段落として出す |
| `dl` `dt` `dd` | 項目ごとの段落にする |
| `caption` | 表の直前の段落にする |

`dt` `dd` `summary` を個別に挙げているのは、親（`dl` `details`）だけを挙げると**中身がまとめて 1 段落になり、項目の境目が消えるため。**

> [!NOTE]
> `hr` は対象外。テキストを持たないため「中身を落とさない」の対象にならず、`---` を出すのは記号を足さない方針に触れる。**この判断は[決着 9](#5-決着と残る論点)で改めた。**

### 決着 5 — 章の外の見出しも段を詰める ✅ **対処済み**

章の外では `h2` だけが 1 段上がり、`h3` 以下は上がっていなかった。`##` の次が `####` になり `###` が抜ける。

**章の外の見出しは章と同じ立場**（目次・関連文書など文書全体に対する見出し）なので、`h2` を `##` にする判断はそのまま残し、同じ調整を `h3` 以下にも通した。

| 入力 | 章の中 | 章の外（旧） | 章の外（新） |
|---|---|---|---|
| `h2` | `###` | `##` | `##` |
| `h3` | `####` | `####` | `###` |
| `h4` | `#####` | `#####` | `####` |

調整は `HeadingMark` の 1 か所に寄せ、`h2` だけが持っていた分岐は消した。

### 決着 6 — 取り消し線は記法、他はタグで残す ✅ **対処済み**

`del` は `~~取り消し線~~` にする。<strong>ただし `~~` も `**` と同じ前後判定を受ける。</strong>成立しない位置では `<del>` で出すため、強調と同じセンチネル方式に載せた。

```markdown
取り消し線は ~~この部分~~ が対象。
閉じの直前が句読点だと記法が成立しない: <del>やめました。</del>次の文へ続く。
```

それ以外の意味を持つタグは、**GitHub のレンダラで実際に生き残るものだけ**タグのまま残す。開きタグと閉じタグだけを退避し、中身は通常の変換を通すので、`<kbd><strong>Ctrl</strong></kbd>` のような入れ子でも中身が変換される。

#### どのタグが残るかは実測で決めた

「GitHub は HTML を解釈するのでタグのまま残せる」という見込みで 11 個を並べたが、**実際に `api.github.com/markdown` へ投げると 4 個は除去された。**

| タグ | GitHub | 扱い |
|---|---|---|
| `sup` `sub` `kbd` `mark` `ins` `q` | 残る | タグのまま出す |
| `abbr` `small` `cite` `time` | **除去される** | 平文に落とす |
| `del` | 残る | `~~` にする（前後判定で成立しないときはタグ） |

除去されるものは中身のテキストだけが残る。タグで出しても表示に効かないため、平文にした。

> [!IMPORTANT]
> **タグが生き残るかを確かめる仕組みは無い。**`check-markdown` は `**` が記号のまま残っていないかだけを見ている。上の表は手で投げて確かめた結果で、GitHub 側のサニタイズが変われば古くなる。

> [!IMPORTANT]
> この対応で<strong>退避の仕組みに潜んでいた欠陥が表面化した。</strong>キーが「制御文字＋連番＋同じ制御文字」の形だったため、**あるキーの閉じ・本文の数字・次のキーの開きが並ぶと偽のキーができる。**`2<sup>10</sup>` が別の退避内容に置き換わっていた。コードスパンだけを退避していた頃から潜んでいたもので、両端を別の文字にして直した。

> [!WARNING]
> センチネルに使えるのは <strong>`\s` にマッチしない制御文字だけ。</strong>本文は最後に空白をまとめるため、`\t \n \v \f \r`（0x09〜0x0D）を使うとキーが空白に置き換わって壊れる。最初に選んだ `\v`（0x0B）でこれを踏んだ。

### 決着 7 — 置き換えるのは変換されるページへのリンクだけ ✅ **対処済み**

決着 3 で md-skip のページを除いたが、**探索フォルダの外にある HTML へのリンクも `.md` に書き換わっていた。**`--dir` に含めていない `docs/` を参照すると、生成されない `docs/…md` を指すことになる。

判定を裏返して、**この実行で `.md` ができるページの一覧**を持つ形にした。一覧にあるものだけ置き換え、無いものは `.html` のまま残す。md-skip のページも探索フォルダの外も、同じ 1 つの判定で片付く。

| リンク先 | 出力 |
|---|---|
| 探索フォルダの中で、md-skip でない | `.md` に置き換える |
| md-skip のページ | `.html` のまま |
| 探索フォルダの外 | `.html` のまま |
| 実在しないファイル | `.html` のまま（HTML 側の検査が拾う） |

### 決着 8 — SVG の CSS 変数は切り出すときに埋める ✅ **対処済み**

デザインの取り決めは `stop-color="var(--accent)"` の書き方を前提にしているが、<strong>単体ファイルに切り出すと変数が解決されず色が失われる。</strong>参照先の `<style>` が付いてこないためで、**取り決めに従って書いた HTML ほどこれを踏む。**

`<style>` から変数を読み、切り出すときに実際の値を埋める。<strong>章ごとに色が違うので、その図がどの章にあるかを見る必要がある。</strong>章の定義を先に引き、無ければ `:root` を引く。

| 書き方 | 解決 |
|---|---|
| `var(--accent)`（`.ch02` の中） | `.ch02` の定義 |
| `var(--accent)`（章の外） | `:root` の定義 |
| `var(--x, #336699)`（定義なし） | 既定値の `#336699` |
| `var(--x)`（定義も既定値もなし） | **そのまま残す** |

定義がある変数は、既定値が書かれていても定義の側を使う。ブラウザと同じ順序にした。解決できないものは書き換えずに残す。**消すと図が壊れるより、そのままのほうが気づける。**

> [!IMPORTANT]
> <strong>`@media` の中は読まない。</strong>ダークモードの定義が通常の色を上書きしてしまうため、ブロックごと落としてから読む。入れ子があるので括弧を数えて終端を決めている。JS による上書きも対象外。

> [!NOTE]
> フォールバックの取り出しは正規表現ではなく括弧を数えている。`var(--x, hsl(280,78%,25%))` のように**既定値の中に括弧が入ると、`[^)]*` では途中で切れて壊れる。**

既存 6 プロジェクトの SVG を調べたところ `var(` を含むものは無く、影響は出ていなかった。**いずれもリテラルの `hsl()` で書かれていたため表面化していなかっただけで、取り決めに沿って書き直せば踏む。**

### 決着 9 — dl は箇条書き、details はタグ、hr は区切り線 ✅ **対処済み**

決着 4 でテキストは落ちなくなったが、<strong>構造は捨てたままだった。</strong>3 つとも落とし先を決めた。

| タグ | 出力 | 決めた理由 |
|---|---|---|
| `dl` `dt` `dd` | 箇条書き。`dt` が項目、`dd` は 4 字下げた入れ子 | 表にすると列の意味を書き手が決められない。箇条書きなら足す記号が `-` だけで済む |
| `details` `summary` | タグのまま出す | GitHub が解釈する。畳みが効き、元の構造がそのまま残る |
| `hr` | `---` | 区切りという意味を持つ要素で、`---` はその記法の対応物 |

#### dl の出力

```markdown
- 用語
    - 説明
    - 2 つ目の説明
```

入れ子の字下げは `ul` `ol` と同じ 4 字にする。**`dt` を太字にしない。**`**` は HTML に無い装飾で、足すと文言の同一性から外れる。

#### details の出力

```markdown
<details>
<summary>見出しの文</summary>

中身は Markdown に変換して入れる。

</details>
```

> [!IMPORTANT]
> <strong>`</summary>` の後に空行を置く。</strong>空行が無いと GitHub は中身を HTML として読み、Markdown の記法が効かない。閉じる前にも空行を置く。

`summary` の中身はインラインだけ変換する。`details` の外に単独で置かれた `summary` は、これまでどおり段落として出す。

#### hr の実装

> [!WARNING]
> **`hr` は閉じタグを持たない。**`GetBlock` は閉じタグを探して見つからなければ末尾までを 1 ブロックとするため、そのまま渡すと<strong>`hr` より後ろが丸ごと飲み込まれる。</strong>空要素として開きタグだけを切り出す分岐を `GetBlock` に足す。

### 決着 10 — chapters は data-columns 付きの表にする ✅ **対処済み**

`20260822-powershell-pwsh-learn` からの要求（[課題 i260830-05](../40_issues/issues.html)）。`<ul class="chapters">` の中の `span` 3 つが連結され、リンクのラベルが 1 本の長い文字列になっていた。

要求元 HTML を `<table>` に書き換える案（各プロジェクトが手作業で書き換え、カード風の見た目を失う）と比べ、**html2md が `chapters` 構造を解釈して表にする案を選んだ**。要求元は既存の HTML 構造のまま、次回変換で自動的に表になる。

#### クラス名

| クラス | 意味 | 備考 |
|---|---|---|
| `chapters`（`ul`） | 章一覧の入れ物 | `data-columns` が必須 |
| `data-columns`（属性） | 表のヘッダ 3 列をカンマ区切りで持つ（例 `"部,タイトル,内容"`） | HTML に無い文言を検査で拾わせないための持たせ方。`aria-label` と同じ扱いで、検査は属性値も「HTML にある文言」に含める |
| `part`（`span`） | 部・グループ（1 列目） | **`no` ではなく `part`。**`issues.html` は課題番号に `no` を使っており、章番号とは意味が違う同名クラスになるため改名した |
| `ttl`（`span`） | タイトル（2 列目）。`<a href>` の中にあれば、その href をリンクにして出す | — |
| `desc`（`span`） | 内容（3 列目） | — |

#### 入力・出力

```html
<ul class="chapters" data-columns="部,タイトル,内容">
  <li><a href="docs/01-背景.html">
    <span class="part">第1部 基礎編</span>
    <span class="ttl">01. PowerShell の生まれた経緯</span>
    <span class="desc">DOS・Bash・Node.js と比較しながら、何を解決する道具なのかを掴む</span>
  </a></li>
</ul>
```

```markdown
| 部 | タイトル | 内容 |
|---|---|---|
| 第1部 基礎編 | [01. PowerShell の生まれた経緯](docs/01-背景.md) | DOS・Bash・Node.js と比較しながら、何を解決する道具なのかを掴む |
```

#### エラーにする条件

- <strong>`data-columns` が無い `chapters` は変換を止める。</strong>黙って見出しの無い表を出さない。`convert-encoding` の「表現できない文字があれば書き換えずに止まる」と同じ考え方
- `data-columns` の列数は 3 固定（`part` / `ttl` / `desc` に対応）。3 以外ならエラー

`part`・`desc` は行ごとに省略してよい（空セルにする）。`li class="c01"` のような番号用クラスは表示側の飾りとして無視する。

#### 反映するルール文書

実装後、次の 3 か所に反映する: `html-class-rules.html`（クラス名の正式追加）、`~/.claude/CLAUDE.md` のクラス名一覧、`TOOLS-USAGE.html`（使い方）。反映後 ai-chat-lite で周知し、要求元プロジェクトに HTML の書き換え（`no`→`part`、`data-columns` の追加）を依頼する。

✅ **済** 2026-09-09 に実装した。`Table.cs`（`ListTableConverter.ConvertChapters`）と `html2md-ps.ps1`（`Convert-Chapters`）に両対応で追加し、`Checks.cs` の「HTML に無い文言」検査に `data-columns` を aria-label と同じ扱いで足した。テストケース `tests/cases/chapters` を新仕様に更新し、全テスト成功。`html-class-rules.html`・`TOOLS-USAGE.html` は反映済み。`~/.claude/CLAUDE.md` への反映は利用者の判断を待つ。

> [!CAUTION]
> <strong>不具合（同日中に修正）。</strong>初回実装は `ttl` の `href` を自前で `"[text](href)"` と組み立てており、`.md` 置換・他ファイルのアンカー張り替えを行う共通経路を素通りしていた。要求元プロジェクトから ai-chat-lite（#699）で報告を受け、`ttl` の生の中身を合成 `<a>` に包んで `inline.Convert` に通す形に直した。テストケースに実在するリンク先ファイルを足し、`.md` 置換が効くことを確認する回帰を追加した。

### 決着 11 — 他ファイルへのアンカーも見出しアンカーへ張り替える ✅ **対処済み**

[課題 i260830-07](../40_issues/issues.html)。同一ファイル内の `#chNN` は見出しアンカーに張り替えていたが、**他ファイルへのリンクのアンカー部分は変換していなかった。**

```
[03.2 実行ポリシー](docs/03-実行環境.html#ch02)
  ↓ いま
[03.2 実行ポリシー](docs/03-実行環境.md#ch02)     ← 飛ばない
  ↓ あるべき
[03.2 実行ポリシー](docs/03-実行環境.md#032-実行ポリシー--なぜ動かないのか)
```

#### 変換対象すべてのアンカーマップを先に作る

いままではファイルごとに独立して変換していた。他ファイルのアンカーを解決するには、**変換対象すべての見出しアンカーマップを先に作り、リンク先のファイルのマップを引く**形にする必要がある。

| 段階 | やること |
|---|---|
| 事前パス | 変換対象のページごとに HTML を読み、**本変換はせず見出しアンカーマップだけ**作る（`id → 生成後のアンカー`）。絶対パスをキーにした辞書に集める |
| 本変換 | リンクの `href` が他ファイルを指し、変換対象に含まれるとき、**アンカー部分だけ**を対象ファイルのマップで引いて張り替える。無ければ元のアンカーのまま残す（同一ファイル内の張り替えと同じ落とし方） |

md-skip のページと探索フォルダの外にある HTML は、決着 7 と同じくアンカーも張り替えない（`.html` のまま残るため）。

> [!IMPORTANT]
> <strong>事前パスは、md-skip 判定のために既に読んでいる HTML をそのまま使う。</strong>同じファイルを 2 回読まない。

✅ **済** 2026-09-09 に実装した。`HtmlUtil.ConvertLinkTarget` に対象ファイルごとのアンカーマップ（`crossAnchors`）を渡すよう拡張し、`Converter.BuildAnchorsFromHtml`（事前パス用の公開ラッパー）を追加。`Program.cs` の md-skip 判定ループで同時にマップを集める。`html2md-ps.ps1` にも同じ構造で実装（`Get-StrippedBody` を共通ヘルパーに切り出し）。テストケース `tests/cases/cross-anchor` を新設し、exe と ps1 の出力が一致することを確認。全テスト成功。

### 決着 12 — HTML ブロックの中は Markdown が効かない ✅ **対処済み**

決着 9 で `details` はタグのまま出すことにしたが、<strong>`summary` の行に置いた `**` が記号のまま表示される。</strong>CommonMark は HTML ブロックの中身を生の HTML として扱い、インラインの記法を解釈しない。`<summary>` の行は `<details>` から続く 1 つの HTML ブロックの中にあるため、そこだけ記法が効かない。

課題の一覧（`md-skip` を外した写し）を変換して GitHub のレンダラに掛けると、**32 箇所すべてが `summary` の中のバッジだった。**

```markdown
<summary>✅ **済** i260830-01caption が出力されない</summary>
    ↑ ** が記号のまま        ↑ 番号と件名がくっつく
```

#### 1. summary の中の強調はタグで出す

強調を `**` にするかタグにするかは、前後の文字を見て最終段で決めている（決着 6）。<strong>HTML ブロックの中では前後の文字に関係なく必ずタグにする。</strong>判定を 1 つ足すだけで、`strong` ・ `em` ・ `del` が揃って直る。

```markdown
<summary>✅ <strong>済</strong> i260830-01 caption が出力されない</summary>
```

#### 2. 課題番号（.no）は空白 1 個を補う

番号と件名が詰まるのは、<strong>HTML 側が CSS の余白（`margin`）でしか離していないため。</strong>余白は Markdown に持ち込めないので、バッジと同じ扱いで空白 1 個を補う。`no` をクラス名の取り決めに加える。

#### 3. md-flat を付けた details は見出しに展開する

`summary` は見出しにならないため、<strong>1 件ごとの見出しもアンカーも Markdown 側に残らない。</strong>GitHub の目次に出るのは章だけになる。畳めることを取るか、見出しになることを取るかは資料によって違うので、`class="md-flat"` で選べるようにする。

| 書き方 | Markdown の出力 | 向くもの |
|---|---|---|
| `<details>` | タグのまま。畳みが効く | 本文の補足。読み飛ばせることに意味がある |
| `<details class="md-flat">` | `summary` を見出し、中身をその配下の本文にする | 課題の一覧。1 件ずつ参照したい |

見出しの段は**その位置の `h2` と同じ扱いにする**（章の中なら `###`）。`details` の入れ子や、見出しの深さを書き手が指定する形にはしない。

> [!IMPORTANT]
> <strong>`md-flat` の `details` に `id` を振っても、アンカーマップには載らない。</strong>そこへのリンクは張り替えられず、変換後の検査がアンカー切れとして報告する。載せるかどうかは、使う場面が出てから決める。

✅ **済** 2026-09-11 に 3 つとも実装した。`Emphasis.ResolveAsTags`（ps1 は `Resolve-Emphasis -ForceTags`）を足し、`summary` の行だけ前後の文字を見ずにタグで確定させる。`no` は `span` の変換でバッジと同じく空白 1 個を補う。`md-flat` は `ConvertDetails` が見出し＋本文のブロック列を返す形にした。テストケース `tests/cases/details` を新設し、exe と ps1 の出力が一致することと、GitHub のレンダラで `**` が残らないことを `check-markdown` で確認した。全テスト成功。

### 残る論点

`del` 以外に取り消し線を表すタグ（`s` `strike`）は対象にしていない。

`summary` の中のリンクとコードスパンは、決着 12 と同じ理由で `[文字](リンク先)` ・ ``コード`` が記号のまま表示される。<strong>直すにはタグ（`<a href>` ・ `<code>`）で出す必要があり、リンクは `.md` 置換とアンカー張り替えの経路も通す。</strong>今回の範囲には入れていない。
