# コマンド起動サーバ 計画

HTTP で待ち受け、受け取ったコマンド文字列を、同じユーザーのまま新しい窓で独立したプロセスとして起動する TypeScript のツール（`spawn-server`）。

## 1. 背景と狙い

窓を開いた本人のコンテキストのまま、外から（HTTP で）コマンドを起動したい。`bin/cc.cmd` が `start` で claude を新しい窓に立てるのと同じ形にする。

- **サーバーは起動するだけ**。終わるのを待たず、出力も受け取らない。応答で返すのは起動したプロセスの pid
- **起動したプロセスはサーバーから独立する**。サーバーを止めても道連れにならない（`taskkill /T` で止めたときは除く。第 4 章）
- **依頼ごとに新しい窓を開く**。コンソール ・ 標準入力 ・ 標準出力 ・ 標準エラーはその窓のもので、サーバーの窓とは共有しない。入力の取り合いも起きない
- **ユーザーコンテキストはサーバーのまま**。環境変数 ・ カレント ・ 権限（昇格の有無）を引き継ぐ

## 2. 守る仕様

### 起動のしかた

```shell
spawn-server --port 8790
```

- **ポートは引数で渡す**（共通ルール「プロセスの識別性」）。`process.title` にも `spawn-server:8790` を入れる
- 起動時に待受けのアドレスを出す

### 依頼の形

| 項目 | 案 |
|---|---|
| 要求 | `POST /run`。本文は JSON `{"command": "…", "cwd": "…", "title": "…"}`。`cwd` は省略可（省略時はサーバーのカレント）。`title` は窓のタイトルで省略可（省略時はコマンド文字列） |
| 解釈 | コマンド文字列はシェルに渡す（第 6 章 2） |
| 応答（成功） | `200` `{"pid": 1234}`。起動できた時点で返す |
| 応答（失敗） | 起動できない `500` ・ 形が違う `400` ・ Origin 付き `403`。本文に日本語の理由 |

### ログ

受けた依頼と起動した pid を、サーバーの窓に 1 行ずつ出す（JST `yyyy/mm/dd hh:mm:ss.ccc`）。

## 3. 安全策

> [!CAUTION]
> <strong>任意のコマンドを本人の権限で走らせる口になる。</strong>ほかの人・ほかのサイトから届けば、そのままこの PC の操作になる。作ったあとで塞ぐのではなく、最初から入れる。

- **待ち受けは `127.0.0.1` だけ**。`0.0.0.0` にしない
- **トークンは使わない**。呼ぶのは同じ PC からだけなので、127.0.0.1 と Origin 拒否で足りるとした。**同じ PC のほかのプロセスからの依頼は防げない**
- **ほかのページからの依頼を断る**。`Origin` は自分の入力ページ（第 6 章の追加）と同じときだけ通し、本文は `application/json` だけを受ける（悪意あるページから localhost へ投げられるのを防ぐ）
- CORS のヘッダは返さない

## 4. 実装の方式

HTTP は `node:http`（bun でも動く）。起動は `CreateProcessW` を FFI で直に呼び、新しい窓の `cmd /c` にコマンドを渡す（`src/spawn-server-ts/create-process.ts`）。

```text
CreateProcessW(NULL, 'cmd.exe /d /s /c "title <title> & <command>"', …, bInheritHandles=0,
               CREATE_NEW_CONSOLE, lpEnvironment=NULL, lpCurrentDirectory=<cwd>, STARTUPINFOW{cb だけ}, …)
```

- **FFI は bun が `bun:ffi`、node が koffi**（共通ルール「bun と node で FFI を使うとき」）
- **標準入出力のハンドルを渡さない**（`STARTF_USESTDHANDLES` なし）。`CREATE_NEW_CONSOLE` で作った窓に出力が出る
- **環境変数は渡さない**（`NULL`）。サーバーのものをそのまま引き継ぐ。渡すための作業用の変数も要らない
- 返す pid は窓の中の `cmd` のもので、`taskkill /T` で止めれば中身ごと止まる
- タイトルは `cmd` の `title` に渡すので、`" & | < > ^ %` を外す
- **FFI が使えないとき**（node で koffi が入っていない等）は PowerShell の `Start-Process` に落ちる（案 A）。機能は同じで、起動に 0.6 秒ほどかかる。`SPAWN_SERVER_NO_FFI=1` で最初からこちらにでき、テストは両方の道を回す

### 起動方法の比較（2026-10-01）

5 つの案を、起動の部分だけを切り出して比べた（`tools/50_run/bench-spawn/`）。サーバー役のプロセスから起動し、次を見た。

- 起動の速さ: 依頼を受けてから pid が返るまで。`cmd /c exit` を 5 回起動した中央値
- 機能: `>` と `&` を含み、日本語 ・ サーバーの環境変数 ・ 作業用の変数（`%SPAWN_COMMAND%`）・ 標準出力が窓につながっているか（`[Console]::IsOutputRedirected`）をファイルに書き、10 秒ほど生きるコマンド
- 新しい窓: 起動したものの下に `conhost.exe` がいるか
- 止め方: サーバー役だけを止めたとき（`/T` なし。Ctrl+C に近い）と、`taskkill /T` で止めたときに残るか

| 案 | やり方 | 速さ | `>` ・ `&` | 日本語 ・ 環境変数 | 作業用の変数の漏れ | 出力が窓に出る | サーバーだけ止めた | `/T` で止めた |
|---|---|---:|---|---|---|---|---|---|
| A | PowerShell の `Start-Process`。変数は起動前に消す | 568 ms | 動く | 渡る | なし | 出る | 残る | 残る |
| B | 窓なしの node の中継から `cmd` | 8 ms | 動く | 渡る | なし | **出ない**（NUL に流れる） | 残る | 道連れ |
| C | 窓なしの `cmd` から `start /wait`。遅延展開で渡す | 14 ms | **壊れる** | **渡らない** | なし | 出る | 残る | 道連れ |
| D | `conhost.exe cmd.exe` | ― | **node ・ bun からは窓が開かない**。`stdio` が `ignore` ならすぐ終わり、`pipe` なら窓を作らずパイプへ流す |  |  |  |  |  |
| E | FFI で `CreateProcessW` | 13 ms（bun）<br>23 ms（node） | 動く | 渡る | なし | 出る | 残る | 道連れ |

プロセスツリー（サーバー役から。E）。間に何も挟まない。

```text
bun.exe（サーバー役）
  cmd.exe        ← 返す pid
    conhost.exe  ← 新しい窓
    PING.EXE
```

- **B ・ D が窓に出せないのは、node の `spawn` が子に標準入出力のハンドルを必ず渡すため**。B は中継が NUL を受け取り、それを `cmd` に引き継ぐ。D の `conhost` はハンドルを受け取ると窓を作らず、疑似コンソールとしてそちらへ流す（挙動からの推測）
- **C が壊れるのは展開と解釈の順序**。遅延展開した文字列の `>` ・ `&` は演算子にならず、解釈させるには `cmd` をもう 1 段挟むことになる
- **`/T` で道連れになるのは、起動したものがサーバーの子として残るため**。A だけ残るのは、間の PowerShell がすぐ終わり、親子がつながらないから
- **E を採った**（2026-10-01、利用者の判断）。機能がすべて正しく、速く、プロセスの構成も最小。`/T` で道連れになる点は引き換えにした

> [!IMPORTANT]
> <strong>途中の形。</strong>最初は `cc.cmd` と同じく `cmd` の `start` に任せ、終わった `start` の子を探して pid を取った。すぐ終わるコマンドを取りこぼしたので A に替え、PowerShell の遅さと変数の漏れを避けるために比べ直して E にした。

### 実測の結果

テスト（第 5 章）で bun ・ node とも、FFI と `Start-Process` の両方の道で確かめた。

- 依頼ごとに新しい窓が開き（`conhost` がいる）、指定したカレントフォルダで動く
- サーバーだけを止めても、起動したものは生き残る
- 環境変数はサーバーのものを引き継ぎ、作業用の変数は持ち込まない
- コマンド文字列の `"` ・ `>` ・ `&` ・ 日本語はそのまま渡る。`echo` が書いたファイルは CP932 なので、新しい窓は既定のコードページで開いている（bun で動かしたときも同じ）

## 5. 置き場とテスト

- 本体 `src/spawn-server-ts/spawn-server-main.ts`、入口 `bin/spawn-server.cmd` ・ `bin/spawn-server`（bun を優先し、無ければ node）
- テスト `tools/40_test/run-spawn-server-tests.ts`。`run-all-tests.ps1` に足し、bun ・ node の両方で回す
- テストで確かめること: `Origin` 付きは 403、`127.0.0.1` 以外で待ち受けていない、起動した pid が実在する、サーバーだけを止めても起動したものが残る、指定したカレントフォルダで動く、新しい窓で開く、作業用の変数を持ち込まない。FFI と `Start-Process` の両方の道で回す。**窓はテスト中に開いて閉じる**（起動するのは、ファイルを 1 つ書いて終わる短いコマンドにする）
- テストで立てたサーバーと起動したものは、テストの最後に必ず止める（共通ルール「残ったプロセスを調べるときは psls を使う」）
- 使い方は `TOOLS-USAGE.html` に章を足す
- 配布物（`build-release.ps1`）には `node_modules/koffi`（1.6 MB）を含め、`package.json` の依存に版を書く。配布物を node で動かしても koffi で起動することを確かめた

## 6. 決めたこと

2026-09-30、利用者の判断。

- **名前と置き場**。`spawn-server`、`src/spawn-server-ts/`
- **窓**。依頼ごとに `cc.cmd` と同じく新しい窓を開き、コマンドが終われば閉じる
- **コマンド文字列**。新しい窓の `cmd /c` に渡す。起動は FFI で `CreateProcessW`（第 4 章の案 E）
- **応答の pid**。窓の中でコマンドを走らせているプロセスの pid を返す
- **トークン**。使わない（第 3 章）
- **呼ぶ場所**。同じ PC からだけ。ブラウザからは呼ばない

### 追加: 入力ページ（2026-10-01 承認 ・ 実装済み）

`GET /` で、コマンド行を 1 つ置いたページを返す。入力して Enter で `POST /run` し、返った pid をページに出す。ブラウザから呼ぶことになるので、上の「ブラウザからは呼ばない」を次のように改める。

- **自分のページからの依頼だけを通す**。`Origin` が `http://<Host>`（開いたときと同じ）と一致するときだけ受け、それ以外の `Origin` は今までどおり 403
- **`Host` ヘッダは `127.0.0.1:<port>` と `localhost:<port>` に限る**。よそのドメインを 127.0.0.1 に向けて（DNS リバインディング）自分のページに見せかけるのを防ぐ。`localhost` は利用者の指示で足した（2026-10-01）
- ページは本体に文字列で持つ（外部ファイル ・ CDN を使わない）。欄は command ・ cwd（省略可）の 2 つ。送ったコマンドと結果を下に積む
- テストに足すこと: `GET /` が 200 でページを返す、自分の `Origin` なら起動できる、`Host` が違えば 403

### 対応していないこと

- **同じ PC のほかのプロセス ・ ユーザーからの依頼を防げない**。トークンを使わないため（第 3 章）。127.0.0.1 に届くものは、サーバーを立てた人の権限でコマンドを起動できる。ほかのユーザーから通るかは未確認
- **コマンド文字列の `%変数%` は、窓の中の `cmd` が展開する**。`cmd` に渡す以上そうなるが、使い方の資料には書いていない
- **`taskkill /T` でサーバーを止めると、起動したものも止まる**。サーバーの子として残るため（第 4 章）。サーバーだけを止めれば残る
- **テストを回すと窓が数回開き、フォーカスを奪う**。全テストの間、ほかの作業の邪魔になる
- **同時に起動できる数に上限が無い**。入力ページは Enter で欄を空にするので同じものを二重に送りにくいが、別のものを続けて送れば、その数だけ窓が開く

<strong>結果。</strong>テストが bun ・ node とも通る（件数は第 5 章のテストの最新を見る）。`http://localhost:<port>/` も実際に開ける（curl で 200）。ページの中の JavaScript（Enter で送る ・ 結果を積む）は、ブラウザで動かしては確かめていない（Chrome の拡張がつながらなかった）。
