番号問い選んだ案
220-A予約のフォルダの名前 (キー)uuid_<project_uuid>_<プロジェクト id>。探すときは uuid の部分だけを見る。GitHub の情報は key.json に書くだけ。203-A (p261109-01-d3) を置き換える。選ばなかった案: GitHub のキーを残し、キーが変わったら前の予約を写す
221-Aプロジェクト id を変えたとき、名前の後ろを付け直すか道具が呼ばれたときに、今の id と違えば付け直す。付け直せなければ古い名前のまま使う。選ばなかった案: 付け直さない
222-Auuid が変わったときの扱いissue init --new-id で uuid を変えるとき、古い uuid のフォルダを新しい uuid の名前に移す。選ばなかった案: 何もしない
223-Bプロジェクト id を変えたときの legacy_ids の旧 idproject-uuid.txt に former_ids を足し、旧 id も自分の id として数える。選ばなかった案: 何もしない

今ある動きと試験

今ある動き: 直したあとも、次の動きを保つ。どれも run-issue-numbers-tests.ts (無ければ、予約を試す既存の試験) で見る。

  • 予約を mkdir で取る。同じ番号は 2 回取れない
  • 3 日より前の予約を消す。系列ごとの最大の 1 つは残す (日付の番号は、今日より前の日なら最大も消す)
  • worktree から呼んでも、本体と同じ置き場を使う
  • 選択肢の番号は、予約の最大と legacy_ids の旧番号の最大の、大きい方の次
  • issue init は、project-uuid.txt があれば書き換えない。--new-id のときだけ新しい uuid にする
  • 試験のときは、本物のホームを汚さず、プロジェクトの _numbers/ を使う

進め方

どの手順も、試験を先に書き、❌Red を見てから直す。bun と node の両方で流す。

  1. キーを uuid_<uuid>_<id> にし、探すときは uuid_<uuid>_ で始まるフォルダを探す (220-A)。uuid が無いプロジェクトは、今までどおりキーを決められない
  2. 古い名前のフォルダ (github_… と uuid_<uuid>) を、key.json の project_uuid を見て、新しい名前に移す。最初に呼ばれたときに道具が行う。移す先が既にあれば、移さずに警告を出す
  3. id が変わったら、名前の後ろを付け直す。付け直せなければ、古い名前のまま使う (221-A)
  4. issue init --new-id のときは、古い uuid の予約を新しい uuid の名前に写す (222-A)。実装で、移すから写すに変えた: --new-id はフォルダごとコピーして別のプロジェクトにしたときにも使うので、移すと元のプロジェクトの予約を取り上げる
  5. legacy_ids を数えるときに、旧 id も自分の id として扱う (223-B)。実装で、former_ids は作らず、既にある legacy_names (154-A、改名したときの旧名) を使うことにした。同じ役目のキーを 2 つにしないため
  6. oracle-cloud で uuid が変わった原因を調べる。直し方が 1 つに決まらなければ、案を出す
  7. TOOLS-USAGE と詳細仕様に書く。repo を作る ・ 名前を変える ・ id を変えるときに手順が要らないこと、id を変える手順 (project_id を直し、former_ids に旧 id を足す)
