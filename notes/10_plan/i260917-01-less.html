背景

html2md・convert-encoding・text 等の出力を DOS の more コマンドへパイプしてページングすると、UTF-8 の出力が CP932 として読まれて文字化けする。more は Windows 標準の .NET／PowerShell 系が持つ「出力コードページ問題」の受け手側で、課題 i260912-06 と根が同じ。

UTF-8 セーフなページャー（less）を新設する。

実装方式（決定済み）

TypeScript（bun 優先・node 予備）にする。他ツール（html2md・text・convert-encoding・psh・check-*）と同じ理由で、Node・Bun は常に UTF-8 で出すため。C#／PowerShell を選ぶと、この課題そのものを再び踏む。

置き場・呼び方は他ツールと同じ形に揃える。

ファイル役割
lesssh 入口。bun を優先、無ければ node で src/less/main.ts を実行
less.cmdcmd 入口。同じ振り分け
src/less/main.ts本体

機能範囲（決定）

A（最小限のページング）を採用。あわせて上下スクロールを追加する。2026-09-17 決定。

  • q — 終了
  • Space — 1 画面分下
  • Enter／↓ — 1 行下
  • ↑ — 1 行上
  • PageDown — 画面の高さの 2/3 くらい下
  • PageUp — 画面の高さの 2/3 くらい上

検索・行番号・g/G（先頭・末尾へ）は今回持たない（B の残り）。標準出力がパイプ／端末でない（リダイレクト先がファイル等）ときは、ページングせずそのまま流す。

暫定と恒久: 検索・行番号等、今回見送った機能は、実際に使ってみて不足を感じたら個別に足す（一度に全部作らない）。

詳細仕様

入力

  • 標準入力からパイプで受け取る（html2md | less の形）
  • ファイル引数は今回持たない。まずパイプ専用（用途は「他コマンドの出力を見る」ため）

キー入力の取得元（上下スクロール追加で新たに要る論点）

cmd | less の形では、process.stdin はデータそのもの（パイプ）で埋まっており、キー入力には使えない。先頭を1画面表示するだけの案（Space/Enter/qだけ）ならデータを読み終えた後に process.stdin を使い回せたが、上下スクロールは表示中も随時キーを受けるため、データ用のストリームとキー入力用のストリームを分ける必要がある。

Windows ではコンソール入力を CONIN$（自プロセスのコンソール入力バッファを指す予約名）で直接開けるので、process.stdin とは別にこれを開き、Node の tty.ReadStream でラップして setRawMode(true) にする。

const fd = fs.openSync('\\\\.\\CONIN$', 'r');
const key = new tty.ReadStream(fd);
key.setRawMode(true);

開けなければ（コンソールが無い環境）、スクロール操作を諦めて素通しにする（下記「開けないとき」）。

実装時に踏んだ落とし穴。素の 'CONIN$' を渡すと、Node がカレントフォルダからの相対パス（例: N:\ai-agent-tools\CONIN$）として解決してしまい、ENOENT で失敗する（Bash・PowerShell 両方の実環境で実測）。Win32 のデバイス名前空間 \\.\ を前置すると正しく開け、isTTY も true になる。

ページング

  • 標準入力を全部読み切ってから始める（戻りスクロールのため、全行をメモリに持つ）
  • process.stdout.rows で端末の行数を取り、1 画面分の行数を決める（取得できなければ 24 行）
  • 表示位置は「先頭からの行オフセット（top）」1 つで持つ。キー操作は top を動かして再描画するだけ
  • 再描画は画面クリア（\x1b[2J\x1b[H）してから top 〜 top+高さ を出す。最下行にステータス（-- less (NN%) --）を出す
  • top は 0 〜 行数-画面高さ の範囲にクランプする
  • 標準出力が端末でない（process.stdout.isTTY が false）とき、または CONIN$ を開けないときは、ページングせずそのまま出力する

終了コード

コード意味
0正常に最後まで表示、または q で終了
2引数の誤り

テスト方針

キー入力を伴う対話的な画面遷移は自動テストにしにくい。切り分けて考える。

  • 自動テストにする: 1 画面分の行数計算、top のクランプ（範囲外に動かそうとしても止まる）、isTTY が false のときにページングせず素通しする経路
  • 手動確認にとどめる: 実際のキー入力（Space・Enter・矢印・PageUp/PageDown・q）による画面遷移、CONIN$ が開けること自体、日本語を含む長文での表示崩れの有無

置き場は他ツールと同じtools/40_test/run-less-tests.ps1（＋同名の cmd）。
