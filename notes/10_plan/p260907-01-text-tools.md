## 1. 目的と背景

Claude Code の標準ツールは、UTF-8 以外のファイルで壊れる。SJIS（cmd・bat）、UTF-16LE（reg）、UTF-8BOM（html）で、読む・探す・編集する・書くのいずれもが化けるか破壊する。しかもエラーにならず**成功が返る**ことが多い。

| 標準ツール | 壊れ方 |
|---|---|
| **Read** | UTF-8 として読むので SJIS・UTF-16 が化ける |
| **Grep** | SJIS・UTF-16 を漏らす。0 件ではなく一部だけ返るので欠けに気づけない |
| **Edit** | 読めないバイトを U+FFFD にして書き戻す。破壊し、成功が返る |
| **Write** | SJIS・UTF-16 を破壊。UTF-8BOM は BOM 消失・LF 化 |
| Bash / PowerShell のファイル操作 | `cat` `sed` `Get-Content` `Set-Content` も同じに壊れる（同じ decode の罠） |

**これら「壊れるツール」の代わりを一式そろえる**のがこの計画。`Glob`（名前だけで中身を読まない）と `SendUserFile`（バイトのまま渡す）は壊れないので対象外。

### 3 つの原則

<strong>1. 文字コードと改行の「組」で扱う。</strong>文字コード単体ではなく、改行まで含めた組を判定し、書き戻すときはその組のまま保つ。

| 組 | 主な用途 | convert-encoding の用途名 |
|---|---|---|
| `sjis/crlf` | cmd・bat | `--to cmd` |
| `utf16le/crlf` | reg | （新規） |
| `utf8bom/crlf` | ps1 | `--to ps1` |
| `utf8bom/lf` | html | `--to html` |
| `utf8/lf` | md・その他 | （既定） |

<strong>2. 文字コードで場合分けしない。</strong>UTF-8 は特別扱いの本線ではなく、判定結果のひとつ。SJIS を後付けの別対応にしない。**どのファイルでも同じ 1 本を呼ぶ**と、ツールが組を判定して正しく扱う。使う前に文字コードを知っている必要がなくなる（それが今の事故のもと）。

<strong>3. 最後は Linux・Mac にも展開する。</strong>Windows だけの前提を作り込まない。判定は BOM とバイト構造だけで決まるので OS に依存しない。引っかかるのは **SJIS（CP932）が非 Windows の .NET では既定で使えない**点（`CodePages` プロバイダの登録で解く）と、**ビルド・実行の道具と実行ファイルの形**が OS で変わる点。これらは 7 章で扱う。**オプションは GNU 形（`--path`）に統一する**（PowerShell 風は採らない。OS をまたいでも綴りが同じ）。

> [!NOTE]
> <strong>標準ツールを透過的に差し替えることはできない。</strong>Read・Grep・Edit・Write はハーネス組み込みで、このツールを裏で使わせる仕組みはない。**実現形は「壊れる相手のときは自分でこのコマンドを呼ぶ」という運用＋共通ルールでの明文化**になる（いまの「ツールごとの文字コードの扱い」の表がその土台）。UTF-8 だけを触ると分かっているときは、差分表示・許可 UI が効く標準 Edit を使ってよい。

## 2. 全体設計（1 エンジン＋4 動詞）

判定エンジンは 1 つ。その上に 4 つの動詞を載せる。

| 代わり | 標準 | 役目 |
|---|---|---|
| `text read` | Read | 何であろうと読み、UTF-8 で見せる。edit 用にサイズ・更新日・範囲の合言葉も返す |
| `text find` | Grep | 何であろうと探す。パス・行番号・行＋判定した組を出す |
| `text edit` | Edit | 判定 → 部分置換 → 元の組のまま書き戻す。合言葉で競合を検知 |
| `text write` | Write | 指定した組（または元の組）で全文を書く |

### コマンドの形（多機能コマンドに決定）

**1 つの多機能コマンド `text` に、動詞をサブコマンドで載せる。**`text read` / `text find` / `text edit` / `text write` の形。実行ファイルは `text`（Windows は `text.exe`）1 つで、PATH に置くのも 1 つで済む。判定エンジンを 4 つの動詞で共有する作りとも相性がよい。独立コマンドを 4 つ並べる案は採らない。

### オプションの綴り（GNU 形に決定）

<strong>GNU 形（`--path` `--recurse` `--lines` …）に統一する。</strong>PowerShell 風（`-Path`）は採らない。理由は 2 つ: `convert-encoding` と綴りが揃うこと、将来 Linux・Mac へ展開しても綴りが同じで済むこと。短縮形は grep 慣習の `-r`（recurse）・`-i`（ignore-case）だけ添える。以降の例はこの形で書く。

## 3. 文字コードと改行の判定

ファイルごとに、まず文字コードを 1 回決める。「UTF-8 でやってみて、だめなら SJIS を足す」ではなく、**先に組を決めてから、その組で読み書きする**。全文字コードが対等。

| 順 | 条件 | 組の文字コード |
|---:|---|---|
| 1 | 先頭 `EF BB BF` | `utf8bom`（UTF-8 BOM 付き） |
| 2 | 先頭 `FF FE` | `utf16le` |
| 3 | 先頭 `FE FF` | `utf16be` |
| 4 | BOM 無しで、全体が厳密な UTF-8 として妥当 | `utf8` |
| 5 | BOM 無しで、UTF-8 として不正 | `sjis`（CP932） |

改行は中身から見る。`CRLF` が主なら crlf、`LF` だけなら lf、`CR` だけなら cr。文字コードと合わせて**組**として持つ。

### 表記の約束

ツールが出す**組は小文字**で書く。文字コードは `sjis` / `utf8` / `utf8bom` / `utf16le` / `utf16be`、改行は `crlf` / `lf` / `cr`。組は `sjis/crlf` のように `/` でつなぐ。

**日時（mtime）は `yymmdd-hhmmss-ccc`**（年 2 桁・月・日 ／ 時・分・秒 ／ ミリ秒 3 桁）。例: 2026-09-07 19:00:00.123 → `260907-190000-123`。短く、名前順が時刻順になり、合言葉の一部にも収まる。

土台は `convert-encoding` の `Detector`。ただし<strong>「両方妥当」の倒し方が動詞で変わる</strong>。

| 動詞 | UTF-8 と SJIS が両方妥当（非 ASCII） | 理由 |
|---|---|---|
| `text read` / `text find` | UTF-8 に倒す（読む・探すだけ） | 止まると探せない。UTF-8 が既定で、実ファイルの両方妥当はまれ |
| `text edit` / `text write` | **拒否して止まる**（終了 3） | 書き戻すので取り違えは破壊になる。convert-encoding の既定の拒否がそのまま正しい |

> [!NOTE]
> <strong>UTF-16 は BOM で判定する。</strong>BOM 無し UTF-16 は当てにならないので追わない。要望の `reg` は UTF-16LE ＋ BOM なので足りる。バイナリ（UTF-16 でないのに NUL を含む）は黙って飛ばし、`exe`・画像を結果に混ぜない。

## 4. text read（読む）

Read の代わり。何であろうと読み、**UTF-8 に起こして見せる**。加えて、続く `text edit` のためのメタ（組・サイズ・更新日時・合言葉）をヘッダに出す。

### オプション

| オプション | 既定 | 意味 |
|---|---|---|
| `<path>` | — | 読むファイル（必須） |
| `--from <組>` | 自動判定 | 元の組を明示して自動判定を上書き（例 `--from sjis`）。convert-encoding の `--from` と同じ「入力側」の指定 |
| `--lines A-B` | 全文 | その行範囲だけ出す（1 始まり、両端含む）。省トークン |
| `--no-number` | 番号付き | 行番号を付けずに中身だけ出す（そのまま別処理へ渡すとき） |

### 表示のしかた

**1 行目は `◆` ファイルヘッダ**（find と共通）、続いて**行番号付きの中身**。ヘッダは次の並び。パスは**渡されたまま**（read は単一ファイルなので相対化しない）、ダブルクォートで囲む（空白や `()` を含められる）。

```
◆"<path>" [<組>] size=<バイト> mtime=<yymmdd-hhmmss-ccc> [lines=A-B] digest=<hex>
```

中身の各行は **行番号を 6 桁右寄せ、続けて `:` とタブ、そのあと本文**（書式 `%6d:\t%s`）。標準 Read の `cat -n`（6 桁右寄せ＋タブ）に `:` を 1 つ足した形。下の例では見やすさのためタブを空白で表す（実際は `:` の後がタブ）。

```
# 全文を読む
text read build.cmd
→ ◆"build.cmd" [sjis/crlf] size=164 mtime=260907-190000-123 digest=3c9f0b47
     1:  @echo off
     2:  rem 参照実装から呼ぶ
     3:  powershell -NoProfile ...

# 一部だけ読む（省トークン）。その範囲の合言葉を出す
text read build.cmd --lines 3-3
→ ◆"build.cmd" [sjis/crlf] size=164 mtime=260907-190000-123 lines=3-3 digest=9f2a1c33
     3:  powershell -NoProfile ...

# 判定を上書きして強制的に sjis で読む
text read data.txt --from sjis
```

`--lines A-B` を渡すと**その範囲だけ**を出し、その範囲の合言葉（`digest`）を返す。範囲を渡さなければ全文と全体の合言葉。狭く読めるので、Read で全文を読むより**トークンが減る**。

### Claude Code 標準の Read との違い

標準の Read は `cat -n` と同じ「行番号（6 桁右寄せ）→ タブ → 中身」で、**文字コードは UTF-8 決め打ち・メタは出ない**。同じ SJIS の `build.cmd` を読むと差が出る（下の例のタブは空白で表す）。

| 標準 Read（6 桁右寄せ＋タブ） | `text read`（`◆` ヘッダ＋`:`） |
|---|---|
| `1  @echo off      2  rem �Q�Ǝ�������Ăԡ���  ← 化ける      3  powershell -NoProfile ...` | `◆"build.cmd" [sjis/crlf] size=164 mtime=260907-190000-123 digest=3c9f0b47      1:  @echo off      2:  rem 参照実装から呼ぶ  ← 正しい      3:  powershell -NoProfile ...` |

- **SJIS・UTF-16 を正しく読む**（標準は UTF-8 として読むので化ける）
- **`◆` ヘッダで組・サイズ・更新日時・合言葉を返す**（標準は本文だけ。編集の下ごしらえにならない）。ヘッダは find と共通の形
- **行番号のあとに `:` を足す**（標準は 6 桁右寄せ＋タブ、text read は 6 桁右寄せ＋`:`＋タブ）。数字だけの列と本文の境目がはっきりする

> [!NOTE]
> **合言葉（digest）＝ 3 つをまとめた値（決定）。**`text edit` の競合検知は、<strong>行範囲のハッシュ ＋ ファイルサイズ ＋ 更新日時（ミリ秒精度）</strong>の 3 つで見る。read はこの 3 つを 1 つの短い `digest` にまとめて返し、edit はそれを渡すだけでよい。<br> ハッシュの対象は**改行を LF に正規化した decode 後の文字列**（文字コード・改行の違いに依存しない）。`size` と `mtime` は人にも見えるよう別に出すが、判定は 3 つまとめた `digest` の一致で行う。**`digest` は hex 8 桁固定（32 bit）**（例 `9f2a1c33`）。これは read 時の 1 個と edit 時に計算し直す 1 個の**1 対 1 の突き合わせ**で、集合から探すわけではないため、誤一致は 1 回あたり ≈ 2⁻³² と実質ゼロ。**暗号強度は不要で CRC32 でよい**（改ざん対策ではなく“変わったか”の検知）。更新日時を含めるため、内容が同じでも `touch` 等で日時が動けば合言葉は変わる（安全側＝誤って上書きしない）。

## 5. text edit（部分置換・合言葉）

Edit の代わり。判定 → 部分置換 → **元の組のまま書き戻す**。置換対象の指し方は 2 通り。**基本は行範囲＋合言葉**（省トークン・競合検知）、標準 Edit と同じく**中身（old）で指す**やり方も選べる。置き換える中身はどちらも `--new`。

### オプション

| オプション | 意味 |
|---|---|
| `<path>` | 編集するファイル（必須） |
| `--from <組>` | 元の組を明示して自動判定を上書き（read と同じ「入力側」の指定） |
| `--lines A-B` | 置換する行範囲（合言葉方式） |
| `--digest <hex>` | <strong>基本。</strong>read が返した合言葉。行範囲＋サイズ＋更新日時を照合して競合を検知 |
| `--old <str>` | 置換対象を中身で指す（標準 Edit 風）。一意であること |
| `--old-file <path>` | 置換対象の中身をファイルから読む（長い・日本語で引数事故を避ける） |
| `--new <str>` | 置き換える中身（インライン） |
| `--new-file <path>` | 置き換える中身をファイルから読む |

対象の指し方は排他ではない。**`--lines` は範囲（スコープ）、`--old` はその中身**として、単独でも併用でもよい。

| 指定 | 動き |
|---|---|
| `--lines A-B` のみ | その**行範囲まるごと**を置換 |
| `--old` のみ | **ファイル全体で一意**な `--old` を探して置換（標準 Edit と同じ。重複するとエラー） |
| `--lines A-B` ＋ `--old` | **その範囲の中だけ**で `--old` を探して置換。他所にも出る語を範囲で一意化できる |

中身は `--new`／`--new-file` のどちらか。`--digest` はどの指し方にも付けられ、対象範囲が read 時から変わっていないかを照合する。**ファイル入力は `--old-file`／`--new-file`（"from" は使わない。`--from` は組の指定に固定）。**

### 使い方

```
# 基本：行範囲＋合言葉（read が返した digest をそのまま渡す）
text edit build.cmd --lines 3-3 --digest 9f2a1c33 --new "powershell -NoProfile ..."
→ 合言葉が合えば置換／変わっていれば エラー（別の人が更新）

# 中身で指す（標準 Edit 風）。長い置換はファイルから
text edit README.html --old-file tmp/old.txt --new-file tmp/new.txt
```

### 判定の順

1. ファイルの文字コードと改行の組を判定（両方妥当なら**拒否**）
2. 対象を特定。`--lines` があればまず範囲を絞り、`--old` があればその範囲内（無ければファイル全体）で一致箇所を探す。`--old` の一致が 0 / 複数なら**エラー**
3. `--digest` があれば、**行範囲ハッシュ ＋ サイズ ＋ 更新日時**から合言葉を計算し、**一致しなければエラー**で止める（何も書かない）
4. その範囲を `--new`／`--new-file` に差し替える
5. **元の組のまま**書き戻す。置換内容の改行は元の改行に揃える
6. 結果が元と同じならファイルに触らない

> [!NOTE]
> <strong>合言葉が守る範囲（決定）。</strong>合言葉（`digest`）は<strong>行範囲のハッシュ ＋ ファイルサイズ ＋ 更新日時（ミリ秒精度）</strong>の 3 つをまとめた値。行範囲の中身に加え、ファイル全体のサイズと更新日時も見るので、対象範囲の外が変わっても・タイムスタンプだけ動いても検知する。read が返した `digest` をそのまま渡すだけでよい。

> [!NOTE]
> <strong>AV に触れない作り。</strong>バイト列の読み書きは過去に検知された。**バイト操作はすべて exe の中で完結**させ、PowerShell でバイトを触らない（`convert-encoding` と同じ方針）。

### Claude Code 標準の Edit との違い

標準 Edit は `old_string`（全文引用・一意必須）で指し、Read 済みかどうかをハーネスが追跡して競合を防ぐ。`text edit` は同じ穴（非 UTF-8 の破壊）を埋めつつ、競合検知を `--digest` で明示する。

| 観点 | 標準 Edit | `text edit` |
|---|---|---|
| 文字コード | UTF-8 のみ安全。SJIS/UTF-16 は U+FFFD で破壊 | **全組を判定し、元の組（BOM・改行）で書き戻す** |
| 対象の指し方 | `old_string`（全文引用・一意必須） | `--lines`＋`--digest`（範囲）／`--old`（`--lines` で範囲絞り可） |
| 一意性 | 一意でないと失敗 → 文脈を足す or `replace_all` | `--lines` で範囲を絞れば `--old` を一意化できる |
| 競合検知 | Read 必須＋ハーネスが状態を追跡（会話内で変われば失敗） | <strong>`--digest` で明示。</strong>別セッション・別プロセスをまたいでも効く |
| トークン | `old_string` を全文引用（大ブロックは重い） | `--lines`＋`--digest` なら `old` を書かない（軽い） |
| 全置換 | `replace_all` あり | 現状 1 箇所（`--all` は将来） |
| UI | 差分プレビュー・許可 UI に統合 | シェル出力（差分 UI は無い） |

> [!NOTE]
> <strong>棲み分け。</strong>UTF-8 と分かっているファイルは、差分 UI と自動追跡がある**標準 Edit の方が快適**。`text edit` の主戦場は **① 非 UTF-8（sjis/utf16le/utf8bom）**、**② 大きな範囲を安く置換したいとき**、**③ 別プロセスと競合しうる編集を明示的に守りたいとき**。`--digest` を read→edit で持ち回る手間は、裏返せば**可搬な競合検知**という強みでもある。

## 6. text find・text write

### text find（Grep の代わり）

素の文字列（部分一致）で探す。パス・行番号・行に加え、read と同じく**組・サイズ・更新日時**もファイルごとに出す。正規表現は将来（`--regex`）。まず素の文字列で足りる、という要望に従う。

```
text find 日本語 --path . --recurse --include "*.cmd,*.reg" --exclude-dir node_modules
```

- 大文字小文字は既定で区別（`-i` / `--ignore-case` で無視）
- ファイル名で絞る `--include` / `--exclude`（glob）。フォルダで外す `--exclude-dir`（例 `node_modules`）
- 各ファイルの組は自動判定。`--from <組>` で全ファイルの判定を上書きできる（read と同じ「入力側」の指定）
- **複数の glob はダブルクォートで囲む**（`--include "*.cmd,*.reg"`）。囲まないと PowerShell がカンマで 2 引数に割る（共通ルールに沿う）。`--exclude-dir "node_modules,dist"` も同じ
- 既定で外すのは `.git` と 先頭 `_` のフォルダの 2 つだけ。それ以上は `--exclude-dir` で足す（既定で外しすぎない）

#### 出力形（決定）

サクラエディタの grep（ファイル毎）を参考にしつつ簡素にする。**検索フォルダ（`◎`）→ サブフォルダー（`■`）→ ファイル（`◆`）→ 一致行**の入れ子。フルパスは `◎ ＋ ■ ＋ ◆` に分かれ、**一致行にパスが付かないので読みやすい**。`◆` 行と一致行の書式は read と共通。`◎` `■` `◆` の値は**ダブルクォートで囲む**（空白や `()` を含められる）。

```
◎"N:/html2md"
  検索="日本語"  対象="*.cmd,*.reg"  再帰
■"."
◆"build.cmd" [sjis/crlf] size=164 mtime=260907-190000-123
     3:  rem 日本語コメント
     7:  echo 日本語
■"tools/50_run"
◆"app.reg" [utf16le/crlf] size=88 mtime=260907-184500-902
     5:  "名前"="日本語"
```

- `◎"検索フォルダ"`: `--path` の起点。**先頭に 1 回だけ**。次行にオプション（検索語・対象＝`--include`・再帰・大小区別など）を添える
- `■"相対パス"`: 検索フォルダ起点の相対（`/` 区切り）。**直下は `■"."`**。サブフォルダーごとにまとめる
- `◆"ファイル名" [組] size=… mtime=…`: 名前だけ（フォルダは `◎`＋`■` にある）
- 一致行は read と同じ **行番号 6 桁右寄せ ＋ `:` ＋ タブ ＋ 本文**（例はタブを空白で表す）
- **同じ行に複数マッチしても、既定ではその行を 1 回だけ出す**（grep と同じ）
- 純 grep 形（`パス:行番号:本文`）が要るときは `--bare`

> [!NOTE]
> <strong>桁（列）は既定で出さない。</strong>面倒（半角・全角やタブの数え方）を持ち込まないため。将来 `--col` を付けるなら、一致行を `<行>(<桁>):タブ本文` にする。**桁はバイト数ではなく文字数**（1 始まり。decode 後の文字位置。組でバイト長が違うため、バイトでは意味が揃わない）。桁を出すときだけ、**同じ行の複数マッチはマッチごとに 1 行**（同じ本文＋別の桁）にする。

> [!NOTE]
> **絶対パスを出さない（共通ルール）。**`◎` は `--path` の起点を出すので、**相対の `--path` を渡す**。`■`・`◆` は起点からの相対なので、利用者プロファイル配下の絶対パスは出ない。

### text write（Write の代わり）

全文を書く。**組を指定**するか、**既存ファイルの組を継承**する。実質は「Write ＋ `convert-encoding --to`」を 1 手にしたもの。

```
# 用途名で組を決めて新規に書く（convert-encoding と同じ --to 用途名）
text write new.cmd --to cmd --in tmp/body.txt
# 既存の組を保って全書き換え
text write app.reg --keep --in tmp/body.txt
```

| オプション | 意味 |
|---|---|
| `<path>` | 書くファイル（必須） |
| `--from <組>` | `--keep` のとき、既存ファイルの組の自動判定を上書きする（read と同じ「入力側」） |
| `--to <用途>` | 書き出す組（`cmd\|ps1\|html\|reg\|utf8`）。`convert-encoding --to` と同じ用途名 |
| `--keep` | 既存ファイルの組を継承して書き戻す（`--to` の代わり） |
| `--in <path>` | **書き込む中身をファイルから**（主）。標準入力（パイプ）も受ける。引数直書きは短い本文のときだけ |

<strong>中身の入力は `--in`（"from" ではない。`--from` は組の指定に固定）。</strong>大きな本文や日本語で、引数の長さ・エスケープ事故を避けるためファイル／パイプを主にする。

### 終了コード（共通）

| コード | 意味 |
|---:|---|
| 0 | 成功（text find は一致あり、text edit は置換した／変更なし） |
| 1 | text find で一致 0 件（正常） |
| 2 | エラー（対象が無い・引数が不正） |
| 3 | text edit / text write で組が両方妥当のため拒否 |
| 4 | text edit で合言葉が不一致（別の人が更新） |

## 7. 実装方針・ビルド・テスト

### 作り

`convert-encoding` と同じ作り。csproj を持たず `csc` でビルドする C# の CLI。**実行ファイルは `text` の 1 つ**で、`read`／`find`／`edit`／`write` のサブコマンドに振り分ける。<strong>判定エンジンは共有ライブラリに切り出す（決定）。</strong>4 つの動詞が同じ `Detector`・`Digest` を使うため、コピーではなく 1 か所に置く。

| 置き場 | 役目 |
|---|---|
| `src/Text/Program.cs` | 入口。第 1 引数（read/find/edit/write）でサブコマンドへ振り分ける |
| `src/Text/Detector.cs` | 文字コードと改行の組の判定（両方妥当の倒し方は呼び手が指定） |
| `src/Text/Digest.cs` | 合言葉（行範囲を LF 正規化 → ハッシュ ＋ サイズ ＋ 更新日時ミリ秒） |
| `src/Text/Read.cs` ほか | 4 つの動詞それぞれの処理。共有部分を参照する |

`convert-encoding` の `Detector`・`Converter` と重なる。**将来 convert-encoding もこの共有部分に寄せて二重持ちを解消する**のが理想だが、まずは新ツール側だけで完結させ、convert-encoding には手を入れない（動いているものを崩さない）。**非 Windows のために起動時に `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` を呼ぶ**（Windows でも無害）。

### ビルドと配置

いまは `convert-encoding` と同じく `build-text.cmd`（SJIS ＋ CRLF）で `text.exe` をビルド。出力 exe はリポジトリ直下、`*.exe` は `.gitignore` のまま（課題 i260830-16）。PATH は既存ツールと同じ場所。exe が 1 つなので配置も 1 つで済む。

### Linux・Mac への展開を見越して

最後は Linux・Mac にも展開する。**コードは今から OS 非依存に書く**が、道具立ては段階を踏む。

| 論点 | Windows（いま） | Linux・Mac（あと） |
|---|---|---|
| ビルド | `csc`（.NET Framework） | `csc` は無い。**.NET SDK の `dotnet build`** に寄せる（csproj を 1 つ足す）。C# のコードはそのまま使える |
| CP932（SJIS） | 標準で使える | **既定では使えない**。`System.Text.Encoding.CodePages` を参照し、起動時に `Encoding.RegisterProvider(CodePagesEncodingProvider.Instance)` を呼ぶ。この登録は Windows でも無害 |
| 実行ファイル | `*.exe` | 拡張子なしの実行ファイル。`dotnet publish` の自己完結ビルド、または `dotnet <dll>` |
| パス区切り | `/` で統一（共通ルールどおり）。`Path` API に任せ、文字列で `\` を組まない |  |
| ランチャー | `*.cmd` | シェルスクリプト。テスト・ビルドのランチャーは OS ごとに用意 |

> [!NOTE]
> <strong>ビルド道具（決定）。</strong>いまは `csc` のまま作り、Linux・Mac へ出す段で `dotnet`（csproj）へ移す（既存ツールと足並みがそろう・今すぐ動く）。最初から `dotnet` にすると `convert-encoding` だけ `csc` のまま残り作りが割れるので採らない。<strong>A に決定。</strong>将来 `convert-encoding` ごと `dotnet` に寄せるのが筋で、そのとき一緒に移す。`RegisterProvider` と OS 非依存の書き方だけは今から入れておく。

### テスト

`tests/` に本体、`tools/40_test/run-text-tests.ps1`（＋ cmd）にランチャー。`run-all-tests.ps1` に足す。テスト用の SJIS・UTF-16 ファイルは `convert-encoding --from hex` で作る（バイト書きの誤検知を避ける）。確かめること:

- text read: `sjis`・`utf16le`・`utf16be`・`utf8bom` を UTF-8 として見せる。size・mtime・合言葉を返す。`--lines` で範囲を絞る
- text find: Grep が漏らす日本語が当たる。組を出す。`--include`/`--exclude`/`--recurse`。バイナリを飛ばす。終了 0/1/2
- text edit: 合言葉一致で置換、不一致でエラー（終了 4）。**元の組を保つ**（`sjis/crlf` が crlf のまま）。両方妥当で拒否（終了 3）。変更なしなら触らない
- text write: `--to` と `--keep` で組が決まる

### 済んだら

動作を確認したら、**共通ルールの手作業の回避策を、この一式に差し替える**案を出す（「ツールごとの文字コードの扱い」の表と、Read/Edit/Grep の注意書き）。<strong>ルールの変更は利用者の判断を待つ。</strong>差し替えたら ai-chat-lite に周知（見出し名と変わった点だけ）。`USAGE-FOR-PROJECTS` と `README` にも使い方を足す。

### 進め方（決定）

4 つの動詞を一度に作ると重い。**穴の大きい順に、動詞ごとに区切って実装・確認する**: `text find`（要望・独立）→ `text read`（合言葉の土台）→ `text edit`（合言葉の本命）→ `text write`。各段でテストを通してから次へ。
