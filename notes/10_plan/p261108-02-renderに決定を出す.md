# render に決定を出す 計画 (ai-agent-tools)

`issue decide` で記録した決定を、`issue render` ・ `issue view` の HTML で読めるようにする。

> 📅 作成: 2026-11-08 / 更新: 2026-11-08

## 1. 決めたこと

2026-11-08 に、利用者がすべて A を選んだ。

| 番号 | 問い | 選んだ案 |
|---|---|---|
| 185-A | 決定をどこに出すか | 親が課題の決定は、その課題の本文の下に「決定」として出す。親が計画 (`p`) ・ 調査 (`r`) の決定は、最後の「計画の決定」の章にまとめる。課題を読むときに、その場で決まったことも読めるため |
| 186-A | 1 件の見せ方 | `details` で畳む。`summary` は番号 ・ 問い ・ 選んだ案、中は全部の案と本文。課題と同じ作りで、選んだ答えは開かずに読めるため |
| 187-A | 覆された決定 | 出す。灰色にし、「→ <新しい番号> で覆した」と添える。なぜ変えたかを、あとから追えるため |

## 2. 出し方

### 課題の下

- 課題の `details` の中、本文の後ろに `<h4>決定</h4>` を置き、その課題を親に持つ決定を、id の順 (連番の数の順) に並べる。決定が無い課題には何も足さない
- 1 件は `<details class="decision" id="<決定の id>">`。`summary` は `<span class="dno"><id></span> 問い → 選んだ字: 選んだ案の文`。中は、決めた日 ・ 参照 ・ ファイルへのリンクの行と、本文 (案の一覧を含む Markdown)
- 決定の `details` は既定で閉じる (選んだ答えは `summary` で読める)

### 計画の決定の章

- 親が課題でない決定があるときだけ、最後に「計画の決定 (n 件)」の章を足し、目次にも入れる。章の中は、親の番号ごとに `h2` で分ける
- 章の色は、章数に入れて振り直す (色相 280 → 0)
- `render` を課題の番号 (`<id>…`) ・ `--group` で絞ったときは、この章を出さない (絞った課題の下の決定だけを出す)

### 覆された決定

- ほかの決定の `replaces` に挙がった決定は、`details` に `superseded` の class を付け、灰色 (`#5a6472` の字、`#f1f3f6` の地) にする。`summary` の末尾に「→ 新しい id で覆した」を添える (同じページにあればリンク)
- 新しい決定の側には「← 古い id を覆した」を添える

### 壊さないもの

- **課題の数え方を変えない**。`summary` の番号は `span.no` ではなく `span.dno` にする。`span.no` にすると、`_issues.html` を課題ごとに読む `compare-migration` (`parseLegacyIssues`) が、決定を課題と数える
- タイトルバーと足の件数 (`課題 n 件 …`) には決定を混ぜない。決定があれば、件数の後ろに「・ 決定 n 件」を足す
- `decisions/` が無いプロジェクトの出力は、今と 1 字も変えない

## 3. 進め方

**今ある動き:** `render` は、章 ・ 目次 ・ 件数 ・ 状態のバッジ ・ 既定の開閉 ・ 戻るリンクと旧 HTML へのリンク ・ 画像とリンクの付け替え ・ 中身が同じなら書かない、を受け持つ。これらは `run-issue-render-tests.ts` の 71 件で守る。決定が無いときに出力が変わらないことは、試験を 1 件足して守る。

1. 試験 (`tools/40_test/run-issue-render-tests.ts`) を先に書き、❌Red を見る。課題の下に出る (185-A) ・ 計画の決定の章 (185-A) ・ 絞ったときは章が出ない ・ `summary` と中身 (186-A) ・ 覆された決定の灰色と矢印 (187-A) ・ `span.no` が増えない ・ `decisions/` が無いときは出力が変わらない
2. `src/issue/render.ts` を直し、✅Green にする。決定の読み込みは `decide.ts` の読み方を使い回す
3. 関係する試験 (render ・ decide ・ migrate) を、node と bun の両方で流す
4. 詳細仕様 (`notes/50_spec/課題ファイルの形と検査.html`) と TOOLS-USAGE の第 15 章を、作った姿に直す
5. 185〜187 を `issue decide new --parent p261108-02` で記録し、`issue view` で、このプロジェクトの画面を見て確かめる
6. [決定の記録 計画](p261108-01-決定の記録.md) の「後に回すもの」の 3 を済にする
7. commit と push (ローカルルール第 6 章)

### 結果 (2026-11-08)

- 試験を先に書き、❌Red は 13 件 (決定が無いとき ・ 絞ったときの 5 件は、前から通る)。直したあとは ✅Green: render 89 件 ・ decide 36 件 ・ migrate 72 件が、node と bun の両方で通った
- 決定の CSS は、決定があるときだけ足す。決定が無いプロジェクトの出力は変わらない
- 185〜187 は `p261108-02-d1`〜`d3` として記録した。このプロジェクトの `_issues.html` で「計画の決定 (3 件)」の章を見て確かめ、`check-contrast` も問題なし
