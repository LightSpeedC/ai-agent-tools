check-public の除外指定 計画（ファイル名とキーワードの組で誤検出を外す）

公開前の検査 check-public の誤検出を、「このファイルの、この語に当たった、この項目だけ」の指定で外せるようにする。外した件数は、出力に出す。

依頼と、いまの動き

2026-10-18、20260828-typescript-learn から依頼が来た（ai-chat-lite #1550）。配布物の TypeScript 本体（docs/js/lib/typescript.js）で、[認証情報] が 53 件出る。依頼元は、全件が字句解析器の変数名（token = scanner.scan() 等）への誤検出だと見ている。

欲しいもの

  • 「このファイルの、この語に当たった [認証情報] だけを外す」指定。ファイル全体や種別全体（--skip secret）を外すと、本物の鍵を見逃す
  • 外した件数を、出力に出す。外しすぎに気づけるように
  • 指定の形（引数か設定ファイルか）は、こちらに任された

いまの動き（コードを読んだ範囲）

  • 指摘は、1 行ずつ、項目（mail ・ path ・ secret ・ script ・ words ・ author）ごとに数える。出力は ファイル:行 [項目] で、当たった値は出さない
  • 外す手段は --skip <項目> だけ。項目ごと、すべてのファイルで外れる。ファイル単位も、語単位も無い
  • [認証情報] は、password ・ passwd ・ secret ・ api_key ・ token の語に = か : と値が続くもの。値が「8 文字以上で、英字と数字を両方含み、識別子や呼び出しの形でない」ときだけ当てる

依頼の事例は、読んだ限りでは、いまの判定で当たらない形に見える。token = scanner.scan() は、値に数字が無く、「英字と数字の両方を含む」条件に当たらないので外れる。53 件の実際の行を見ないと、除外の指定で外すべきものか、判定そのものの誤りかが分からない（決める点 60）。

設計（決める点 55 〜 59）

案の形は、依頼元の「ファイル名と語の組」を満たすものに絞った。推す案を A にしてある。

55. 指定の形

決めたこと（2026-10-18、利用者の判断）。55-A。設定ファイルに書く。

  • 55-A（推奨）: 設定ファイルに書く。推す理由: 53 件でも、指定は「ファイル 1 つ ・ 語 1 つ」で済む。ただし、プロジェクトごとに増える。毎回の呼び出しに書く形だと、Stop フック等の呼び出しすべてに同じ長い引数が要り、書き違えると結果が変わる
  • 55-B: 引数 --allow "<パス> <項目> <語>"（何度でも渡せる）。設定ファイルが増えないが、呼び出しのたびに同じ指定を渡す

56. 設定ファイルの名前と置き場

決めたこと（2026-10-18、利用者の判断）。56-A。プロジェクト直下の check-public-allow.txt。Git で管理する。

  • 56-A（推奨）: プロジェクト直下の check-public-allow.txt。Git で管理する（--allow-list <パス> で差し替えられる。除外語リストの --word-list と同じ形）。推す理由: 中身はパスと語だけで、秘密ではない。別のセッション ・ 別の PC ・ クラウドで、同じ結果になる。外す指定が履歴に残り、あとから見直せる
  • 56-B: _public-allow.txt（先頭 _ で Git の管理外）。人の名前を書く除外語リストと同じ扱いだが、別の環境で結果が変わる。外した指定が履歴に残らない

設定ファイルが無いときは、いまと同じに動く（除外語リストのような「飛ばしました」の表示は出さない）。

57. 語の当て方

決めたこと（2026-10-18、利用者の判断）。57-A。当たった行に、その語が含まれるときだけ外す（部分一致 ・ 大小を無視）。

書式は、1 行に 1 指定。空白で 3 つに分け、3 つ目は行の残り全部（語に空白を含められる）。# で始まる行と空行は読み飛ばす。

# パス          項目     語
docs/js/lib/typescript.js   secret   scanner.
  • 57-A（推奨）: 当たった行に、その語が含まれるときだけ外す（部分一致 ・ 大小を無視）。推す理由: どの項目（mail ・ words 等）にも同じ決まりで使える。語を空にする指定（ファイル × 項目の全部を外す）は、依頼の趣旨に反するので、誤りとして止める（終了コード 2）
  • 57-B: 当たった値（[認証情報] なら = の右側）が、語で始まるときだけ外す。外す範囲は狭いが、「値」の定義が項目ごとに違い、mail や path では別の決めが要る
  • 57-C: 当たったキーワード（token ・ secret 等）だけを語にする。token を外すと、そのファイルの token = '本物の鍵' も外れる。依頼の「本物の鍵を見逃さない」に反する

58. パスの書き方

決めたこと（2026-10-18、利用者の判断）。58-A。相対パスの完全一致。末尾が / のときは、そのフォルダの下すべて。

  • 58-A（推奨）: プロジェクトからの相対パス（/ 区切り）。完全一致。末尾が / のときは、そのフォルダの下すべて。推す理由: 配布物のライブラリ置き場（docs/js/lib/）をまとめて指せる。ワイルドカードは持たず、広がりすぎない
  • 58-B: 完全一致だけ。いちばん狭いが、ファイルごとに 1 行ずつ書く
  • 58-C: * を使えるワイルドカード。書き方の幅が広がるが、* の置き方を誤ると、広く外してしまう

59. 出力（外した件数）

決めたこと（2026-10-18、利用者の判断）。59-A'。外した合計 ・ 指定ごとの件数 ・ [認証情報] では、当たったキーワードの内訳 ・ 使われていない指定の警告を出す。

  除外した指摘: 55 件
    docs/js/lib/typescript.js  [認証情報]  「scanner.」  53 件（token 50 ・ secret 3）
    docs/js/lib/typescript.js  [メールアドレス]  「@example.」  2 件
  ⚠️ 使われていない除外の指定: docs/old.js  [メールアドレス]  「foo」
=== 指摘はありません（除外 55 件）===
  • 内訳に出すキーワードは、規則に決まっている固定の語（password ・ passwd ・ secret ・ api_key ・ token）。大小は小文字に寄せ、api-key ・ apikey も api_key にまとめる。検査したファイルの中身（当たった値）ではないので、「当たった値は出さない」を破らない
  • 内訳は [認証情報] のときだけ出す。mail ・ path 等には、キーワードの概念が無い
  • 語（scanner.）は設定ファイルに書かれたもので、これも検査したファイルの中身ではない
  • 1 つの指定で外れた件数が多すぎる（外しすぎ）ことと、secret のような想定外のキーワードが混ざっていることに、気づける。古くなった指定（件数 0）には、警告を出す
  • 終了コードは変えない。外した分は、指摘の件数に数えない
  • 実装: 規則に、当たったキーワードを返す口を足す（src/lib/public-rules.ts。history2html は使わない）

検討して採らなかった案: 59-A（キーワードの内訳なし）、59-B（合計の 1 行だけ。どの指定が効いたかが分からない）。

60. 検出の判定そのものの見直し（調べること。決める点ではない）

依頼の事例は、読んだ限りでは、いまの判定では当たらない形に見える。実際に当たった行の「形」を、依頼元に聞く（値は伏せて、token = <式> の式の形だけでよい。ファイルの中身を、こちらが読みに行かない）。

  • 式の形が、字句解析の変数名として普通のものなら、除外の指定で外す（この計画）
  • 判定の穴（呼び出しに引数がある形 ・ 数字を含む識別子等）が原因なら、判定を直す。別の課題として立て、利用者の判断を待つ。判定を緩めると、本物の鍵を見逃す側に倒れるため
