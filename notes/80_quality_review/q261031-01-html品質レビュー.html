HTML作成ルールの詳細適合性検証

1. 保存形式・文字コードとメタタグ

共通ルール「ドキュメントの保存場所と形式」では、HTML は BOM 付き UTF-8 で保存すること、および <head> に <meta name="format-detection" content="telephone=no"> を配置することが義務付けられている。

  • 適合BOM の付与: 調査対象の全 31 HTML ファイル（管理ドキュメント 26、ルート 2、ツールベンチ 2、viewer 1）において、先頭 3 バイトが 0xEF 0xBB 0xBF であることをバイナリ検査で確認。Markdown 生成物側は全件 BOM 無しであり、完全準拠している。
  • 適合電話番号自動リンク防止: 管理ドキュメント 26 件およびルート 2 件すべてに format-detection=no が設置されており、CVE 番号や日付、連番の誤認リンク化が防止されている。

2. タイトルバーとドキュメント作成日・更新日

「ドキュメントの作成日・更新日ルール」では、書式 📅 作成: yyyy-mm-dd / 更新: yyyy-mm-dd をタイトルバー内に表示し、フッター等に重複させないこと、および本文更新時に更新日を追随させることが規定されている。

  • 適合日付書式と配置: 管理ドキュメント全件でタイトルバー内（.titlebar .date）に正規書式で配置されている。フッター側への重複記載は全件で排除されている。
  • 要確認更新日の乖離警告（20 件）: html2md --root . --dry-run 実行時、20 ファイルで「ヘッダー更新日よりもファイルの最終更新日時が新しい」旨の警告（▲）が出力された。体裁修正（CSS 調整や微修正）のみであれば更新日を変えないルールであるため即時不適合ではないが、本文変更を伴う更新の記録漏れがないか確認が推奨される。

3. 戻るリンクとアイコンの設計

「root の README.html と資料の html は相互リンクする」ルールでは、本文（.wrap）の先頭とフッターの両方に戻るリンクを設置し、紺のバッジ（--navy1 → --navy2 の 100deg グラデーション ＋ 白文字、border-radius: 6px）、アイコンは家アイコン（⌂ または SVG）、上側は margin-top: 18px を空けることが求められている。

  • 適合上下両方への設置: README.html（親サイト ../ への戻るリンク）および全管理ドキュメント（README.html への戻るリンク）において、本文先頭とフッターの両方に配置されている。
  • 適合バッジ装飾と余白: 上側戻るリンクは .backlink { margin: 18px 0 0; } によりタイトルバーとの間に 18px の間隔が確保され、フッター側は上部余白なしで配置されている。バッジは a.home クラスにより紺色グラデーションと角丸 6px が適用されている。

4. レイアウト寸法とタイポグラフィ

本文の折り返し幅は max-width: 1600px、左右 padding: 0 30px、本文フォントサイズ 15.5px、行高 line-height: 1.85 が基本寸法として定められている。

  • 適合全管理資料で完全統一: .wrap、.titlebar .inner、footer のすべてで 1600px 幅および左右 30px padding が揃えられており、画面解像度に依存しない統一感のある表示が実現されている。

5. 配色設計と章見出しの虹色配分（Hue 減算計算）

章見出し(h1)は、虹色（紫→藍→青→緑→黄→橙→赤）を減算方向に割り当て、色相は 280°（紫）から 0°（赤）まで、刻み幅 280 ÷ (章数 - 1) で均等配分する。彩度・明度は --accent: 78%/25%、--accent2: 58%/55%、--soft: 28%/95% で固定する。

品質維持のための自動チェック方針

ローカルルール第 2 章「判断が不要な作業はいつも消化する」の適用。記録の実態追いつかせ、テストの穴埋め、機械検査の警告解消は、判断不要作業として指示を待たずに最後まで進めることができる。作業完了時には html2md、check-contrast、check-public の 3 ツールを必ず実行し、すべてクリーンであることを確認する。
