置き場と 1 件のファイルの形

置き場

ファイル名

<id>-<件名>.md (例: i261103-01-li内の表.md)。

  • <id>: i ＋ yymmdd ＋ - ＋ 2 桁の連番。連番は、英字を小文字にした 35 字 (l は欠番)。0k の次は 0m (0a ・ 0k ・ 0m)。前に使っていた大文字の L の番号は、そのまま読み、k と m の間に並べる
  • <件名>: 立てるときに決める短い名前で、あとから変えない。英数字 ・ ハイフン ・ 下線 ・ ピリオド ・ 日本語 (ひらがな ・ カタカナ ・ 漢字) だけ。空白は入れない。30 文字を超えると警告する
  • 題を直しても、ファイル名は動かない。題は本文のメタ情報の title に自由に書く

先頭に --- で囲んだメタ情報 (F2 の キー: 値 の行)、そのあとが Markdown の本文。

状態 (フォルダで持つ)

課題の状態は、state キーではなく、置いてあるフォルダで決まる (計画 p261103-01 の 126-A)。状態の正本がフォルダ 1 つなので、二重管理にならない。

フォルダ状態置ける課題
todo/未すべて
doing/着手すべて
done/済やることが残っていない (未 ・ 着手 が 0 件) 課題。from があれば confirmed が true
archived/済 (退避)done/ と同じ条件。グループの全件が済になって退避したもの
  • 状態を変えるのは、ファイルを隣のフォルダへ動かすこと (git mv)。動かしても、ファイル名 (<id>-<件名>.md) と中身は変わらない。動かすのは本文の変更と別の commit にする (git の rename 検出が、小さなファイルで外れないように)
  • state キーが残っていれば誤り (state-key)。items/ 直下や、上の 4 つ以外のフォルダにある .md も誤り (place)
  • 「未・着手」だけを読めば足りる問い (一覧 ・ 検索) は、todo/ と doing/ だけを読む。済は増え続けるが、費用は未・着手の件数で決まる

F2 の書き方の決まり

  • 先頭の行が ---。次の --- の行までがメタ情報。1 行 1 キー
  • キー: 値 の形。最初の : で分け、前後の空白を除く。キーは小文字の英数字と _
  • 引用符 ・ コメント (#) ・ 入れ子は無い。# は値の一部 (#1737 等)
  • 複数行は キー: | の塊だけ (課題 i261117-03 の決定 269-A)。次の行から、2 字下げの行が続く間が値で、各行の先頭の 2 字を除いて改行でつなぐ。塊の中の空行は、空行のまま書く (2 字の空白だけの行も読める。末尾の空白を消すエディタを通っても壊れない)。空行は、そのあとに 2 字下げの行が続くときだけ塊に含め、塊のあとの空行は含めない (今までどおり誤り)。値の末尾の改行は含まない。字下げの行が 1 つも無ければ、値が空の誤り。塊の中では : ・ 引用符 ・ --- もそのまま書ける (2 字下げの行は、メタ情報の閉じの --- と区別される)。塊でない鍵のあとの字下げの行は、今までどおり誤り
  • 値の型は 4 つだけ: 文字列 ・ 整数 ・ 真偽 (true / false) ・ 一覧 (カンマ区切りの文字列)。どのキーがどの型かは、上の表が決める
  • 値が空のキーは書かない。任意のキーは、無ければ省く。空行はメタ情報の中に置けない
  • キーの順は上の表の順。順が違っても読めるが、警告する。知らないキーも読めるが、警告する
  • UTF-8 (BOM 無し) ・ LF。BOM と CR は誤りとして止める

やること

  • 本文の中の、行頭が - [未] ・ - [着手] ・ - [済] の行。状態の語は 3 つだけで、これ以外は誤り
  • 課題が done/ か archived/ にあるのに、未 か 着手 のやることが残っていれば誤り

project-uuid.txt

課題ファイルと同じ キー: 値 の行だけで、--- の区切りは付けない (計画 p261109-01 の 207-A ・ 208-A)。

schema: 2
project_uuid: 7b0c4e1a9f3d4a62b8d51c2e6f90a3b7
project_id: ai-agent-tools
  • project_uuid は小文字 32 桁の 16 進数 (UUID のハイフン無し)。プロジェクトを見分ける内部の値
  • project_id はプロジェクトのフォルダ名 (chat の名乗り ・ :<id>: の参照 ・ Vault のノートの id と同じ値)。worktree から作ったときも、元の作業フォルダの名前を入れる。改名したら旧名を legacy_names (カンマ区切り) に残す。選択肢の番号の始まりを決めるとき、legacy_ids の :<旧名>: も自分の番号として数える (223-B)
  • 古い形の project-id.txt (schema: 1 と、乱数の project_id) も読む。issue init が、乱数を変えずに project-uuid.txt へ移し、古いほうを消す。issue check は、古い形を警告にして移すよう促す

番号の予約

課題 ・ 決定 ・ 選択肢の番号は、~/.ai-agent-tools/numbers/<キー>/ に予約してから使う (計画 p261109-01)。同じ PC の同じユーザなら、worktree でも別の clone でも重ならない。

  • キー: uuid_<project_uuid>_<project_id> (計画 i261110-01 の 220-A)。探すときは uuid_<project_uuid>_ の部分だけを見るので、GitHub のリポジトリを作る ・ 名前を変える ・ 持ち主を移す ・ プロジェクト id を変える、のどれでも同じ置き場を使い、手順は要らない。後ろの project_id は人が見て分かるための飾りで、今の id と違えば道具が付け直す (付け直せなければ古い名前のまま使う。221-A)。key.json にキーの元 (GitHub のリモート ・ project_uuid ・ project_id) を書く
  • 古い名前の置き場: 以前のキー (github_<所有者>_<名前> ・ uuid_<project_uuid>) の置き場は、key.json の project_uuid で見つけ、最初に予約するときに新しい名前に移す
  • uuid を変えたとき (issue init --new-id): 前の uuid の置き場を、新しい uuid の名前に写す (222-A)。移さないのは、コピーして別のプロジェクトにしたときに、元のプロジェクトの予約を取り上げないため
  • uuid のファイルが消えて作り直されたとき: 前の uuid が分からないので、引き継げない。新しく置き場を作るとき、同じ project_id の別の uuid の置き場があれば、[警告] で知らせる (227-A)。名前だけでは別のプロジェクトかもしれないので、引き継ぎはしない。project-uuid.txt は、できたらすぐ commit する
  • 置き場: ids/<番号>/ (課題 ・ 決定) と choices/<番号>/ (選択肢)。中に info.json (いつ ・ どの作業フォルダから ・ 何のために)。置き場の根は環境変数 AI_AGENT_TOOLS_NUMBERS_DIR で差し替えられる。ISSUE_TEST_TODAY があって、この環境変数が無いとき (試験) は、プロジェクトの _numbers/
  • 取り方: 次の番号は、予約と手元のファイルの両方の最大 + 1。mkdir で予約し (既にあれば次の番号)、予約のあとにも同じ id のファイルが無いかをもう一度見る。空いた番号を後から埋めない
  • 残し方 (205-A): 書き終えても予約を残す。予約するついでに、3 日より前の予約を消す。系列 (日付の番号は日付ごと、決定は親ごと、選択肢は 1 つ) の最大の 1 つは残す。ただし今日より前の日の日付の番号は、最大も消す

groups.txt

グループ (章) の名前を、表示順に 1 行ずつ。空行は無視する。同じ名前を 2 度書くと誤り。課題の group がここに無ければ警告する。

決定のファイル (decisions/)

選択肢で決めたことを、1 件 1 ファイルで notes/40_issues/decisions/ の直下に置く (計画 p261108-01)。状態のフォルダは持たない。覆すときは、新しい決定を立てて replaces で指す。decisions/ が無いプロジェクトもある (無くても誤りにしない)。

  • 名前は <id>-<件名>.md。件名の決まりは課題と同じ
  • id は、親の番号 + -d + 連番 (i261103-01-d1 ・ p261103-01-d96)。親は課題 (i) ・ 計画 (p) ・ 調査 (r) の番号。連番は 10 進数で 1 から数え、桁をそろえない。親の中だけで数える
  • 文字コードは課題と同じ (UTF-8 の BOM 無し ・ LF)

id: p261108-01-d1
title: 進める順
parent: p261108-01
decided: 2026-11-08
chosen: A
refs: p261106-01
legacy_ids: :ai-agent-tools:171-A

issue check の検査

issue check                  # 作業フォルダから親をたどって、プロジェクトを探す
issue check --root <dir>      # プロジェクトのフォルダを指す
issue check --json           # 結果を JSON で出す
  • プロジェクトの探し方: 作業フォルダから親へたどり、notes/40_issues/items/ を持つ最初のフォルダ。--root があれば、そのフォルダを使う。見つからなければ終了コード 5
  • 読み取り専用。何も書き換えない。ほかのプロジェクトも読まない
  • 出力に絶対パスを出さない。ファイルはプロジェクトからの相対パス (/ 区切り)

出力

[NG] notes/40_issues/items/todo/i261103-01-li内の表.md [state-key] state キーは持たない (状態はフォルダで持つ)
[警告] notes/40_issues/items/todo/i261103-02-x.md [key-order] キーの順が決まりと違う (決まり: schema ・ id ・ title ・ …)
[NG] 課題 2 件 (未 2 件 ・ 着手 0 件 ・ 済 0 件 ・ archived 0 件)。エラー 1 件 ・ 警告 1 件

最後の 1 行は、エラーがあれば [NG] 課題 N 件 (未 a 件 ・ 着手 b 件 ・ 済 c 件 ・ archived d 件)。エラー E 件 ・ 警告 W 件。エラーが無く警告があれば [OK] …。エラー 0 件 ・ 警告 W 件。どちらも無ければ [OK] …。問題なし。--json では ok ・ errors ・ warnings ・ issues (全件) ・ todo ・ doing ・ done ・ archived (フォルダごとの件数) ・ decisions (決定の件数) ・ findings (level ・ code ・ file ・ message) を持つ。決定が 1 件以上あれば、文字の出力の件数の括弧の後ろに ・ 決定 N 件 を足す。

操作

共通の決まり: 出力に絶対パスを出さない (相対パス ・ / 区切り)。終了コードは、成功 0 ・ 失敗 1 (見つからない ・ 重複 ・ 番号を使い切った) ・ 引数の誤り 5 (2 は使わない)。プロジェクトは、--root か、作業フォルダから親をたどって探す。

issue init [--root <dir>] [--new-id]

  • project-uuid.txt を作る (schema: 2 ＋ 乱数の project_uuid ＋ フォルダ名の project_id)。items/ が無ければ作るが、状態のフォルダは作らない (空フォルダを作らない)
  • 既にあれば変えず、「既にある」と出す。--new-id は project_uuid を振り直す (フォルダごとコピーして別のプロジェクトにしたとき)
  • 古い project-id.txt があれば、乱数を変えずに project-uuid.txt へ移し、古いほうを消して「移した」と出す。issue new は移さない (同時に動いた new が移し合わないため)
  • プロジェクトは、--root、無ければ作業フォルダから親をたどって見つけたもの、それも無ければ作業フォルダ

issue new --title <題> --group <グループ> [--slug <件名>] [--from <報告元>] [--refs <番号,…>] [--body <本文>] [--root <dir>] [--json]

  • todo/ に <id>-<件名>.md を作る。引数はすべて、何かを作る前に確かめる。誤りなら、何も作らず終了コード 5
  • id は、i ＋ 今日の日付 (JST の yymmdd) ＋ 連番。連番は、その日の既存の最大 (4 つのフォルダすべて) の次で、35 字 2 桁 (09 の次は 0a、0k の次は 0m、0z の次は 10)。その日の最初は 01
  • 件名は、--slug があればそれ、無ければ題から作る (使えない文字 ・ 空白は - に直し、30 文字までに切る)。--slug が使えない文字を含む ・ 30 文字を超える ・ 題からも作れない (記号だけ等) ときは終了コード 5
  • groups.txt があれば、--group がそこに並んでいる名前であること (誤字を防ぐため)。無ければ何でもよい
  • --from があれば、from と confirmed: false を書く。--refs は番号をカンマで区切り、カンマのあとに空白 1 つで書く。chat の発言の番号 (#1923) も並べて書ける。形が違えば終了コード 5
  • メタ情報は、決まりの順で書く。本文は、閉じの --- の次の空行のあと。--body が無ければ空行だけ。UTF-8 (BOM 無し) ・ LF
  • project-uuid.txt も古い project-id.txt も無ければ、issue init と同じに作る。--root で指したプロジェクトに items/ が無くても作れる。--root が無く、プロジェクトが見つからなければ終了コード 5 (issue init を促す)
  • 番号の予約: 第 2 章「番号の予約」のとおり、~/.ai-agent-tools/numbers/<キー>/ids/<id>/ に取る
  • 予約が効くのは同じ PC の同じユーザの中だけ。別の PC やクラウドで、件名違いに同じ番号が立つと、issue check の duplicate が後から止める
  • 出力: [OK] <相対パス> を作った (<id>)。--json は { id, file }
  • 今日の日付は、環境変数 ISSUE_TEST_TODAY (yyyy-mm-dd) で固定できる (試験用。環境変数の仕様)

issue show <id> [--root <dir>] [--json]

  • <id>- で始まるファイルを、4 つのフォルダから探して読む。id は完全一致 (例: i261103-01)。形が違えば終了コード 5、見つからなければ 1、同じ id のファイルが複数あれば 1 (「複数ある」と出す)
  • 出力: 1 行目に <id> <状態> (<フォルダ>/) <相対パス>、続けてファイルの全文。archived/ の課題は、状態が 済 で、フォルダが archived/
  • --json: id ・ state (未 ・ 着手 ・ 済) ・ folder ・ file ・ meta (キーと値) ・ body ・ todos ({ state, text } の配列)

issue list [--state 未,着手,済,archived | --all] [--group <g>] [--missing <鍵,…>] [--root <dir>] [--json]

  • --missing <鍵,…> は、その鍵のどれかを持たない課題だけに絞る (課題 i261117-03。決定 271-A)。鍵は version ・ released ・ kind ・ note をカンマで区切る (例: --missing version,note)。--state ・ --all ・ --group と一緒に使える。鍵が空 ・ 4 つ以外なら終了コード 5。件数の行は絞った後の件数
  • 既定は未・着手 (todo/ と doing/ だけを読む)。--state は、未 ・ 着手 ・ 済 (done/) ・ archived をカンマで区切る。--all は 4 つすべて。--state と --all は同時に使えない。知らない語は終了コード 5
  • --group で、グループが一致するものだけに絞る
  • id の順に並べる (日付、次に 36 進数の連番。文字コード順ではない: L は 0 〜 9 と a 〜 k の後)。フォルダには関わらない
  • 出力: 1 行 1 件 <id> <状態> <グループ> <題> (archived/ は 済 (archived))、最後の行が N 件。--json は { id, state, folder, group, title, created, file } の配列
  • メタ情報が読めない課題は、飛ばして標準エラーに警告を出す (終了コードは 0)。理由は issue check で確かめる
  • 費用は、読むフォルダの件数で決まる。済 ・ archived/ は、既定では読まない

issue search <語> [--regex] [--state 未,着手,済,archived | --all] [--group <g>] [--root <dir>] [--json]

  • 題と本文 (ファイルの全文) から、語を含む行を探す。英字は大小を区別しない。語は 1 つの文字列で、空白を含めて一致させる。語が無ければ終了コード 5
  • --regex を付けたときだけ、語を正規表現として探す (213-A。"表|幅" 等)。英字の大小は区別しない。式が読めなければ終了コード 5。付けなければ、| ・ ( 等の記号も文字として探す
  • 読むフォルダ (既定は未・着手。--state ・ --all) と --group の絞り方は、list と同じ
  • 出力: list と同じ 1 行 ＋ 一致した行 ( L<行番号>: <行>。1 件の課題につき 3 行まで、1 行は 120 文字まで) ＋ 最後の行が N 件。--json は、課題の配列に matches ({ line, text } の配列。全件) を足したもの
  • メタ情報が読めない課題は、飛ばして標準エラーに警告を出す。見つからなければ 0 件 で終了コード 0
  • 決定も探す (196-A): decisions/ の全部の決定 (親の課題の状態によらない) から、同じ決まりで探し、課題の後ろに <id> 決定 (親 <親の番号>) <問い> と一致した行を出す。N 件 は課題と決定の合計。--state ・ --all は課題だけに効く。--group を付けたときは、決定を探さない (グループは課題の持ち物)。--json では、決定は { kind: "decision", id, parent, title, file, matches } で、課題の後ろに並ぶ

issue set <id> [--version <版>] [--released <yyyy-mm-dd hh:mm>] [--kind <種別>] [--note <説明>] [--started <yyyy-mm-dd hh:mm>] [--done <yyyy-mm-dd hh:mm>] [--root <dir>] [--json]

  • 6 つの鍵 (version ・ released ・ kind ・ note ・ started ・ done) を書く (課題 i261117-03。決定 269-A 〜 272-B。started ・ done は課題 i261120-01 の決定 285-A: 値の形は released と同じ yyyy-mm-dd hh:mm。archived/ の課題にも書ける。--state が書いた値は、同時に渡した --started ・ --done で上書きされる)。その行だけを書き換え、知らない鍵 ・ 鍵の並び ・ 本文は変えない。フォルダも動かさない。commit はしない
  • 新しい鍵は、鍵の順 (refs の後ろに version → released → kind → note) で、手前にある鍵の後ろへ入れる。書いてある鍵は、その行 (| の塊なら塊の全部) を置き換える。値が空 (--version "") なら、その鍵を消す。無い鍵を空にしても何もしない。同じ値なら、ファイルを変えない
  • --note は複数行にできる。1 行で、前後に空白が無く、| で始まらない値は 1 行で書き、そうでなければ note: | の塊で書く。読み戻すと、書いた文字列と同じ (末尾の改行 ・ 空白だけは落とす)。--version ・ --kind ・ --released に改行は書けない (終了コード 5)
  • --released が yyyy-mm-dd hh:mm の実在する日時でなければ、書かずに終了コード 5。--state と一緒に指定でき、先に鍵の検査だけをし、状態を動かしてから、鍵を書く。状態の指定が誤り ・ 済にできない ・ archived/ にある ・ 鍵の値が誤りのどれでも、何も変えない (鍵だけ書かれて状態が動かない、がない)。archived/ の課題にも、鍵だけなら書ける (状態を問わない。リリースの組み立てが版を書くため)
  • BOM か CR のあるファイル ・ メタ情報が読めないファイルは書き換えない (終了コード 1)。指定が 1 つも無ければ 5、id が見つからなければ 1
  • 書き換えは原子的 (課題 i261118-01。決定 273-A)。set ・ confirm ・ todo ・ decide set ・ render が既にあるファイルを書き直すときは、同じフォルダの一時ファイル (*.tmp) に書いてから置き換える (共通の writeAtomic)。途中で落ちても、半分だけ書かれたファイルは残らない。同じ課題に同時に書く 2 つの操作が、互いの変更を消すことは防がない (読んでから書くまでの錠は持たない)
  • 形の誤り (重複 ・ x-foo など) がメタ情報に残っていても、その行だけを書き換える (x-foo を残すため)。書いたあと、標準エラーに [警告] <ファイル>: メタ情報に形の誤りが N 件残っている。issue check で確かめる を出す (決定 274-A。終了コードは 0。--json の標準出力は変わらない)
  • 出力: [OK] <id> の version ・ note を書いた (<ファイル>)。変わらなければ「変更なし」。--json は { id, changed, file } (--state と一緒なら、状態の JSON に changed を足す)
  • 前からある --state の動きは変わらない (下の節)

issue set <id> --state 未|着手|済 [--root <dir>] [--json]

  • 状態を変える = ファイルを、隣のフォルダへ動かすこと (todo/ ・ doing/ ・ done/)。git の管理下 (追跡中) なら git mv で動かし、ステージされた rename になる。そうでなければ名前を変えるだけ。commit はしない。動かしたあとに、日時を書く (課題 i261120-01。決定 278-A ・ 279-A ・ 282-A。JST の yyyy-mm-dd hh:mm): 着手へ動かすと、started が無ければ書く (最初の着手日。再着手で上書きしない)。済へ動かすと done を書く。済から未・着手へ戻すと done を消す (started は残す)。すでにその状態なら動かさず、done も上書きしない。git mv は名前の変更だけを stage するので、日時の書き込みは stage 前の変更として残る (git status では RM)。日時を書けなければ (BOM ・ CR ・ メタ情報が読めない)、状態は動かしたまま、標準エラーに [警告] を出す (終了コードは 0)
  • 済にするときは、条件を満たさなければ、動かさずに終了コード 1 (理由を出す): やること (未 ・ 着手) が残っている ・ from があるのに confirmed が true でない
  • 既にその状態なら、何もせず終了コード 0 (「既に」と出す)。archived/ の課題は動かさない (終了コード 1。issue unarchive を促す)。--state に archived や知らない語は終了コード 5。--state が無い ・ id の形が違うときも 5、見つからなければ 1
  • 出力: [OK] <id> を <旧> から <新> へ動かした (todo/ → doing/)。--json は { id, state, folder, from: { state, folder }, file, stamps } (stamps は、書いた・消した日時の鍵)

issue todo <id> [--add <文> | --done <n> | --doing <n> | --undone <n>] [--root <dir>] [--json]

  • 引数が無ければ、やることを番号つきで出す (<n> [<状態>] <文>)。--json は { id, todos: [{ n, state, text }] }
  • --add は、やることの最後に - [未] <文> を足す (やることの節が無ければ、ファイルの最後に ## やること の節を作る)。--done ・ --doing ・ --undone は、n 番目の状態を 済 ・ 着手 ・ 未 にする。操作は 1 つだけ。番号が整数でない ・ 範囲外 ・ 文が空 ・ 改行を含むときは終了コード 5
  • done/ ・ archived/ の課題には、未のやることを足せず、やることを 未 ・ 着手 に戻せない (終了コード 1。先に issue set --state 着手)。済のままにする操作は通る
  • BOM や CR のあるファイルは、書き換えずに終了コード 1 (issue check で直す)。出力: [OK] <id> のやること <n> を <状態> にした: <文>

issue confirm <id> [--undo] [--root <dir>] [--json]

  • 報告元の確認 (confirmed) を true に直す。--undo は false に戻す。フォルダは動かさず、その行だけを書き換える (キーの順は変えない)。confirmed のキーが無ければ、from の次に足す
  • from (報告元) が無い課題は、終了コード 5 (confirmed は、他プロジェクトからの報告の課題だけに要る。ファイルは変えない)
  • 既に同じ値なら、何もせず終了コード 0 (「既に」と出す)。done/ ・ archived/ の課題は、false に戻せない (終了コード 1。先に issue set --state 着手)。true にする操作は通る (直接動かした誤りを直せる)
  • BOM や CR のあるファイルは、書き換えずに終了コード 1。見つからなければ 1、id の形が違う ・ id が無い ・ 知らないオプションは 5
  • 出力: [OK] <id> の報告元の確認 (confirmed) を true にした (報告元: <from>)。--json は { id, confirmed, from, changed, file }

issue render [<id>…] [--state … | --all] [--group <g>] [--out <ファイル>] [--standalone] [--root <dir>] [--json]

  • 課題の Markdown から、人が見る HTML を作る。生成だけで、開かない (計画の 134-A。開くのは issue view)。既定の出力先は notes/40_issues/_issues.html で、先頭 _ なので Git 管理外 (commit しない。131-A)
  • 範囲: 既定は未・着手・済 (archived/ は含めない)。--state ・ --all ・ --group は list と同じ。<id> を 1 つ以上指せば、その課題だけを、どのフォルダからでも作る。見つからない id は終了コード 1、id の形が違えば 5
  • ページの構成: タイトルバー (件数) ・ 戻る (README.html) と旧 HTML (issues-legacy.html があれば) へのリンク ・ 目次 ・ グループごとの章。章の順は groups.txt の並びで、無いものは最初の課題の id の順。章の色は章数で決まる (色相 280 → 0)
  • 課題の行 (130-A): details の summary に、番号 → 状態のバッジ → 題の順に出す。バッジは 未 = b-none ・ 着手 = b-warn ・ 済 = b-ok、archived/ は「済 ・ archived」。未・着手は開き、済は閉じる。本文の前に、作成日 ・ 報告元 (確認待ち / 確認済み) ・ 参照 (ページの中の課題は #id のリンク) ・ ファイルへのリンクを出す
  • 決定 (計画 p261108-02 の 185-A ・ 186-A ・ 187-A): decisions/ の決定のうち、親が課題のものは、その課題の本文の後ろに <h4>決定</h4> と並べる (id の順)。親が計画 ・ 調査のものと、親の課題が items/ に無いものは、最後の「課題の外の決定 (n 件)」の章 (195-A) に、親の番号ごとの h2 で並べ、目次にも入れる。<id> ・ --group で絞ったときと、archived だけのページ (_issues-archive.html ・ --state archived。197-A) には、この章を出さない。親の課題が archived の決定は、その課題と一緒に保管のページに出る。1 件は閉じた details.decision で、summary は span.dno の番号 → 問い → 「→ 選んだ字: 案の文」。中は、決めた日 ・ 参照 ・ ファイルへのリンクと、本文 (全部の案)。ほかの決定の replaces に挙がった決定は superseded で灰色にし、「→ 新しい id で覆した」を、覆した側には「← 古い id を覆した」を添える。番号を span.no にしないのは、_issues.html を課題ごとに読む道具が、決定を課題と数えないため。件数の後ろに「・ 決定 n 件」(出した数) を足す。決定が無ければ、出力は決定を入れる前と同じ (CSS も足さない)
  • 本文の変換: 見出し (## は h3、### は h4 …) ・ 段落 ・ 箇条書き (入れ子 ・ 番号つき。やること行は状態のバッジつき) ・ コードブロック (言語つき) ・ 表 (右寄せの列は、見出しも右寄せ) ・ 引用 ・ callout (> [!NOTE] 等) ・ 区切り線 ・ 太字 ・ インラインのコード ・ リンク ・ 画像 ・ <br>。Markdown の中の HTML は、解釈せずエスケープする (<br> だけ通す)。javascript: 等のリンクは、リンクにしない。ページに JS は含まない
  • 画像 (128-A ・ 129-A): ../images/… を、出力から見た相対パスに直す。プロジェクトの外 ・ 画像でない拡張子 ・ 無いファイルは、[画像が見つからない: 名前] に置き換え、標準エラーに警告を出す (終了コードは 0)。明るい版 (#gh-light-mode-only) だけを出し、暗い版 (#gh-dark-mode-only) は出さない。生成した HTML は、背景が常に淡い色なので、暗い版を出すと浮くため (計画 129-A の <picture> による切り替えではなく、この形にした)
  • --out <ファイル>: 指した場所に作る。リンクと画像のパスは、その場所からの相対パス。--standalone (渡す用。--out と一緒に使う。無ければ終了コード 5): 画像を data: URI で埋め込み、戻る ・ 旧 HTML ・ ファイル ・ ほかのファイルへのリンクを外す (ページの中のリンクは残る)
  • 書き方: BOM 付き UTF-8 ・ LF、<meta name="md-skip"> を入れる。末尾に、作った日時 (JST) と件数を出す。日時の部分を除いて中身が同じなら、書かず「変更なし」と出す (更新日時と差分が動かない)
  • 出力: [OK] <相対パス> を作った ・ を作り直した ・ は変更なし ((課題 N 件) つき)。--json は { file, issues, written, warnings } (written は created ・ updated ・ unchanged)。出力先が root の外なら、file はファイル名だけ。課題のファイルは書き換えない。メタ情報が読めない課題は、飛ばして警告を出す
  • 作った日時は、環境変数 ISSUE_TEST_NOW (yyyy/mm/dd hh:mm:ss) で固定できる (試験用。環境変数の仕様)

issue stats [--since <yyyy-mm-dd>] [--until <yyyy-mm-dd>] [--root <dir>] [--json] (日別の集計)

  • 課題 i261120-01 の決定 283-A。日別に 立てた (created がその日) ・ 着手にした (started の日付がその日) ・ 済にした (done の日付がその日) ・ 残り を出す。4 つのフォルダ (archived/ も) の全課題が対象。書き換えない
  • 残り = その日の終わりに、created がその日以前で、かつ (done が無い か done の日付がその日より後) の数。状態の履歴は持たないので、戻した課題は今の状態で数える近似。同じ日に立てて済にした課題は、その日の残りに入らない
  • done が無いのに済 (done/ ・ archived/) の課題は、残りに数える (済にした日が分からないため)。その件数を、テキストでは末尾の行に、--json では undatedDone に出す。issue backfill-done で減らせる
  • 範囲: --since の既定は created ・ started ・ done のいちばん古い日付、--until の既定は今日 (JST)。1 日 1 行で、件数が 0 の日も出す。日付の形が違う ・ 実在しない ・ --since が --until より後は終了コード 5。メタ情報を読めない課題があれば、集計せず終了コード 1
  • 出力: 日付 ・ 立てた ・ 着手 ・ 済 ・ 残り の表。--json は { since, until, days: [{ date, created, started, done, remaining }], undatedDone }
