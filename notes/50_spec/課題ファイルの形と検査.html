課題ファイルの形と検査の仕様 (ai-agent-tools)

課題管理ツール issue が読み ・ 検査する、課題ファイルと project-id.txt の形。いまは、読み込み ・ issue check ・ init ・ new ・ show ・ list ・ search ・ set ・ todo ・ confirm ・ archive ・ unarchive ・ render まで。

📅 作成: 2026-11-03 / 更新: 2026-11-08

課題を 1 件 1 ファイルで持つ形と、その検査 (issue check) のいまの姿。決めた経緯と、番号付きの決定は 課題管理ツール 計画 にある。実装と食い違ったら、実装が正しい。

この仕様が扱う範囲: 課題ファイルの形 ・ project-id.txt ・ groups.txt ・ issue check ・ init ・ new ・ show ・ list ・ search ・ set ・ todo ・ confirm ・ archive ・ unarchive ・ render ・ view と、更新の操作の最後の自動の作り直し。横断は、まだ実装していない (第 4 章)。

置き場と 1 件のファイルの形

置き場

置き場中身
notes/40_issues/items/todo/状態が未の課題
notes/40_issues/items/doing/状態が着手の課題
notes/40_issues/items/done/状態が済の課題。グループが片付くまで、ここに残す
notes/40_issues/items/archived/グループの全件が済になって、退避した課題 (済のまま)。done/ と同じ条件を満たす
notes/40_issues/items/project-id.txtプロジェクトを見分ける UUID。リポジトリに commit する
notes/40_issues/items/groups.txtグループ (章) の名前を、表示順に 1 行ずつ並べる。任意

ファイル名

<id>-<件名>.md (例: i261103-01-li内の表.md)。

  • <id>: i ＋ yymmdd ＋ - ＋ 2 桁の連番。連番は 36 進数で、英字は小文字。l は読み間違えるので大文字の L と書く (0a ・ 0k ・ 0L ・ 0m)
  • <件名>: 立てるときに決める短い名前で、あとから変えない。英数字 ・ ハイフン ・ 下線 ・ ピリオド ・ 日本語 (ひらがな ・ カタカナ ・ 漢字) だけ。空白は入れない。30 文字を超えると警告する
  • 題を直しても、ファイル名は動かない。題は本文のメタ情報の title に自由に書く

1 件のファイル

先頭に --- で囲んだメタ情報 (F2 の キー: 値 の行)、そのあとが Markdown の本文。

---
schema: 1
id: i261103-01
title: li の中の表を、表のまま出す
group: html2md
created: 2026-11-03
from: ai-chat-lite #1737
confirmed: false
refs: p261103-01
---

(本文。Markdown)

## やること
- [未] convertList で項目の中の表を convertTable に渡す
- [着手] check-markdown で実測する
- [済] 原因の特定

キー項目

キー必須値備考
schema必須整数 1形の版
id必須上の <id> の形ファイル名の先頭と一致させる
title必須1 行の文字列最初の : で分けるので、値の中にコロンがあってもよい
group必須文字列章 (グループ) の名前。groups.txt があれば、そこに並んでいる名前
created必須yyyy-mm-dd (実在する日付)立てた日。変えない
from任意文字列 (プロジェクト名 #発言番号)他プロジェクトからの報告のときだけ書く
confirmedfrom があるとき必須true / false報告元の確認。true になるまで、done/ ・ archived/ に置けない (済にできない)
refs任意カンマ区切りの番号 (p261103-01, r261025-01)計画 ・ 調査 ・ 課題の番号。ほかのプロジェクトの番号は プロジェクト名:番号

更新日 (updated) は持たない。更新の経緯は git log -- <課題のファイル> で見る。state も持たない (次の「状態」)。

状態 (フォルダで持つ)

課題の状態は、state キーではなく、置いてあるフォルダで決まる (計画 p261103-01 の 126-A)。状態の正本がフォルダ 1 つなので、二重管理にならない。

フォルダ状態置ける課題
todo/未すべて
doing/着手すべて
done/済やることが残っていない (未 ・ 着手 が 0 件) 課題。from があれば confirmed が true
archived/済 (退避)done/ と同じ条件。グループの全件が済になって退避したもの
  • 状態を変えるのは、ファイルを隣のフォルダへ動かすこと (git mv)。動かしても、ファイル名 (<id>-<件名>.md) と中身は変わらない。動かすのは本文の変更と別の commit にする (git の rename 検出が、小さなファイルで外れないように)
  • state キーが残っていれば誤り (state-key)。items/ 直下や、上の 4 つ以外のフォルダにある .md も誤り (place)
  • 「未・着手」だけを読めば足りる問い (一覧 ・ 検索) は、todo/ と doing/ だけを読む。済は増え続けるが、費用は未・着手の件数で決まる

F2 の書き方の決まり

  • 先頭の行が ---。次の --- の行までがメタ情報。1 行 1 キー
  • キー: 値 の形。最初の : で分け、前後の空白を除く。キーは小文字の英数字と _
  • 引用符 ・ コメント (#) ・ 複数行 ・ 入れ子は無い。# は値の一部 (#1737 等)
  • 値の型は 4 つだけ: 文字列 ・ 整数 ・ 真偽 (true / false) ・ 一覧 (カンマ区切りの文字列)。どのキーがどの型かは、上の表が決める
  • 値が空のキーは書かない。任意のキーは、無ければ省く。空行はメタ情報の中に置けない
  • キーの順は上の表の順。順が違っても読めるが、警告する。知らないキーも読めるが、警告する
  • UTF-8 (BOM 無し) ・ LF。BOM と CR は誤りとして止める

やること

  • 本文の中の、行頭が - [未] ・ - [着手] ・ - [済] の行。状態の語は 3 つだけで、これ以外は誤り
  • 課題が done/ か archived/ にあるのに、未 か 着手 のやることが残っていれば誤り

project-id.txt

課題ファイルと同じ キー: 値 の行だけで、--- の区切りは付けない。

schema: 1
project_id: 7b0c4e1a9f3d4a62b8d51c2e6f90a3b7
  • project_id は小文字 32 桁の 16 進数 (UUID のハイフン無し)
  • project_name は持たない (フォルダ名から読む。リネームで古くならないため)

groups.txt

グループ (章) の名前を、表示順に 1 行ずつ。空行は無視する。同じ名前を 2 度書くと誤り。課題の group がここに無ければ警告する。

決定のファイル (decisions/)

選択肢で決めたことを、1 件 1 ファイルで notes/40_issues/decisions/ の直下に置く (計画 p261108-01)。状態のフォルダは持たない。覆すときは、新しい決定を立てて replaces で指す。decisions/ が無いプロジェクトもある (無くても誤りにしない)。

  • 名前は <id>-<件名>.md。件名の決まりは課題と同じ
  • id は、親の番号 + -d + 連番 (i261103-01-d1 ・ p261103-01-d96)。親は課題 (i) ・ 計画 (p) ・ 調査 (r) の番号。連番は 10 進数で 1 から数え、桁をそろえない。親の中だけで数える
  • 文字コードは課題と同じ (UTF-8 の BOM 無し ・ LF)
---
schema: 1
id: p261108-01-d1
title: 進める順
parent: p261108-01
decided: 2026-11-08
chosen: A
refs: p261106-01
legacy_ids: :ai-agent-tools:171-A
---

## 案

- A: フェーズ 5 を先に作る
- B: 計画どおり、フェーズ 1 から順に進める
キー必須値
schema必須1
id必須ファイル名の先頭と同じ
title必須問い (1 行)
parent必須親の番号。id の -d より前と同じ
decided必須決めた日 (実在する yyyy-mm-dd)
chosen必須選んだ案の英大文字 1 字。本文に、その字の案の行がある
refs任意参照する課題 ・ 計画 ・ 調査 ・ 決定の番号 (カンマ区切り)。別プロジェクトは :名前:番号 か 名前:番号
replaces任意この決定が置き換えた決定の id (カンマ区切り。形は refs と同じ)
legacy_ids任意旧番号。:プロジェクト名:旧番号 をカンマで区切る

案の行は - X: 文 (X は英大文字 1 字)。本文のどこに置いてもよい。## 案 の見出しは issue decide new が書く形で、検査はしない。

issue check の検査

issue check                  # 作業フォルダから親をたどって、プロジェクトを探す
issue check --root <dir>      # プロジェクトのフォルダを指す
issue check --json           # 結果を JSON で出す
  • プロジェクトの探し方: 作業フォルダから親へたどり、notes/40_issues/items/ を持つ最初のフォルダ。--root があれば、そのフォルダを使う。見つからなければ終了コード 5
  • 読み取り専用。何も書き換えない。ほかのプロジェクトも読まない
  • 出力に絶対パスを出さない。ファイルはプロジェクトからの相対パス (/ 区切り)

出力

[NG] notes/40_issues/items/todo/i261103-01-li内の表.md [state-key] state キーは持たない (状態はフォルダで持つ)
[警告] notes/40_issues/items/todo/i261103-02-x.md [key-order] キーの順が決まりと違う (決まり: schema ・ id ・ title ・ …)
[NG] 課題 2 件 (未 2 件 ・ 着手 0 件 ・ 済 0 件 ・ archived 0 件)。エラー 1 件 ・ 警告 1 件

最後の 1 行は、エラーがあれば [NG] 課題 N 件 (未 a 件 ・ 着手 b 件 ・ 済 c 件 ・ archived d 件)。エラー E 件 ・ 警告 W 件。エラーが無く警告があれば [OK] …。エラー 0 件 ・ 警告 W 件。どちらも無ければ [OK] …。問題なし。--json では ok ・ errors ・ warnings ・ issues (全件) ・ todo ・ doing ・ done ・ archived (フォルダごとの件数) ・ decisions (決定の件数) ・ findings (level ・ code ・ file ・ message) を持つ。決定が 1 件以上あれば、文字の出力の件数の括弧の後ろに ・ 決定 N 件 を足す。

終了コード

コード意味
0エラーが無い (警告があってもよい)
1エラーが 1 件以上ある
5引数の誤り ・ プロジェクトが見つからない

2 は使わない (Stop フックが 2 を「続ける」と読むため)。

操作

共通の決まり: 出力に絶対パスを出さない (相対パス ・ / 区切り)。終了コードは、成功 0 ・ 失敗 1 (見つからない ・ 重複 ・ 番号を使い切った) ・ 引数の誤り 5 (2 は使わない)。プロジェクトは、--root か、作業フォルダから親をたどって探す。

issue init [--root <dir>] [--new-id]

  • project-id.txt を作る (schema: 1 ＋ 乱数の project_id)。items/ が無ければ作るが、状態のフォルダは作らない (空フォルダを作らない)
  • 既にあれば変えず、「既にある」と出す。--new-id は project_id を振り直す (フォルダごとコピーして別のプロジェクトにしたとき)
  • プロジェクトは、--root、無ければ作業フォルダから親をたどって見つけたもの、それも無ければ作業フォルダ

issue new --title <題> --group <グループ> [--slug <件名>] [--from <報告元>] [--refs <番号,…>] [--body <本文>] [--root <dir>] [--json]

  • todo/ に <id>-<件名>.md を作る。引数はすべて、何かを作る前に確かめる。誤りなら、何も作らず終了コード 5
  • id は、i ＋ 今日の日付 (JST の yymmdd) ＋ 連番。連番は、その日の既存の最大 (4 つのフォルダすべて) の次で、36 進数 2 桁 (09 の次は 0a、0k の次は 0L)。その日の最初は 01
  • 件名は、--slug があればそれ、無ければ題から作る (使えない文字 ・ 空白は - に直し、30 文字までに切る)。--slug が使えない文字を含む ・ 30 文字を超える ・ 題からも作れない (記号だけ等) ときは終了コード 5
  • groups.txt があれば、--group がそこに並んでいる名前であること (誤字を防ぐため)。無ければ何でもよい
  • --from があれば、from と confirmed: false を書く。--refs は番号をカンマで区切り、カンマのあとに空白 1 つで書く。形が違えば終了コード 5
  • メタ情報は、決まりの順で書く。本文は、閉じの --- の次の空行のあと。--body が無ければ空行だけ。UTF-8 (BOM 無し) ・ LF
  • project-id.txt が無ければ、issue init と同じに作る。--root で指したプロジェクトに items/ が無くても作れる。--root が無く、プロジェクトが見つからなければ終了コード 5 (issue init を促す)
  • 番号の予約: 作る前に notes/40_issues/_lock/<id>/ を mkdir で作る (mkdir は既にあれば失敗するので、排他になる)。先頭 _ のフォルダなので Git 管理外。取れなければ次の番号を試し、作り終えたら消す。60 秒より古い予約は、持ち主が居ないとみなして消し、取り直す。予約を取ったあとにも、同じ id のファイルが無いかをもう一度見る
  • 予約が効くのは同じ PC の中だけ。別の PC やクラウドで、件名違いに同じ番号が立つと、issue check の duplicate が後から止める
  • 出力: [OK] <相対パス> を作った (<id>)。--json は { id, file }
  • 今日の日付は、環境変数 ISSUE_TEST_TODAY (yyyy-mm-dd) で固定できる (試験用。環境変数の仕様)

issue show <id> [--root <dir>] [--json]

  • <id>- で始まるファイルを、4 つのフォルダから探して読む。id は完全一致 (例: i261103-01)。形が違えば終了コード 5、見つからなければ 1、同じ id のファイルが複数あれば 1 (「複数ある」と出す)
  • 出力: 1 行目に <id> <状態> (<フォルダ>/) <相対パス>、続けてファイルの全文。archived/ の課題は、状態が 済 で、フォルダが archived/
  • --json: id ・ state (未 ・ 着手 ・ 済) ・ folder ・ file ・ meta (キーと値) ・ body ・ todos ({ state, text } の配列)

issue list [--state 未,着手,済,archived | --all] [--group <g>] [--root <dir>] [--json]

  • 既定は未・着手 (todo/ と doing/ だけを読む)。--state は、未 ・ 着手 ・ 済 (done/) ・ archived をカンマで区切る。--all は 4 つすべて。--state と --all は同時に使えない。知らない語は終了コード 5
  • --group で、グループが一致するものだけに絞る
  • id の順に並べる (日付、次に 36 進数の連番。文字コード順ではない: L は 0 〜 9 と a 〜 k の後)。フォルダには関わらない
  • 出力: 1 行 1 件 <id> <状態> <グループ> <題> (archived/ は 済 (archived))、最後の行が N 件。--json は { id, state, folder, group, title, created, file } の配列
  • メタ情報が読めない課題は、飛ばして標準エラーに警告を出す (終了コードは 0)。理由は issue check で確かめる
  • 費用は、読むフォルダの件数で決まる。済 ・ archived/ は、既定では読まない

issue search <語> [--state 未,着手,済,archived | --all] [--group <g>] [--root <dir>] [--json]

  • 題と本文 (ファイルの全文) から、語を含む行を探す。英字は大小を区別しない。語は 1 つの文字列で、空白を含めて一致させる。語が無ければ終了コード 5
  • 読むフォルダ (既定は未・着手。--state ・ --all) と --group の絞り方は、list と同じ
  • 出力: list と同じ 1 行 ＋ 一致した行 ( L<行番号>: <行>。1 件の課題につき 3 行まで、1 行は 120 文字まで) ＋ 最後の行が N 件。--json は、課題の配列に matches ({ line, text } の配列。全件) を足したもの
  • メタ情報が読めない課題は、飛ばして標準エラーに警告を出す。見つからなければ 0 件 で終了コード 0

issue set <id> --state 未|着手|済 [--root <dir>] [--json]

  • 状態を変える = ファイルを、隣のフォルダへ動かすこと (todo/ ・ doing/ ・ done/)。git の管理下 (追跡中) なら git mv で動かし、ステージされた rename になる。そうでなければ名前を変えるだけ。中身は変えない。commit はしない (動かす commit は、本文の変更と別にする)
  • 済にするときは、条件を満たさなければ、動かさずに終了コード 1 (理由を出す): やること (未 ・ 着手) が残っている ・ from があるのに confirmed が true でない
  • 既にその状態なら、何もせず終了コード 0 (「既に」と出す)。archived/ の課題は動かさない (終了コード 1。issue unarchive を促す)。--state に archived や知らない語は終了コード 5。--state が無い ・ id の形が違うときも 5、見つからなければ 1
  • 出力: [OK] <id> を <旧> から <新> へ動かした (todo/ → doing/)。--json は { id, state, folder, from: { state, folder }, file }

issue todo <id> [--add <文> | --done <n> | --doing <n> | --undone <n>] [--root <dir>] [--json]

  • 引数が無ければ、やることを番号つきで出す (<n> [<状態>] <文>)。--json は { id, todos: [{ n, state, text }] }
  • --add は、やることの最後に - [未] <文> を足す (やることの節が無ければ、ファイルの最後に ## やること の節を作る)。--done ・ --doing ・ --undone は、n 番目の状態を 済 ・ 着手 ・ 未 にする。操作は 1 つだけ。番号が整数でない ・ 範囲外 ・ 文が空 ・ 改行を含むときは終了コード 5
  • done/ ・ archived/ の課題には、未のやることを足せず、やることを 未 ・ 着手 に戻せない (終了コード 1。先に issue set --state 着手)。済のままにする操作は通る
  • BOM や CR のあるファイルは、書き換えずに終了コード 1 (issue check で直す)。出力: [OK] <id> のやること <n> を <状態> にした: <文>

issue confirm <id> [--undo] [--root <dir>] [--json]

  • 報告元の確認 (confirmed) を true に直す。--undo は false に戻す。フォルダは動かさず、その行だけを書き換える (キーの順は変えない)。confirmed のキーが無ければ、from の次に足す
  • from (報告元) が無い課題は、終了コード 5 (confirmed は、他プロジェクトからの報告の課題だけに要る。ファイルは変えない)
  • 既に同じ値なら、何もせず終了コード 0 (「既に」と出す)。done/ ・ archived/ の課題は、false に戻せない (終了コード 1。先に issue set --state 着手)。true にする操作は通る (直接動かした誤りを直せる)
  • BOM や CR のあるファイルは、書き換えずに終了コード 1。見つからなければ 1、id の形が違う ・ id が無い ・ 知らないオプションは 5
  • 出力: [OK] <id> の報告元の確認 (confirmed) を true にした (報告元: <from>)。--json は { id, confirmed, from, changed, file }

issue render [<id>…] [--state … | --all] [--group <g>] [--out <ファイル>] [--standalone] [--root <dir>] [--json]

  • 課題の Markdown から、人が見る HTML を作る。生成だけで、開かない (計画の 134-A。開くのは issue view)。既定の出力先は notes/40_issues/_issues.html で、先頭 _ なので Git 管理外 (commit しない。131-A)
  • 範囲: 既定は未・着手・済 (archived/ は含めない)。--state ・ --all ・ --group は list と同じ。<id> を 1 つ以上指せば、その課題だけを、どのフォルダからでも作る。見つからない id は終了コード 1、id の形が違えば 5
  • ページの構成: タイトルバー (件数) ・ 戻る (README.html) と旧 HTML (issues-legacy.html があれば) へのリンク ・ 目次 ・ グループごとの章。章の順は groups.txt の並びで、無いものは最初の課題の id の順。章の色は章数で決まる (色相 280 → 0)
  • 課題の行 (130-A): details の summary に、番号 → 状態のバッジ → 題の順に出す。バッジは 未 = b-none ・ 着手 = b-warn ・ 済 = b-ok、archived/ は「済 ・ archived」。未・着手は開き、済は閉じる。本文の前に、作成日 ・ 報告元 (確認待ち / 確認済み) ・ 参照 (ページの中の課題は #id のリンク) ・ ファイルへのリンクを出す
  • 本文の変換: 見出し (## は h3、### は h4 …) ・ 段落 ・ 箇条書き (入れ子 ・ 番号つき。やること行は状態のバッジつき) ・ コードブロック (言語つき) ・ 表 (右寄せの列は、見出しも右寄せ) ・ 引用 ・ callout (> [!NOTE] 等) ・ 区切り線 ・ 太字 ・ インラインのコード ・ リンク ・ 画像 ・ <br>。Markdown の中の HTML は、解釈せずエスケープする (<br> だけ通す)。javascript: 等のリンクは、リンクにしない。ページに JS は含まない
  • 画像 (128-A ・ 129-A): ../images/… を、出力から見た相対パスに直す。プロジェクトの外 ・ 画像でない拡張子 ・ 無いファイルは、[画像が見つからない: 名前] に置き換え、標準エラーに警告を出す (終了コードは 0)。明るい版 (#gh-light-mode-only) だけを出し、暗い版 (#gh-dark-mode-only) は出さない。生成した HTML は、背景が常に淡い色なので、暗い版を出すと浮くため (計画 129-A の <picture> による切り替えではなく、この形にした)
  • --out <ファイル>: 指した場所に作る。リンクと画像のパスは、その場所からの相対パス。--standalone (渡す用。--out と一緒に使う。無ければ終了コード 5): 画像を data: URI で埋め込み、戻る ・ 旧 HTML ・ ファイル ・ ほかのファイルへのリンクを外す (ページの中のリンクは残る)
  • 書き方: BOM 付き UTF-8 ・ LF、<meta name="md-skip"> を入れる。末尾に、作った日時 (JST) と件数を出す。日時の部分を除いて中身が同じなら、書かず「変更なし」と出す (更新日時と差分が動かない)
  • 出力: [OK] <相対パス> を作った ・ を作り直した ・ は変更なし ((課題 N 件) つき)。--json は { file, issues, written, warnings } (written は created ・ updated ・ unchanged)。出力先が root の外なら、file はファイル名だけ。課題のファイルは書き換えない。メタ情報が読めない課題は、飛ばして警告を出す
  • 作った日時は、環境変数 ISSUE_TEST_NOW (yyyy/mm/dd hh:mm:ss) で固定できる (試験用。環境変数の仕様)

issue view [--state … | --all] [--group <g>] [--root <dir>] [--json]

  • _issues.html を render と同じ中身で作り直し (中身が同じなら書かない)、既定のアプリで開く (計画の 131-A ・ 134-A)。人が見るときに使う。AI は窓を開かないよう、render を使う
  • 受ける引数は --state ・ --all ・ --group ・ --root ・ --json だけ。--out ・ --standalone ・ <id> は受けない (終了コード 5)
  • 開けない環境 (画面の無い Linux 等) では、開かずにパスを出して終了コード 0。HTML は作る。出力: [OK] <相対パス> を作り直して開いた ・ 開けなければ … 開けなかったので、自分で開く: <相対パス>。--json は render の項目に opened を足したもの
  • 試験では、環境変数 ISSUE_TEST_OPEN_LOG (開くパスを追記するファイル) と ISSUE_TEST_OPEN_FAIL (1 なら開けなかった扱い) で、アプリを開かずに確かめる (環境変数の仕様)

issue migrate [--dry-run | --apply | --undo] [--state-override <番号=状態,…>] [--root <dir>] [--json]

  • 旧 issues.html の課題を読み、新しい形へ移す (計画 p261105-01 の ch02 ・ p261106-01 の 143-A: 済みも移す)。既定は --dry-run (何も書かない)。--apply で items/ へ書き、--undo で書いたものを消す
  • 読む旧 HTML: notes/40_issues/issues-legacy.html (無ければ issues.html) と issues-archive.html。どちらも無ければ終了コード 1
  • 読み方は、作りに頼らない (179-A。プロジェクトごとに旧 HTML の作りが違うため)。
    • 課題: summary に番号 (span.no か code.no。class に別の語が並んでいてもよい) を持つ details。本文は summary より後ろ全部 (div.issue-body で包んでいれば、その中身)。本文の中の details は課題として数えない
    • グループ: 番号を持たない details で、中に番号を持つ details があるものの summary (バッジと span.count を除く)。無ければ、その課題より前で最も近い見出し (h1 か div.groupbar の h2。summary の中のものは除く)
    • 題: summary から、バッジと番号を除いた 1 行 (summary の中の h1 でもよい)
    • 状態: バッジの字が 未 ・ 着手 ・ 済 なら字。そうでなければ class で決める (181-A。b-done ・ b-ok は済、b-wip ・ b-warn ・ b-doing は着手、b-todo ・ b-none は未)。本文のやること (バッジで始まる li) も同じ
    • 番号の連番の小文字の l は L に直して書く (182-A)。--dry-run に「番号を直して書く」として出す
  • 移し先: issues-legacy.html の済は done/、着手は doing/、未は todo/。issues-archive.html は archived/
  • 本文の相対リンク (href ・ src) は、置き場が 2 段深くなる分、../../ を足す。外のリンク ・ ページ内 (#) は変えない
  • 読めない形は、推測で補わず「読めなかった」に出す: 番号が無い (新しい番号を勝手に振らない) ・ 状態が決まらない ・ 同じ番号が重複している (2 件目を読まない) ・ issues-archive.html の状態が済でない ・ 本文もやることも空 (作りを読めていない見込み)。1 件でもあれば終了コード 1
  • 中身の比較 (183-A): 書く前に本文を Markdown にし、HTML に戻して、課題ごとに旧 HTML と比べる。本文の文字数 (タグを除き、空白を除いたもの) が 1 割 (少なくとも 10 字) を超えて違うか、やることの数が違えば「食い違い」に出し、終了コード 1。合計 (本文の文字数 ・ やることの数) も出す
  • --apply: 読めない ・ 旧の記録の食い違い (済なのに未 ・ 着手のやること。--state-override で決める) ・ 中身の食い違いが 1 件でもあれば、何も書かない。書いたら、書いたファイルの一覧を notes/40_issues/_migrate-written.txt (Git 管理外) に足し、書いたファイルを読み直して比べ、issue check を流す。食い違いか誤りが 1 件でもあれば、書いたものを全部消して元に戻し、終了コード 1
  • --undo: _migrate-written.txt にあるファイルだけを消し、一覧も消す。一覧に無いファイルには触らない。一覧が無ければ終了コード 1。旧 HTML の改名は戻さない (戻し方を表示する)
  • すでに items/ にある番号は、移さない件数に数える (作り直さない)
  • --json: --dry-run は { read, sources, move, exists, unreadable, conflicts, mismatches, size }。--apply は { read, written, exists, unreadable, size } (戻したときは { read, written: [], rolledBack, mismatches, checkErrors })。--undo は { listed, removed }

更新の操作の最後の、_issues.html の自動の作り直し

  • new ・ set ・ todo (変える操作) ・ confirm ・ archive ・ unarchive が成功したあと、_issues.html を既定の範囲 (未・着手・済) で作り直す (131-A)。init ・ check ・ show ・ list ・ search ・ todo の一覧と、失敗した操作は、作らない
  • 失敗しても、主な操作は成功のまま、標準エラーに [警告] を出すだけ (終了コード 0)。標準出力は増やさない (--json も JSON のまま)

issue archive <group> ・ issue unarchive <group> ([--root <dir>] [--json])

  • archive: グループの全件が済 (done/) なら、その課題を archived/ へ動かす (追跡中なら git mv)。1 件でも満たさなければ (未・着手が残っている ・ 済の条件を満たさない ・ メタ情報を読めない課題がある)、1 件も動かさず終了コード 1 (その id を出す)。課題が 1 件も無いグループは 1。既に全件が archived/ なら、終了コード 0 (「既に」と出す)
  • unarchive: archived/ のグループの課題を、done/ へ戻す。無ければ終了コード 1
  • issue new は、archived/ に退避済みのグループには立てない (終了コード 5。issue unarchive を促す。何も作らない。計画 p261103-01 の 112-A)
  • 出力: [OK] グループ <g> の N 件を archived/ へ動かした: <id> ・ …。--json は { group, moved, count }
  • この小節の操作は、すべて作業ツリーのファイルを変えるだけで、commit しない

issue decide new ・ list ・ show (決定の記録)

issue decide new --parent <番号> --title <問い> --option <文> [--option <文> …] --chosen <A|B|…>
                 [--slug <件名>] [--refs <番号,…>] [--replaces <id,…>] [--legacy <:名前:旧番号,…>] [--body <本文>] [--root <dir>] [--json]
issue decide list [--parent <番号>] [--root <dir>] [--json]
issue decide show <id> [--root <dir>] [--json]
  • new: decisions/ に決定を作る。--option を書いた順に A ・ B ・ C … と振り、本文の ## 案 に - X: 文 で書く。--chosen は振った字のどれか。連番は、親の決定の最大 + 1。同じ PC で同時に足しても重ならないよう、課題と同じ予約 (_lock/<id>/) を取る。decided は JST の今日。--body は案の後ろに足す。何かを書く前に、引数をすべて確かめる (誤りは終了コード 5 で、何も作らない)。出力は [OK] <相対パス> を作った (<id>)、--json は { id, file }
  • list: 親の番号 (種類 → 日付 → 連番) → 決定の連番の数の順。--parent で絞る。文字の出力は <id> <選んだ案> <決めた日> <問い> と N 件。--json は [{ id, parent, title, chosen, decided, file }]。読めないファイルは飛ばし、標準エラーに [警告]
  • show: 1 件を出す。無ければ終了コード 1、決定の id の形でなければ 5。--json は { id, file, meta, options: [{ key, text }], body }
  • _issues.html は作り直さない (決定は、まだ HTML に出さない)

まだ無いもの ・ 限界
