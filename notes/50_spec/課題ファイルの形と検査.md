# 課題ファイルの形と検査の仕様 (ai-agent-tools)

課題管理ツール `issue` が読み ・ 検査する、課題ファイルと `project-id.txt` の形。いまは「読み込み」と `issue check` まで。

> 📅 作成: 2026-11-03 / 更新: 2026-11-03

[^^](../../README.md)

課題を 1 件 1 ファイルで持つ形と、その検査 (`issue check`) の**いまの姿**。決めた経緯と、番号付きの決定は [課題管理ツール 計画](../10_plan/p261103-01-課題管理ツール.md) にある。実装と食い違ったら、実装が正しい。

> [!NOTE]
> **この仕様が扱う範囲**: 課題ファイルの形 ・ `project-id.txt` ・ `groups.txt` ・ `issue check`。`issue new` ・ `list` ・ `set` 等の操作と、HTML の生成は、まだ実装していない (第 3 章)。

## 1. 置き場と 1 件のファイルの形

### 置き場

| 置き場 | 中身 |
|---|---|
| `notes/40_issues/items/` | 進行中の課題。済の課題も、グループが片付くまでここに残す。状態ではフォルダを分けない |
| `notes/40_issues/items/archived/` | グループの全件が済になって、退避した課題。中はすべて済 |
| `notes/40_issues/items/project-id.txt` | プロジェクトを見分ける UUID。リポジトリに commit する |
| `notes/40_issues/items/groups.txt` | グループ (章) の名前を、表示順に 1 行ずつ並べる。**任意** |

### ファイル名

`<id>-<件名>.md` (例: `i261103-01-li内の表.md`)。

- **`<id>`**: `i` ＋ `yymmdd` ＋ `-` ＋ 2 桁の連番。連番は 36 進数で、英字は小文字。`l` は読み間違えるので大文字の `L` と書く (`0a` ・ `0k` ・ `0L` ・ `0m`)
- **`<件名>`**: 立てるときに決める短い名前で、**あとから変えない**。英数字 ・ ハイフン ・ 下線 ・ ピリオド ・ 日本語 (ひらがな ・ カタカナ ・ 漢字) だけ。空白は入れない。30 文字を超えると警告する
- 題を直しても、ファイル名は動かない。題は本文のメタ情報の `title` に自由に書く

### 1 件のファイル

先頭に `---` で囲んだメタ情報 (F2 の `キー: 値` の行)、そのあとが Markdown の本文。

```markdown
---
schema: 1
id: i261103-01
title: li の中の表を、表のまま出す
state: 未
group: html2md
created: 2026-11-03
from: ai-chat-lite #1737
confirmed: false
refs: p261103-01
---

(本文。Markdown)

## やること
- [未] convertList で項目の中の表を convertTable に渡す
- [着手] check-markdown で実測する
- [済] 原因の特定
```

### キー項目

| キー | 必須 | 値 | 備考 |
|---|---|---|---|
| `schema` | 必須 | 整数 `1` | 形の版 |
| `id` | 必須 | 上の `<id>` の形 | ファイル名の先頭と一致させる |
| `title` | 必須 | 1 行の文字列 | 最初の `: ` で分けるので、値の中にコロンがあってもよい |
| `state` | 必須 | `未` / `着手` / `済` | `済` は、やることが残っている間と、報告元の確認が無い間は付けられない |
| `group` | 必須 | 文字列 | 章 (グループ) の名前。`groups.txt` があれば、そこに並んでいる名前 |
| `created` | 必須 | `yyyy-mm-dd` (実在する日付) | 立てた日。変えない |
| `from` | 任意 | 文字列 (`プロジェクト名 #発言番号`) | 他プロジェクトからの報告のときだけ書く |
| `confirmed` | `from` があるとき必須 | `true` / `false` | 報告元の確認。`true` になるまで `済` にできない |
| `refs` | 任意 | カンマ区切りの番号 (`p261103-01, r261025-01`) | 計画 ・ 調査 ・ 課題の番号。ほかのプロジェクトの番号は `プロジェクト名:番号` |

更新日 (`updated`) は持たない。更新の経緯は `git log -- <課題のファイル>` で見る。

### F2 の書き方の決まり

- 先頭の行が `---`。次の `---` の行までがメタ情報。1 行 1 キー
- `キー: 値` の形。最初の `: ` で分け、前後の空白を除く。キーは小文字の英数字と `_`
- **引用符 ・ コメント (`#`) ・ 複数行 ・ 入れ子は無い**。`#` は値の一部 (`#1737` 等)
- 値の型は 4 つだけ: 文字列 ・ 整数 ・ 真偽 (`true` / `false`) ・ 一覧 (カンマ区切りの文字列)。どのキーがどの型かは、上の表が決める
- 値が空のキーは書かない。任意のキーは、無ければ省く。空行はメタ情報の中に置けない
- キーの順は上の表の順。順が違っても読めるが、警告する。知らないキーも読めるが、警告する
- UTF-8 (BOM 無し) ・ LF。BOM と CR は誤りとして止める

### やること

- 本文の中の、行頭が `- [未]` ・ `- [着手]` ・ `- [済]` の行。状態の語は 3 つだけで、これ以外は誤り
- 課題が `済` なのに、`未` か `着手` のやることが残っていれば誤り

### `project-id.txt`

課題ファイルと同じ `キー: 値` の行だけで、`---` の区切りは付けない。

```text
schema: 1
project_id: 7b0c4e1a9f3d4a62b8d51c2e6f90a3b7
```

- `project_id` は小文字 32 桁の 16 進数 (UUID のハイフン無し)
- `project_name` は持たない (フォルダ名から読む。リネームで古くならないため)

### `groups.txt`

グループ (章) の名前を、表示順に 1 行ずつ。空行は無視する。同じ名前を 2 度書くと誤り。課題の `group` がここに無ければ警告する。

## 2. `issue check` の検査

```shell
issue check                  # 作業フォルダから親をたどって、プロジェクトを探す
issue check --root <dir>      # プロジェクトのフォルダを指す
issue check --json           # 結果を JSON で出す
```

- **プロジェクトの探し方**: 作業フォルダから親へたどり、`notes/40_issues/items/` を持つ最初のフォルダ。`--root` があれば、そのフォルダを使う。見つからなければ終了コード 5
- **読み取り専用**。何も書き換えない。ほかのプロジェクトも読まない
- **出力に絶対パスを出さない**。ファイルはプロジェクトからの相対パス (`/` 区切り)

### 出力

```text
[NG] notes/40_issues/items/i261103-01-li内の表.md [value] state が 未 / 着手 / 済 のどれでもない: 完了
[警告] notes/40_issues/items/i261103-02-x.md [key-order] キーの順が決まりと違う: title
[NG] 課題 2 件 (進行中 2 件 ・ archived 0 件)。エラー 1 件 ・ 警告 1 件
```

最後の 1 行は、エラーがあれば `[NG] 課題 N 件 (進行中 M 件 ・ archived K 件)。エラー E 件 ・ 警告 W 件`。エラーが無く警告があれば `[OK] …。エラー 0 件 ・ 警告 W 件`。どちらも無ければ `[OK] …。問題なし`。`--json` では `ok` ・ `errors` ・ `warnings` ・ `issues` ・ `archived` ・ `findings` (`level` ・ `code` ・ `file` ・ `message`) を持つ。

### 終了コード

| コード | 意味 |
|---|---|
| 0 | エラーが無い (警告があってもよい) |
| 1 | エラーが 1 件以上ある |
| 5 | 引数の誤り ・ プロジェクトが見つからない |

2 は使わない (Stop フックが 2 を「続ける」と読むため)。

### 検査の一覧

| 種別 (`code`) | 重さ | 見ること |
|---|---|---|
| `project-id` | エラー | `project-id.txt` が無い ・ 読めない ・ `schema` が 1 でない ・ `project_id` が小文字 32 桁の 16 進数でない |
| `name` | エラー | ファイル名が `<id>-<件名>.md` の形でない (`i` で始まらない `.md` を含む) ・ 件名に使えない文字がある |
| `encoding` | エラー | BOM がある ・ CR (CRLF) がある |
| `meta` | エラー | 先頭が `---` でない ・ 閉じの `---` が無い ・ `キー: 値` の形でない行 ・ 値が空 ・ キーの重複 ・ メタ情報の中の空行 |
| `key` | エラー | 必須のキーが無い |
| `value` | エラー | 値の形が違う (`schema` ・ `id` ・ `state` ・ `created` ・ `confirmed` ・ `refs`)。`id` がファイル名の先頭と違う |
| `duplicate` | エラー | 同じ `id` のファイルが複数ある (`items/` と `archived/` をまたぐ場合も)。別の PC やクラウドで、件名違いで同じ番号が立つと、git は競合を出さないので、ここで止める |
| `todo` | エラー | やることの状態が 3 つ以外 ・ `済` なのに `未` か `着手` のやることが残っている |
| `confirmed` | エラー / 警告 | `from` があるのに `confirmed` が無い (エラー) ・ `済` なのに `confirmed` が `true` でない (エラー) ・ `from` が無いのに `confirmed` がある (警告) |
| `archived` | エラー | `archived/` の中に、`済` でない課題がある |
| `key-order` | 警告 | キーの順が、表の順と違う |
| `unknown-key` | 警告 | 知らないキーがある |
| `refs` | 警告 | `refs` の参照先が見つからない (課題は `items/` ・ `archived/`、計画 ・ 調査 ・ アイデアは `notes/` のファイル名の先頭)。`プロジェクト名:番号` の形は、外を読まないので確かめない |
| `slug-long` | 警告 | 件名が 30 文字を超える |
| `group` | エラー / 警告 | `groups.txt` で同じ名前が重複している (エラー) ・ 課題の `group` が `groups.txt` に無い (警告) |

## 3. まだ無いもの ・ 限界

- **操作**: `issue new` ・ `list` ・ `show` ・ `set` ・ `todo` ・ `search` ・ `init` ・ `archive` ・ `unarchive`。フェーズ 2 以降
- **HTML の生成** (`issue render`)、**索引 DB**、**横断**: フェーズ 3 以降
- **番号の予約 (`_lock/`)**: `issue new` と一緒に入れる。いまは、重複を `issue check` が後から止めるだけ
- **本文の Markdown の検査はしない**。やること行だけを見る。コードブロックの中の `- [x]` のような行も、やること行として読むので、誤りになる
- **`refs` の参照先は、ファイル名の先頭だけで探す**。移行前の課題 (`issues.html` の中の番号) は見つけられず、警告になる
- 他のプロジェクトのファイルは読まない。検査するのは、見つけた 1 つのプロジェクトだけ
