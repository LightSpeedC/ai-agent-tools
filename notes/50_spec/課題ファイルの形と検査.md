# 課題ファイルの形と検査の仕様 (ai-agent-tools)

課題管理ツール `issue` が読み ・ 検査する、課題ファイルと `project-id.txt` の形。いまは、読み込み ・ `issue check` ・ `init` ・ `new` ・ `show` ・ `list` ・ `search` ・ `set` ・ `todo` ・ `confirm` ・ `archive` ・ `unarchive` まで。

> 📅 作成: 2026-11-03 / 更新: 2026-11-05

[^^](../../README.md)

課題を 1 件 1 ファイルで持つ形と、その検査 (`issue check`) の**いまの姿**。決めた経緯と、番号付きの決定は [課題管理ツール 計画](../10_plan/p261103-01-課題管理ツール.md) にある。実装と食い違ったら、実装が正しい。

> [!NOTE]
> **この仕様が扱う範囲**: 課題ファイルの形 ・ `project-id.txt` ・ `groups.txt` ・ `issue check` ・ `init` ・ `new` ・ `show` ・ `list` ・ `search` ・ `set` ・ `todo` ・ `confirm` ・ `archive` ・ `unarchive`。HTML の表示 (`issue view`) と横断は、まだ実装していない (第 4 章)。

## 1. 置き場と 1 件のファイルの形

### 置き場

| 置き場 | 中身 |
|---|---|
| `notes/40_issues/items/todo/` | 状態が未の課題 |
| `notes/40_issues/items/doing/` | 状態が着手の課題 |
| `notes/40_issues/items/done/` | 状態が済の課題。グループが片付くまで、ここに残す |
| `notes/40_issues/items/archived/` | グループの全件が済になって、退避した課題 (済のまま)。`done/` と同じ条件を満たす |
| `notes/40_issues/items/project-id.txt` | プロジェクトを見分ける UUID。リポジトリに commit する |
| `notes/40_issues/items/groups.txt` | グループ (章) の名前を、表示順に 1 行ずつ並べる。**任意** |

### ファイル名

`<id>-<件名>.md` (例: `i261103-01-li内の表.md`)。

- **`<id>`**: `i` ＋ `yymmdd` ＋ `-` ＋ 2 桁の連番。連番は 36 進数で、英字は小文字。`l` は読み間違えるので大文字の `L` と書く (`0a` ・ `0k` ・ `0L` ・ `0m`)
- **`<件名>`**: 立てるときに決める短い名前で、**あとから変えない**。英数字 ・ ハイフン ・ 下線 ・ ピリオド ・ 日本語 (ひらがな ・ カタカナ ・ 漢字) だけ。空白は入れない。30 文字を超えると警告する
- 題を直しても、ファイル名は動かない。題は本文のメタ情報の `title` に自由に書く

### 1 件のファイル

先頭に `---` で囲んだメタ情報 (F2 の `キー: 値` の行)、そのあとが Markdown の本文。

```markdown
---
schema: 1
id: i261103-01
title: li の中の表を、表のまま出す
group: html2md
created: 2026-11-03
from: ai-chat-lite #1737
confirmed: false
refs: p261103-01
---

(本文。Markdown)

## やること
- [未] convertList で項目の中の表を convertTable に渡す
- [着手] check-markdown で実測する
- [済] 原因の特定
```

### キー項目

| キー | 必須 | 値 | 備考 |
|---|---|---|---|
| `schema` | 必須 | 整数 `1` | 形の版 |
| `id` | 必須 | 上の `<id>` の形 | ファイル名の先頭と一致させる |
| `title` | 必須 | 1 行の文字列 | 最初の `: ` で分けるので、値の中にコロンがあってもよい |
| `group` | 必須 | 文字列 | 章 (グループ) の名前。`groups.txt` があれば、そこに並んでいる名前 |
| `created` | 必須 | `yyyy-mm-dd` (実在する日付) | 立てた日。変えない |
| `from` | 任意 | 文字列 (`プロジェクト名 #発言番号`) | 他プロジェクトからの報告のときだけ書く |
| `confirmed` | `from` があるとき必須 | `true` / `false` | 報告元の確認。`true` になるまで、`done/` ・ `archived/` に置けない (済にできない) |
| `refs` | 任意 | カンマ区切りの番号 (`p261103-01, r261025-01`) | 計画 ・ 調査 ・ 課題の番号。ほかのプロジェクトの番号は `プロジェクト名:番号` |

更新日 (`updated`) は持たない。更新の経緯は `git log -- <課題のファイル>` で見る。`state` も持たない (次の「状態」)。

### 状態 (フォルダで持つ)

**課題の状態は、`state` キーではなく、置いてあるフォルダで決まる** (計画 p261103-01 の 126-A)。状態の正本がフォルダ 1 つなので、二重管理にならない。

| フォルダ | 状態 | 置ける課題 |
|---|---|---|
| `todo/` | 未 | すべて |
| `doing/` | 着手 | すべて |
| `done/` | 済 | やることが残っていない (`未` ・ `着手` が 0 件) 課題。`from` があれば `confirmed` が `true` |
| `archived/` | 済 (退避) | `done/` と同じ条件。グループの全件が済になって退避したもの |

- **状態を変える**のは、ファイルを隣のフォルダへ動かすこと (`git mv`)。動かしても、ファイル名 (`<id>-<件名>.md`) と中身は変わらない。動かすのは本文の変更と別の commit にする (git の rename 検出が、小さなファイルで外れないように)
- **`state` キーが残っていれば誤り** (`state-key`)。`items/` 直下や、上の 4 つ以外のフォルダにある `.md` も誤り (`place`)
- 「未・着手」だけを読めば足りる問い (一覧 ・ 検索) は、`todo/` と `doing/` だけを読む。済は増え続けるが、費用は未・着手の件数で決まる

### F2 の書き方の決まり

- 先頭の行が `---`。次の `---` の行までがメタ情報。1 行 1 キー
- `キー: 値` の形。最初の `: ` で分け、前後の空白を除く。キーは小文字の英数字と `_`
- **引用符 ・ コメント (`#`) ・ 複数行 ・ 入れ子は無い**。`#` は値の一部 (`#1737` 等)
- 値の型は 4 つだけ: 文字列 ・ 整数 ・ 真偽 (`true` / `false`) ・ 一覧 (カンマ区切りの文字列)。どのキーがどの型かは、上の表が決める
- 値が空のキーは書かない。任意のキーは、無ければ省く。空行はメタ情報の中に置けない
- キーの順は上の表の順。順が違っても読めるが、警告する。知らないキーも読めるが、警告する
- UTF-8 (BOM 無し) ・ LF。BOM と CR は誤りとして止める

### やること

- 本文の中の、行頭が `- [未]` ・ `- [着手]` ・ `- [済]` の行。状態の語は 3 つだけで、これ以外は誤り
- 課題が `done/` か `archived/` にあるのに、`未` か `着手` のやることが残っていれば誤り

### `project-id.txt`

課題ファイルと同じ `キー: 値` の行だけで、`---` の区切りは付けない。

```text
schema: 1
project_id: 7b0c4e1a9f3d4a62b8d51c2e6f90a3b7
```

- `project_id` は小文字 32 桁の 16 進数 (UUID のハイフン無し)
- `project_name` は持たない (フォルダ名から読む。リネームで古くならないため)

### `groups.txt`

グループ (章) の名前を、表示順に 1 行ずつ。空行は無視する。同じ名前を 2 度書くと誤り。課題の `group` がここに無ければ警告する。

## 2. `issue check` の検査

```shell
issue check                  # 作業フォルダから親をたどって、プロジェクトを探す
issue check --root <dir>      # プロジェクトのフォルダを指す
issue check --json           # 結果を JSON で出す
```

- **プロジェクトの探し方**: 作業フォルダから親へたどり、`notes/40_issues/items/` を持つ最初のフォルダ。`--root` があれば、そのフォルダを使う。見つからなければ終了コード 5
- **読み取り専用**。何も書き換えない。ほかのプロジェクトも読まない
- **出力に絶対パスを出さない**。ファイルはプロジェクトからの相対パス (`/` 区切り)

### 出力

```text
[NG] notes/40_issues/items/todo/i261103-01-li内の表.md [state-key] state キーは持たない (状態はフォルダで持つ)
[警告] notes/40_issues/items/todo/i261103-02-x.md [key-order] キーの順が決まりと違う (決まり: schema ・ id ・ title ・ …)
[NG] 課題 2 件 (未 2 件 ・ 着手 0 件 ・ 済 0 件 ・ archived 0 件)。エラー 1 件 ・ 警告 1 件
```

最後の 1 行は、エラーがあれば `[NG] 課題 N 件 (未 a 件 ・ 着手 b 件 ・ 済 c 件 ・ archived d 件)。エラー E 件 ・ 警告 W 件`。エラーが無く警告があれば `[OK] …。エラー 0 件 ・ 警告 W 件`。どちらも無ければ `[OK] …。問題なし`。`--json` では `ok` ・ `errors` ・ `warnings` ・ `issues` (全件) ・ `todo` ・ `doing` ・ `done` ・ `archived` (フォルダごとの件数) ・ `findings` (`level` ・ `code` ・ `file` ・ `message`) を持つ。

### 終了コード

| コード | 意味 |
|---|---|
| 0 | エラーが無い (警告があってもよい) |
| 1 | エラーが 1 件以上ある |
| 5 | 引数の誤り ・ プロジェクトが見つからない |

2 は使わない (Stop フックが 2 を「続ける」と読むため)。

### 検査の一覧

| 種別 (`code`) | 重さ | 見ること |
|---|---|---|
| `project-id` | エラー | `project-id.txt` が無い ・ 読めない ・ `schema` が 1 でない ・ `project_id` が小文字 32 桁の 16 進数でない |
| `name` | エラー | ファイル名が `<id>-<件名>.md` の形でない (`i` で始まらない `.md` を含む) ・ 件名に使えない文字がある |
| `place` | エラー | `items/` 直下や、`todo/` ・ `doing/` ・ `done/` ・ `archived/` 以外のフォルダに、`.md` がある |
| `state-key` | エラー | `state` キーが残っている (状態はフォルダで持つ) |
| `encoding` | エラー | BOM がある ・ CR (CRLF) がある |
| `meta` | エラー | 先頭が `---` でない ・ 閉じの `---` が無い ・ `キー: 値` の形でない行 ・ 値が空 ・ キーの重複 ・ メタ情報の中の空行 |
| `key` | エラー | 必須のキーが無い |
| `value` | エラー | 値の形が違う (`schema` ・ `id` ・ `created` ・ `confirmed` ・ `refs`)。`id` がファイル名の先頭と違う |
| `duplicate` | エラー | 同じ `id` のファイルが複数ある (4 つのフォルダをまたぐ場合も)。別の PC やクラウドで、件名違いで同じ番号が立つと、git は競合を出さないので、ここで止める |
| `todo` | エラー | やることの状態が 3 つ以外 ・ `done/` か `archived/` にあるのに、`未` か `着手` のやることが残っている |
| `confirmed` | エラー / 警告 | `from` があるのに `confirmed` が無い (エラー) ・ `done/` か `archived/` にあるのに `confirmed` が `true` でない (エラー) ・ `from` が無いのに `confirmed` がある (警告) |
| `key-order` | 警告 | キーの順が、表の順と違う |
| `unknown-key` | 警告 | 知らないキーがある |
| `refs` | 警告 | `refs` の参照先が見つからない (課題は 4 つのフォルダのどれか、計画 ・ 調査 ・ アイデアは `notes/` のファイル名の先頭)。`プロジェクト名:番号` の形は、外を読まないので確かめない |
| `slug-long` | 警告 | 件名が 30 文字を超える |
| `group` | エラー / 警告 | `groups.txt` で同じ名前が重複している (エラー) ・ 課題の `group` が `groups.txt` に無い (警告) |

## 3. 操作

共通の決まり: 出力に絶対パスを出さない (相対パス ・ `/` 区切り)。終了コードは、成功 0 ・ 失敗 1 (見つからない ・ 重複 ・ 番号を使い切った) ・ 引数の誤り 5 (2 は使わない)。プロジェクトは、`--root` か、作業フォルダから親をたどって探す。

### `issue init [--root <dir>] [--new-id]`

- `project-id.txt` を作る (`schema: 1` ＋ 乱数の `project_id`)。`items/` が無ければ作るが、**状態のフォルダは作らない** (空フォルダを作らない)
- 既にあれば変えず、「既にある」と出す。`--new-id` は `project_id` を振り直す (フォルダごとコピーして別のプロジェクトにしたとき)
- プロジェクトは、`--root`、無ければ作業フォルダから親をたどって見つけたもの、それも無ければ作業フォルダ

### `issue new --title <題> --group <グループ> [--slug <件名>] [--from <報告元>] [--refs <番号,…>] [--body <本文>] [--root <dir>] [--json]`

- `todo/` に `<id>-<件名>.md` を作る。**引数はすべて、何かを作る前に確かめる**。誤りなら、何も作らず終了コード 5
- **id** は、`i` ＋ 今日の日付 (JST の `yymmdd`) ＋ 連番。連番は、**その日の既存の最大 (4 つのフォルダすべて) の次**で、36 進数 2 桁 (`09` の次は `0a`、`0k` の次は `0L`)。その日の最初は `01`
- **件名**は、`--slug` があればそれ、無ければ題から作る (使えない文字 ・ 空白は `-` に直し、30 文字までに切る)。`--slug` が使えない文字を含む ・ 30 文字を超える ・ 題からも作れない (記号だけ等) ときは終了コード 5
- **`groups.txt` があれば**、`--group` がそこに並んでいる名前であること (誤字を防ぐため)。無ければ何でもよい
- `--from` があれば、`from` と `confirmed: false` を書く。`--refs` は番号をカンマで区切り、カンマのあとに空白 1 つで書く。形が違えば終了コード 5
- メタ情報は、決まりの順で書く。本文は、閉じの `---` の次の空行のあと。`--body` が無ければ空行だけ。UTF-8 (BOM 無し) ・ LF
- `project-id.txt` が無ければ、`issue init` と同じに作る。`--root` で指したプロジェクトに `items/` が無くても作れる。`--root` が無く、プロジェクトが見つからなければ終了コード 5 (`issue init` を促す)
- **番号の予約**: 作る前に `notes/40_issues/_lock/<id>/` を `mkdir` で作る (`mkdir` は既にあれば失敗するので、排他になる)。先頭 `_` のフォルダなので Git 管理外。取れなければ次の番号を試し、作り終えたら消す。**60 秒より古い予約は、持ち主が居ないとみなして消し、取り直す**。予約を取ったあとにも、同じ id のファイルが無いかをもう一度見る
- 予約が効くのは**同じ PC の中だけ**。別の PC やクラウドで、件名違いに同じ番号が立つと、`issue check` の `duplicate` が後から止める
- 出力: `[OK] <相対パス> を作った (<id>)`。`--json` は `{ id, file }`
- 今日の日付は、環境変数 `ISSUE_TEST_TODAY` (`yyyy-mm-dd`) で固定できる (試験用。[環境変数の仕様](環境変数.md))

### `issue show <id> [--root <dir>] [--json]`

- `<id>-` で始まるファイルを、**4 つのフォルダから探して**読む。id は完全一致 (例: `i261103-01`)。形が違えば終了コード 5、見つからなければ 1、同じ id のファイルが複数あれば 1 (「複数ある」と出す)
- 出力: 1 行目に `<id>  <状態> (<フォルダ>/)  <相対パス>`、続けてファイルの全文。`archived/` の課題は、状態が 済 で、フォルダが `archived/`
- `--json`: `id` ・ `state` (未 ・ 着手 ・ 済) ・ `folder` ・ `file` ・ `meta` (キーと値) ・ `body` ・ `todos` (`{ state, text }` の配列)

### `issue list [--state 未,着手,済,archived | --all] [--group <g>] [--root <dir>] [--json]`

- **既定は未・着手** (`todo/` と `doing/` だけを読む)。`--state` は、未 ・ 着手 ・ 済 (`done/`) ・ `archived` をカンマで区切る。`--all` は 4 つすべて。`--state` と `--all` は同時に使えない。知らない語は終了コード 5
- `--group` で、グループが一致するものだけに絞る
- **id の順**に並べる (日付、次に 36 進数の連番。文字コード順ではない: `L` は `0` 〜 `9` と `a` 〜 `k` の後)。フォルダには関わらない
- 出力: 1 行 1 件 `<id>  <状態>  <グループ>  <題>` (`archived/` は `済 (archived)`)、最後の行が `N 件`。`--json` は `{ id, state, folder, group, title, created, file }` の配列
- メタ情報が読めない課題は、飛ばして標準エラーに警告を出す (終了コードは 0)。理由は `issue check` で確かめる
- 費用は、読むフォルダの件数で決まる。済 ・ `archived/` は、既定では読まない

### `issue search <語> [--state 未,着手,済,archived | --all] [--group <g>] [--root <dir>] [--json]`

- 題と本文 (ファイルの全文) から、語を含む行を探す。**英字は大小を区別しない**。語は 1 つの文字列で、空白を含めて一致させる。語が無ければ終了コード 5
- 読むフォルダ (既定は未・着手。`--state` ・ `--all`) と `--group` の絞り方は、`list` と同じ
- 出力: `list` と同じ 1 行 ＋ 一致した行 (`    L<行番号>: <行>`。**1 件の課題につき 3 行まで、1 行は 120 文字まで**) ＋ 最後の行が `N 件`。`--json` は、課題の配列に `matches` (`{ line, text }` の配列。全件) を足したもの
- メタ情報が読めない課題は、飛ばして標準エラーに警告を出す。見つからなければ `0 件` で終了コード 0

### `issue set <id> --state 未|着手|済 [--root <dir>] [--json]`

- **状態を変える = ファイルを、隣のフォルダへ動かすこと** (`todo/` ・ `doing/` ・ `done/`)。**git の管理下 (追跡中) なら `git mv`** で動かし、ステージされた rename になる。そうでなければ名前を変えるだけ。中身は変えない。commit はしない (動かす commit は、本文の変更と別にする)
- **済にするときは、条件を満たさなければ、動かさずに終了コード 1** (理由を出す): やること (未 ・ 着手) が残っている ・ `from` があるのに `confirmed` が `true` でない
- 既にその状態なら、何もせず終了コード 0 (「既に」と出す)。`archived/` の課題は動かさない (終了コード 1。`issue unarchive` を促す)。`--state` に `archived` や知らない語は終了コード 5。`--state` が無い ・ id の形が違うときも 5、見つからなければ 1
- 出力: `[OK] <id> を <旧> から <新> へ動かした (todo/ → doing/)`。`--json` は `{ id, state, folder, from: { state, folder }, file }`

### `issue todo <id> [--add <文> | --done <n> | --doing <n> | --undone <n>] [--root <dir>] [--json]`

- 引数が無ければ、やることを番号つきで出す (`<n> [<状態>] <文>`)。`--json` は `{ id, todos: [{ n, state, text }] }`
- `--add` は、やることの最後に `- [未] <文>` を足す (やることの節が無ければ、ファイルの最後に `## やること` の節を作る)。`--done` ・ `--doing` ・ `--undone` は、n 番目の状態を 済 ・ 着手 ・ 未 にする。操作は 1 つだけ。番号が整数でない ・ 範囲外 ・ 文が空 ・ 改行を含むときは終了コード 5
- **`done/` ・ `archived/` の課題には、未のやることを足せず、やることを 未 ・ 着手 に戻せない** (終了コード 1。先に `issue set --state 着手`)。済のままにする操作は通る
- BOM や CR のあるファイルは、書き換えずに終了コード 1 (`issue check` で直す)。出力: `[OK] <id> のやること <n> を <状態> にした: <文>`

### `issue confirm <id> [--undo] [--root <dir>] [--json]`

- 報告元の確認 (`confirmed`) を `true` に直す。`--undo` は `false` に戻す。**フォルダは動かさず、その行だけを書き換える** (キーの順は変えない)。`confirmed` のキーが無ければ、`from` の次に足す
- `from` (報告元) が無い課題は、終了コード 5 (`confirmed` は、他プロジェクトからの報告の課題だけに要る。ファイルは変えない)
- 既に同じ値なら、何もせず終了コード 0 (「既に」と出す)。`done/` ・ `archived/` の課題は、`false` に戻せない (終了コード 1。先に `issue set --state 着手`)。`true` にする操作は通る (直接動かした誤りを直せる)
- BOM や CR のあるファイルは、書き換えずに終了コード 1。見つからなければ 1、id の形が違う ・ id が無い ・ 知らないオプションは 5
- 出力: `[OK] <id> の報告元の確認 (confirmed) を true にした (報告元: <from>)`。`--json` は `{ id, confirmed, from, changed, file }`

### `issue archive <group>` ・ `issue unarchive <group>` (`[--root <dir>] [--json]`)

- **`archive`**: グループの全件が済 (`done/`) なら、その課題を `archived/` へ動かす (追跡中なら `git mv`)。**1 件でも満たさなければ (未・着手が残っている ・ 済の条件を満たさない ・ メタ情報を読めない課題がある)、1 件も動かさず終了コード 1** (その id を出す)。課題が 1 件も無いグループは 1。既に全件が `archived/` なら、終了コード 0 (「既に」と出す)
- **`unarchive`**: `archived/` のグループの課題を、`done/` へ戻す。無ければ終了コード 1
- **`issue new` は、`archived/` に退避済みのグループには立てない** (終了コード 5。`issue unarchive` を促す。何も作らない。計画 p261103-01 の 112-A)
- 出力: `[OK] グループ <g> の N 件を archived/ へ動かした: <id> ・ …`。`--json` は `{ group, moved, count }`

- この小節の操作は、すべて**作業ツリーのファイルを変えるだけで、commit しない**

## 4. まだ無いもの ・ 限界

- **`issue confirm` は、自己申告**。報告元から OK が出たことを、道具は確かめない。報告元へ返信し、OK をもらってから呼ぶのは、人か AI の役目 (共通ルール「課題の管理」)
- **HTML の表示** (`issue render` = 生成だけ ・ `issue view` = 生成して開く ・ `--standalone` = 渡す用の自己完結した HTML。`notes/40_issues/_issues.html` に生成し、commit しない)、**横断**: フェーズ 3 以降。**索引 DB** は持たない (計画 p261103-01 の 121-C)
- **番号の予約 (`_lock/`) は、同じ PC の中だけ**。別の PC ・ クラウドでの重複は、`issue check` が後から止める
- **本文の Markdown の検査はしない**。やること行だけを見る。コードブロックの中の `- [x]` のような行も、やること行として読むので、誤りになる
- **`refs` の参照先は、ファイル名の先頭だけで探す**。移行前の課題 (`issues.html` の中の番号) は見つけられず、警告になる
- 他のプロジェクトのファイルは読まない。検査するのは、見つけた 1 つのプロジェクトだけ
