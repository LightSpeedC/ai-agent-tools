# 環境変数の仕様 (ai-agent-tools)

このプロジェクトの道具が、読む ・ 設定する ・ 消す環境変数の一覧。試験用は後半の章に分けてある。

> 📅 作成: 2026-11-01 / 更新: 2026-11-01

[^^](../../README.md)

道具が環境変数をどう扱うかの、いまの姿。**範囲はこのプロジェクトの全道具** (`src/` ・ `bin/` ・ `tools/` ・ `tests/`)。値は書かない (名前と役目だけ)。

> [!NOTE]
> <strong>変数を足す・消す・改名するときは、この表を同じ回のうちに直す。</strong>探すときの語は `process.env` ・ `$env:` ・ `env::var` ・ `set ` (cmd) ・ `GetEnvironmentVariable`。

## 1. ふだんの運用で読む変数

利用者が道具を使うときに、道具が読む変数。**OS の変数と、cloud の準備で読む変数**だけ。このプロジェクトの道具が独自に決めた名前のものは、ふだんは使わないので第 3 章に置く。

| 変数 | 読む道具 | 役目 | 未設定のとき |
|---|---|---|---|
| `PATH` | `xx` (`src/xx`) | コマンド名を探すフォルダの並び | 空の並びとして扱う (見つからない) |
| `USERPROFILE` | `bin/codex-trusted.ps1` | 設定フォルダ (`.codex`) の親 | 確かめていない |
| `GIT_AUTHOR_NAME` ・ `GIT_AUTHOR_EMAIL` | `bin/cloud-session-start` | **両方が設定されていれば**、プロジェクトの git の author を書き換えない (git が環境変数を使うため) | 片方でも空なら、共通ルールの最新の commit と同じ author を、プロジェクトの `.git/config` に書く |

- `cc-register` と `history2html` は、ホームのフォルダを Node の `os.homedir()` で取る。`USERPROFILE` 等の OS の変数は、直接は読まない (`history2html` は、先に第 3 章の `HISTORY2HTML_HOME` を見る)
- cloud の準備では、呼び手が `CLAUDE_PROJECT_DIR` と `CLAUDE_ENV_FILE` の値を、環境変数ではなく**引数** (`--project` ・ `--env-file`) で渡す。道具は環境変数としては読まない

## 2. 道具が設定する・消す・引き継ぐ変数

道具が環境を変える場合。**変わるのが「起こした相手だけ」か、「呼んだ窓にも残る」か**が、取り違えやすい点。

| 道具 | どうする | 変数 | 効く範囲 |
|---|---|---|---|
| `bin/cc.cmd` ・ `cx.cmd` ・ `ag.cmd` | 消す | `cc` は `CLAUDE` で始まる変数すべて (`CLAUDE_CODE_USE_POWERSHELL_TOOL` を除く)。3 本とも、`KEEPER_*` を、起こすエージェントに渡さない | 共通部 (`src/agent-launch`) が、番人の窓を起こす環境から外す。呼んだ窓は変わらない。Claude Code の中から `cc` を呼んでも、親のセッションの値を子に渡さないため |
| 共通部 → 番人 (`src/agent-launch`) | 渡す | `KEEPER_EXE` ・ `KEEPER_FIRST` ・ `KEEPER_AGAIN` (起こすコマンドと、最初と再起動の引数)。試験の非表示のときだけ `KEEPER_NOASK` | 番人の窓だけ。番人 (`keeper.cmd`) が、起こす行の中で消し、エージェントには渡さない。作業用の `KP_*` も同じ |
| `bin/cc.cmd` ・ `cx.cmd` ・ `ag.cmd` | 設定しない | なし | 呼んだ窓の環境変数もカレントも変えない (入口の cmd は、変数を何も設定せず、カレントも動かさない)。試験は、呼んだあとの窓に、作業用の変数が足されないことを確かめる |
| `bin/use-lms.cmd` | 設定する | `ANTHROPIC_BASE_URL` ・ `ANTHROPIC_AUTH_TOKEN` ・ `ANTHROPIC_API_KEY` (空にする) ・ `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` | 呼んだ窓に残る (読んだ限り。`setlocal` が無い。実測していない) |
| コマンド起動サーバ (`src/spawn-server-ts`) | 引き継ぐ | サーバーの環境変数すべて | 起動した新しい窓へ。作業用の値は持ち込まない (第 3 章の `SPAWN_LINE` ・ `SPAWN_CWD`) |
| `bin/cloud-session-start` | 設定する | `GIT_LFS_SKIP_SMUDGE=1` | `git clone` の 1 回だけ (そのコマンドの行の中) |
| `bin/cloud-session-start` | 書き出す | `PATH` を通す行 | `--env-file` で渡されたファイルへ。ファイルが無ければ通さず、そう報告する |

> [!NOTE]
> **読んだ限りの組み合わせ (実測していない)。**`use-lms.cmd` で `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` を設定した窓から `cc` を使うと、`cc` が `CLAUDE` で始まる変数を消すので、**その 1 つは起こした `claude` に渡らない**。`ANTHROPIC_*` は消されず、渡る。

## 3. 試験 ・ 計測のための変数

試験や計測が、道具の動きを差し替えるための変数。**「本番の道具が読む」と書いたものは、ふだんの運用で設定しても効く** (試験のための入口だが、道具の中に入っている)。「試験の側だけ」と書いたものは、試験のスクリプトだけが読む。

| 変数 | 読む場所 | 役目 | 未設定のとき | 読む側 |
|---|---|---|---|---|
| `CC_ROOT` | `src/agent-launch/main.ts` (`cc` ・ `cx` ・ `ag` 共通) | プロジェクトを作る置き場。試験は `tmp/` の下へ差し替える | `W:\` | 本番の道具が読む |
| `CC_CLAUDE_JSON` | `src/cc-register` | フォルダを登録する先の `.claude.json` | ホームの `.claude.json` | 本番の道具が読む |
| `CC_STUB_OUT` | `tools/40_test/run-cc-tests.ts` が作る代役の `claude` | 受けた引数と `CLAUDE` で始まる変数の書き出し先 | 何も書かない | 試験の側だけ |
| `HISTORY2HTML_HOME` | `src/history2html` | 伏せる対象のホームのフォルダ | `os.homedir()` | 本番の道具が読む |
| `HISTORY2HTML_USERNAME` | `src/history2html` | 伏せる対象のユーザー名 | ホームの末尾のフォルダ名 | 本番の道具が読む |
| `HISTORY2HTML_HOSTNAME` | `src/history2html` | 伏せる対象のホスト名 | `os.hostname()` | 本番の道具が読む |
| `HISTORY2HTML_TEST_NO_MASK` | `src/history2html` | 1 段目の置き換えを、カンマ区切りの名前で外す。2 段目の検査が止めることを確かめる | 外さない | 本番の道具が読む (試験の入口) |
| `HISTORY2HTML_VIEWER_DIR` | `tests/history2html-viewer/viewer.spec.ts` | 書き出したビューアのフォルダ | 空 (試験が「渡っていない」で失敗する) | 試験の側だけ |
| `TRANSCRIBE_VENDOR` | `src/transcribe` | whisper の置き場。試験が本物の `_vendor` を触らないため | `_vendor/whisper` | 本番の道具が読む |
| `CONVERT_AUDIO_VENDOR` | `src/convert-audio` | ffmpeg の置き場。同上 | `_vendor/ffmpeg` | 本番の道具が読む |
| `SAFE_PUSH_TEST_HOSTNAME` | `src/safe-push` | ロックに書くホスト名。別のホストのロックを試す | `os.hostname()` | 本番の道具が読む |
| `SPAWN_SERVER_NO_FFI` | `src/spawn-server-ts` | `1` で、最初から `Start-Process` で起動する (代わりの道を通す) | FFI で起動し、読めなければ以後 `Start-Process` | 本番の道具が読む |
| `AGENT_LAUNCH_TEST_HOME` | `src/agent-launch/main.ts` | 履歴の置き場 (ホームのフォルダ) | 本物のホーム | 本番の道具が読む (試験の入口) |
| `AGENT_LAUNCH_TEST_HIDE` | `src/agent-launch/main.ts` | `1` で、窓を作らず非表示のまま番人を動かし、番人に「尋ねずに終わる」と渡す | 見える窓で、尋ねる (本番) | 本番の道具が読む (試験の入口) |
| `AGENT_LAUNCH_TEST_OUT` | `tools/40_test/run-agent-entry-tests.ts` の代役 | 代役のエージェントが、起動の記録を書く先 | — | 試験の側だけ |
| `AGENT_LAUNCH_TEST_LOG` ・ `AGENT_LAUNCH_TEST_EXIT` | `tools/40_test/run-agent-entry-tests.ts` の番人の試験の代役 | 起動のたびに記録するログ ・ 代役が返す終了コード | — | 試験の側だけ |
| `AG_TRUSTED_TEST_FILE` | `src/ag-trusted/main.ts` | 信頼を書き足す設定ファイル | `~/.gemini/antigravity-cli/settings.json` | 本番の道具が読む (試験の入口) |
| `AG_TEST_STUB_OUT` ・ `AG_TEST_STUB_EXIT` | `tools/40_test/run-ag-trusted-tests.ts` の代役の `agy` | 起動の記録を書く先 ・ 代役が返す終了コード | — | 試験の側だけ |
| `SPAWN_SERVER_TEST_HIDE` | `src/spawn-server-ts/create-process.ts` | `1` で、起動する窓を**非表示**にする (3 つの起動の道とも。窓そのもの = `conhost` は作られる)。試験が、作業中の画面とフォーカスを奪わないため | 見える窓で起動する (本番) | 本番の道具が読む (試験の入口) |
| `SPAWN_TEST_MARK` | `tools/40_test/run-spawn-server-tests.ts` | サーバーの環境変数が、起動した窓へ引き継がれることを確かめる目印 | — | 試験の側だけ |
| `PSH_TARGET` | `tools/40_test/run-psh-tests.ts` | 試す `psh` の exe (Rust 版) | `psh-main.ts` を、走っている処理系で呼ぶ | 試験の側だけ |
| `XX_TARGET` | `tools/40_test/run-xx-tests.ts` | 試す `xx` の exe | `src/xx/target/release/xx.exe` | 試験の側だけ |
| `BENCH_D` | `tools/50_run/bench-spawn/launcher.ts` | 計測 D の起動のしかた | `detached` | 計測の側だけ |
| `SPAWN_COMMAND` ・ `SPAWN_TITLE` ・ `SPAWN_CWD` | `tools/50_run/bench-spawn/launcher.ts` | 計測 A ・ C で、起動するコマンド ・ 窓の題 ・ フォルダを渡す | — | 計測の側だけ |
| `SPAWN_LINE` ・ `SPAWN_CWD` | `src/spawn-server-ts/create-process.ts` | `Start-Process` の道で、起動する行とフォルダを PowerShell に渡す。**読んだらすぐ消す** | — | 本番の道具の内部の受け渡し |

### 試験が子に渡す環境

- `run-cc-tests.ts` と `run-xx-tests.ts` は、子の `PATH` の先頭に代役の置き場を足す。`run-cc-tests.ts` は、`cc` が `CLAUDE` で始まる変数を消すことを確かめるため、`CLAUDECODE` ・ `CLAUDE_CODE_SESSION_ID` 等を子に渡す
- `run-history2html-tests.ts` と `run-history2html-viewer-tests.ts` は、`HISTORY2HTML_HOME` ・ `HISTORY2HTML_USERNAME` ・ `HISTORY2HTML_HOSTNAME` に作り物の値を入れて、実在の値が出力に混ざらないことを確かめる
- `run-spawn-server-tests.ts` は、`SPAWN_SERVER_NO_FFI=1` を付けて自分をもう一度走らせ、`Start-Process` の道も通す
