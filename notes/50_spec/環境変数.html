環境変数の仕様 (ai-agent-tools)

このプロジェクトの道具が、読む ・ 設定する ・ 消す環境変数の一覧。試験用は後半の章に分けてある。

📅 作成: 2026-11-01 / 更新: 2026-11-01

道具が環境変数をどう扱うかの、いまの姿。範囲はこのプロジェクトの全道具 (src/ ・ bin/ ・ tools/ ・ tests/)。値は書かない (名前と役目だけ)。

変数を足す・消す・改名するときは、この表を同じ回のうちに直す。探すときの語は process.env ・ $env: ・ env::var ・ set (cmd) ・ GetEnvironmentVariable。

ふだんの運用で読む変数

利用者が道具を使うときに、道具が読む変数。OS の変数と、cloud の準備で読む変数だけ。このプロジェクトの道具が独自に決めた名前のものは、ふだんは使わないので第 3 章に置く。

変数読む道具役目未設定のとき
PATHxx (src/xx)コマンド名を探すフォルダの並び空の並びとして扱う (見つからない)
USERPROFILEbin/codex-trusted.ps1設定フォルダ (.codex) の親確かめていない
GIT_AUTHOR_NAME ・ GIT_AUTHOR_EMAILbin/cloud-session-start両方が設定されていれば、プロジェクトの git の author を書き換えない (git が環境変数を使うため)片方でも空なら、共通ルールの最新の commit と同じ author を、プロジェクトの .git/config に書く
  • cc-register と history2html は、ホームのフォルダを Node の os.homedir() で取る。USERPROFILE 等の OS の変数は、直接は読まない (history2html は、先に第 3 章の HISTORY2HTML_HOME を見る)
  • cloud の準備では、呼び手が CLAUDE_PROJECT_DIR と CLAUDE_ENV_FILE の値を、環境変数ではなく引数 (--project ・ --env-file) で渡す。道具は環境変数としては読まない

道具が設定する・消す・引き継ぐ変数

道具が環境を変える場合。変わるのが「起こした相手だけ」か、「呼んだ窓にも残る」かが、取り違えやすい点。

道具どうする変数効く範囲
bin/cc.cmd消すCLAUDE で始まる変数すべて (CLAUDE_CODE_USE_POWERSHELL_TOOL を除く)起こす claude だけ (setlocal の中)。呼んだ窓は変わらない。Claude Code の中から cc を呼んでも、親のセッションの値を子に渡さないため
bin/cc.cmd設定して残すCC_ROOT (未設定のとき W:\) ・ 作業用の YMD ・ Y ・ XMD ・ HMSC ・ XHM呼んだ窓に残る (実測。CC_ROOT が未設定の窓で呼ぶと、呼んだあとに W:\ が入っていた)
bin/cx.cmd設定するY ・ YMD呼んだ窓に残るかは、実測していない
bin/use-lms.cmd設定するANTHROPIC_BASE_URL ・ ANTHROPIC_AUTH_TOKEN ・ ANTHROPIC_API_KEY (空にする) ・ CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS呼んだ窓に残る (読んだ限り。setlocal が無い。実測していない)
コマンド起動サーバ (src/spawn-server-ts)引き継ぐサーバーの環境変数すべて起動した新しい窓へ。作業用の値は持ち込まない (第 3 章の SPAWN_LINE ・ SPAWN_CWD)
bin/cloud-session-start設定するGIT_LFS_SKIP_SMUDGE=1git clone の 1 回だけ (そのコマンドの行の中)
bin/cloud-session-start書き出すPATH を通す行--env-file で渡されたファイルへ。ファイルが無ければ通さず、そう報告する

読んだ限りの組み合わせ (実測していない)。use-lms.cmd で CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS を設定した窓から cc を使うと、cc が CLAUDE で始まる変数を消すので、その 1 つは起こした claude に渡らない。ANTHROPIC_* は消されず、渡る。

試験 ・ 計測のための変数

試験や計測が、道具の動きを差し替えるための変数。「本番の道具が読む」と書いたものは、ふだんの運用で設定しても効く (試験のための入口だが、道具の中に入っている)。「試験の側だけ」と書いたものは、試験のスクリプトだけが読む。

変数読む場所役目未設定のとき読む側
CC_ROOTbin/cc.cmdプロジェクトを作る置き場。試験は tmp/ の下へ差し替えるW:\本番の道具が読む
CC_CLAUDE_JSONsrc/cc-registerフォルダを登録する先の .claude.jsonホームの .claude.json本番の道具が読む
CC_STUB_OUTtools/40_test/run-cc-tests.ts が作る代役の claude受けた引数と CLAUDE で始まる変数の書き出し先何も書かない試験の側だけ
HISTORY2HTML_HOMEsrc/history2html伏せる対象のホームのフォルダos.homedir()本番の道具が読む
HISTORY2HTML_USERNAMEsrc/history2html伏せる対象のユーザー名ホームの末尾のフォルダ名本番の道具が読む
HISTORY2HTML_HOSTNAMEsrc/history2html伏せる対象のホスト名os.hostname()本番の道具が読む
HISTORY2HTML_TEST_NO_MASKsrc/history2html1 段目の置き換えを、カンマ区切りの名前で外す。2 段目の検査が止めることを確かめる外さない本番の道具が読む (試験の入口)
HISTORY2HTML_VIEWER_DIRtests/history2html-viewer/viewer.spec.ts書き出したビューアのフォルダ空 (試験が「渡っていない」で失敗する)試験の側だけ
TRANSCRIBE_VENDORsrc/transcribewhisper の置き場。試験が本物の _vendor を触らないため_vendor/whisper本番の道具が読む
CONVERT_AUDIO_VENDORsrc/convert-audioffmpeg の置き場。同上_vendor/ffmpeg本番の道具が読む
SAFE_PUSH_TEST_HOSTNAMEsrc/safe-pushロックに書くホスト名。別のホストのロックを試すos.hostname()本番の道具が読む
SPAWN_SERVER_NO_FFIsrc/spawn-server-ts1 で、最初から Start-Process で起動する (代わりの道を通す)FFI で起動し、読めなければ以後 Start-Process本番の道具が読む
SPAWN_TEST_MARKtools/40_test/run-spawn-server-tests.tsサーバーの環境変数が、起動した窓へ引き継がれることを確かめる目印—試験の側だけ
PSH_TARGETtools/40_test/run-psh-tests.ts試す psh の exe (Rust 版)psh-main.ts を、走っている処理系で呼ぶ試験の側だけ
XX_TARGETtools/40_test/run-xx-tests.ts試す xx の exesrc/xx/target/release/xx.exe試験の側だけ
BENCH_Dtools/50_run/bench-spawn/launcher.ts計測 D の起動のしかたdetached計測の側だけ
SPAWN_COMMAND ・ SPAWN_TITLE ・ SPAWN_CWDtools/50_run/bench-spawn/launcher.ts計測 A ・ C で、起動するコマンド ・ 窓の題 ・ フォルダを渡す—計測の側だけ
SPAWN_LINE ・ SPAWN_CWDsrc/spawn-server-ts/create-process.tsStart-Process の道で、起動する行とフォルダを PowerShell に渡す。読んだらすぐ消す—本番の道具の内部の受け渡し

試験が子に渡す環境

  • run-cc-tests.ts と run-xx-tests.ts は、子の PATH の先頭に代役の置き場を足す。run-cc-tests.ts は、cc が CLAUDE で始まる変数を消すことを確かめるため、CLAUDECODE ・ CLAUDE_CODE_SESSION_ID 等を子に渡す
  • run-history2html-tests.ts と run-history2html-viewer-tests.ts は、HISTORY2HTML_HOME ・ HISTORY2HTML_USERNAME ・ HISTORY2HTML_HOSTNAME に作り物の値を入れて、実在の値が出力に混ざらないことを確かめる
  • run-spawn-server-tests.ts は、SPAWN_SERVER_NO_FFI=1 を付けて自分をもう一度走らせ、Start-Process の道も通す
