# cc ・ cx ・ ag の起動の仕様 (ai-agent-tools)

`cc` (claude) ・ `cx` (codex) ・ `ag` (agy) が、フォルダを決め、履歴があれば続きで、新しい窓で起動し、終了のあとで再起動できるまで。

> 📅 作成: 2026-11-01 / 更新: 2026-11-01

[^^](../../README.md)

詳細仕様 (いまの姿)。実装は `src/agent-launch/` (`main.ts` ・ `pick.ts` ・ `history.ts` ・ `launch.ts` ・ `keeper.cmd`) と `src/ag-trusted/`。入口は `bin/cc.cmd` ・ `cx.cmd` ・ `ag.cmd` ・ `ag-trusted.cmd`。環境変数は [環境変数の仕様](環境変数.md) を見る。

## 1. 起動の流れ

入口の cmd は、`node src/agent-launch/main.ts <cc | cx | ag> <名前>` を呼ぶだけ。変数を設定せず、カレントも動かさないので、**呼んだ窓の環境変数とカレントは変わらない**。常駐するプロセスは無い (起動する短命の node が、すぐ終わる)。

1. **名前が無い**: `[NG]` を出して終了コード 2。何も起こさない
2. **置き場** (`AGENT_LAUNCH_TEST_ROOT`。未設定のとき `W:\`) が無い: `[NG]` で終了コード 1
3. **フォルダを決める**: 年のフォルダ (`<置き場>\<yyyy>`) を、無ければ作る。置き場の直下 → 年のフォルダの中の順に、名前の一部 (大小を区別しない) が当たるフォルダを探す。複数に当たれば、名前順で最初の 1 つ。どちらにも無ければ、年のフォルダの中に `<yyyymmdd>-<名前>` を作る。**フォルダだけを探す** (名前が当たるファイルがあっても、新しく作る)
4. **続きか新規か**: 既存のフォルダで、**そのエージェントの履歴**があれば続き、無ければ新規。新しく作ったフォルダは、必ず新規。別のエージェントが先に作ったフォルダでも、そのエージェントの履歴が無ければ新規になる
5. **起動**: 新しい窓で、番人 (`keeper.cmd`) を動かす。窓のタイトルは `<入口のコマンド名> <フォルダ名>` (例: `cc 20261101-foo`)。起動したフォルダがカレント

### 起こすもの

| 入口 | 起こすコマンド | 最初の引数 (続き / 新規) | 再起動の引数 |
|---|---|---|---|
| `cc` | `claude.exe` | `-c -n "<フォルダ名> <月/日> <時:分>"` / `-n "…"` | `-c -n "…"` (同じセッション名) |
| `cx` | `codex-trusted` | `resume` / (なし) | `resume` |
| `ag` | `ag-trusted` | `--dangerously-skip-permissions --mode auto -c` / `--dangerously-skip-permissions --mode auto` | `--dangerously-skip-permissions --mode auto -c` |

- `cc` は、起こす前に、フォルダを `~/.claude.json` に登録する (初回の信頼の確認を出さないため。失敗しても起動する)。`CLAUDE` で始まる環境変数は、`CLAUDE_CODE_USE_POWERSHELL_TOOL` と `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS` (`use-lms.cmd` が設定する) 以外、起こす `claude` に渡さない
- `--project` ・ `--new-project` (agy) は使わない

## 2. 履歴の判定

置き場の構造だけで判定する (読み取りのみ。会話の中身は読まない)。W: は `C:\work` と同じ場所なので、エージェントがどちらの形でパスを残していても当たるよう、**W: の形と `C:\work` の形の両方**を見る。

| エージェント | 見る場所 | 履歴ありの条件 |
|---|---|---|
| `cc` (claude) | `~/.claude/projects/<符号化したパス>/` | `*.jsonl` が 1 つ以上。符号化は、英数字以外を 1 文字ずつ `-` にする (`W:\2026\foo` → `W--2026-foo`)。**フォルダだけあって `*.jsonl` が 0 個**のものは、履歴なし |
| `ag` (agy) | `~/.gemini/antigravity-cli/cache/last_conversations.json` | そのフォルダのパスがキーにあり (大小を区別しない)、会話の `.db` (`conversations/<ID>.db`) も在る。キーだけで `.db` が無ければ履歴なし |
| `cx` (codex) | `~/.codex/state_5.sqlite` の `threads` 表 | `cwd` がそのフォルダ (`\\?\C:\work\…` の形で残る。接頭辞と大小は無視) で、`archived = 0` の行が 1 件以上。`has_user_event` は全件 0 で、判定に使えない (実データ)。`sqlite` は読み取り専用で開く |

読めない・壊れている・表が無いときは、落とさず、履歴なしとして扱う。

## 3. 窓の番人 (再起動)

新しい窓の中で動くのは、エージェントそのものではなく、**cmd の番人** (`keeper.cmd`)。node ・ bun を、エージェントの数だけ常駐させないため (cmd の待機は約 8 MB、node は約 18〜49 MB。実測)。

1. エージェントを起動する (最初の引数)
2. 終わったら (ctrl-c を 2 回押した終了も、ふつうの終了も、終了コードによらず)、`choice` で **`R` (再起動) か `Q` (終了)** を尋ねる。小文字も受ける
3. `R` なら、**続きの引数**で起動し直す (`claude` は PATH から探すので、入れ直した新しい版が使われる)。履歴の判定は繰り返さない
4. `Q` なら、番人が終わり、窓が閉じる。尋ねている画面で ctrl-c を押したときも、窓が閉じる。答えが読めないとき (`choice` が 255) は、再起動せずに終わる

- 番人への入力は、環境変数 `KEEPER_EXE` ・ `KEEPER_FIRST` ・ `KEEPER_AGAIN`。番人は、起こす行の中で消し、**エージェントに渡さない** (作業用の `KP_*` も)。再起動の 2 回目以降にも値が残るよう、`setlocal` と `endlocal` で戻す
- エージェントは `call` で呼ぶ。`codex-trusted` ・ `ag-trusted` は cmd なので、`call` が無いと、終わっても番人に戻ってこない
- **試験の非表示のときだけ**、尋ねずに終わる (`KEEPER_NOASK`)。非表示の窓では、`choice` が答えを待ち続けて、プロセスが残るため (実測)

## 4. ag-trusted

`codex-trusted` と同じ形。現在のフォルダを、`~/.gemini/antigravity-cli/settings.json` の `trustedWorkspaces` に書き足してから、受けた引数のまま `agy` を起動する。

- **書き方は、文字列としての挿入**。配列に 1 行だけ足し、許可リスト (`permissions.allow`) などは 1 バイトも変えない。`agy` 自身が承認のたびにこのファイルを書き換えるため、JSON を作り直して書き戻さない
- 登録済み (パスの完全一致。大小も区別) なら書かない。書く前に、控え (`settings.json.backup-<日時>`) を取る
- 読んだあとに中身が変わっていたら、読み直す。3 回で諦め、書かずに止まる
- 設定ファイルが無い・壊れている・更新され続けているときは、**書かずに終了コード 3** で止まり、`agy` は起動しない (無いときは、先に `agy` を 1 度起動するよう案内する)。`agy` が見つからないときは終了コード 1。それ以外の終了コードは、`agy` のものをそのまま返す

## 5. 限界と、確かめていないこと

- **`claude` の符号化で、`_` ・ `.` ・ 日本語がどうなるか**は、実データに該当が無く、確かめていない (「英数字以外はすべて `-`」と仮定している)
- **agy の信頼が、パスの完全一致 (大小を含む) か**は、第三者の資料にあるだけで、確かめていない
- agy が、会話を消したときに `last_conversations.json` のキーを消すか。`.db` の有無でも見ているので、消えなくても、履歴なしと判定できる
- **窓を見せる形 (`start` の引数) は、代役 1 回で確かめた** (窓が開き、タイトルが `cx <フォルダ名>` になった)。試験は、窓を非表示にして回すため、`start` の引数そのものは、`startArgs` の組み立ての試験だけ。実際の `claude` ・ `codex` ・ `agy` を起こしての確認は、していない
- 起こしたエージェントが、起動のあとで、自分で窓のタイトルを書き換えるか。ctrl-c を 2 回押して終了したとき、`claude` が返す終了コード (番人は、終了コードによらず尋ねる)
- `codex-trusted.cmd` は、終わりに `pause` を持つため、`cx` では、`codex` を終えたあと、キーを 1 回押してから、番人の質問が出る
- 複数に当たるときの選び方 (名前順で最初の 1 つ) は、いまの `cc.cmd` ・ `cx.cmd` の動きを写したもので、`cx` は元から `cd` のワイルドカードに任せていた。名前順と同じかは、実測していない
