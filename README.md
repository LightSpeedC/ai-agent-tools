# html2md

HTML から生成した Markdown が、**GitHub 上で意図どおりに表示されるか**を確かめるツール。
プロジェクトを問わず使えるよう、ここに置いている。

## なぜ必要か

ローカルで正しく見える Markdown でも、GitHub では壊れることがある。
代表が**日本語の強調**で、CommonMark は `**` の前後の文字を見て開閉を判定する。

``
主題は**「何が流れるか」**です     ← ** が記号のまま表示される
``

開きの `**` の直後が `「`（句読点扱い）で、その直前が通常文字だと**開き記号にならない**。
閉じ側も同様に、直前が `。` `」` `）` `］` だと閉じられない。

**この種の不具合はローカルの目視では見つからない。**実際、閉じ側だけを直して
「60 件解決した」と判断した後、GitHub 上では開き側の 29 箇所が壊れたままだった。

## 使い方

``powershell
# フォルダ配下をまとめて
.\check-markdown.ps1 -Path N:\2026\myproject -Recurse

# 1 ファイルだけ
.\check-markdown.ps1 -Path .\README.md

# レート制限を緩める（60 回/時 → 5000 回/時）
.\check-markdown.ps1 -Path . -Recurse -Token ghp_xxxxx
``

`check-markdown.cmd` をダブルクリックしてもよい（カレントディレクトリが対象）。

問題があれば該当箇所を前後 45 文字つきで表示し、**終了コード 1** を返す。CI にも組める。

## 仕組み

Markdown を GitHub の Markdown API（`https://api.github.com/markdown`）に投げ、
**実際に GitHub が返す HTML** を見る。そこに `**` が残っていれば強調が効いていない。
コードブロックとコードスパンは対象外（`**` が実際のコードのことがあるため）。

| 項目 | 内容 |
|------|------|
| レート制限 | 認証なし 60 回/時。`-Token` で 5000 回/時 |
| 文字コード | `ConvertTo-Json` の結果を UTF-8 のバイト列にして送る。そのままだと日本語が壊れる |
| 除外の注意 | GitHub は `<code class="notranslate">` とクラスを付ける。`<code>` 決め打ちでは拾えない |

## 直し方

該当箇所だけ `<strong>〜</strong>` に置き換える。GitHub は Markdown 中の HTML を
解釈するので確実に太字になる。半角スペースを入れて成立させる方法もあるが、
日本語の文中に隙間が空くので使わない。

判定は変換スクリプト側で機械的に行い、書き手には意識させない。
