## 1. このフォルダにあるもの

| ツール | 何を確かめるか |
|---|---|
| `check-markdown.ps1` | Markdown が **GitHub 上で意図どおりに表示されるか** |
| `check-contrast.ps1` | HTML の文字色と背景色が **読める組み合わせになっているか** |
| `html2md.ps1` | HTML から Markdown を生成する |

どちらの検証ツールも、**推測ではなく実物で判定する**。前者は GitHub のレンダラに投げ、後者はブラウザで実際に描画して計測する。ローカルの理屈と実物の表示は一致しないことがある。

## 2. check-markdown

### なぜ必要か

ローカルで正しく見える Markdown でも、GitHub では壊れることがある。代表が**日本語の強調**で、CommonMark は `**` の前後の文字を見て開閉を判定する。

```
主題は**「何が流れるか」**です     ← ** が記号のまま表示される
```

開きの `**` の直後が `「`（句読点扱い）で、その直前が通常文字だと**開き記号にならない**。閉じ側も同様に、直前が `。` `」` `）` `］` だと閉じられない。

<strong>この種の不具合はローカルの目視では見つからない。</strong>実際、閉じ側だけを直して「60 件解決した」と判断した後、GitHub 上では開き側の 29 箇所が壊れたままだった。

### 使い方

```powershell
# フォルダ配下をまとめて
.\check-markdown.ps1 -Path N:\2026\myproject -Recurse

# 1 ファイルだけ
.\check-markdown.ps1 -Path .\README.md

# レート制限を緩める（60 回/時 → 5000 回/時）
.\check-markdown.ps1 -Path . -Recurse -Token ghp_xxxxx
```

`check-markdown.cmd` をダブルクリックしてもよい（カレントディレクトリが対象）。

問題があれば該当箇所を前後 45 文字つきで表示する。CI にも組めるよう終了コードを分けている。

| 終了コード | 意味 |
|---:|---|
| 0 | 問題なし |
| 1 | 表示が壊れる箇所がある |
| 2 | **検証できなかった**（レート制限・通信断など）。**「問題なし」ではない** |

> [!WARNING]
> <strong>2 を 0 と混同しないこと。</strong>検証できていないのに「問題なし」と報告するのは、このツールが防ごうとしている誤りそのもの。

### 仕組み

Markdown を GitHub の Markdown API（`https://api.github.com/markdown`）に投げ、**実際に GitHub が返す HTML** を見る。そこに `**` が残っていれば強調が効いていない。コードブロックとコードスパンは対象外（`**` が実際のコードのことがあるため）。

| 項目 | 内容 |
|---|---|
| レート制限 | 認証なし 60 回/時。`-Token` で 5000 回/時 |
| 文字コード | `ConvertTo-Json` の結果を UTF-8 のバイト列にして送る。そのままだと日本語が壊れる |
| 除外の注意 | GitHub は `<code class="notranslate">` とクラスを付ける。`<code>` 決め打ちでは拾えない |

### 直し方

該当箇所だけ `<strong>〜</strong>` に置き換える。GitHub は Markdown 中の HTML を解釈するので確実に太字になる。半角スペースを入れて成立させる方法もあるが、日本語の文中に隙間が空くので使わない。

判定は変換スクリプト側で機械的に行い、書き手には意識させない。

## 3. check-contrast

### なぜ必要か

CSS を読み返しても「白背景に白文字」は見つからない。**CSS は宣言単位で無効化される**ためで、色を CSS 変数で渡していると、変数が未定義のスコープで `background` だけが落ち、`color` だけが生き残る。

```css
.toc a {
	background: linear-gradient(100deg, var(--dc), var(--dc2));  /* --dc 未定義 → この宣言だけ無効 */
	color: #fff;                                                  /* こちらは生き残る */
}
```

背景が消えてページの地色（白）になり、そこに白文字が乗る。ペアで書いたつもりでも片方だけ落ちる。同じ壊れ方をする経路は3つある。

| 経路 | 起きること |
|---|---|
| 変数が未定義 | その宣言だけ無効。背景が消えて文字色が残る |
| セレクタが広すぎる | 想定外の要素に片方だけ当たる |
| 継承 | 親の `color` を継いだ要素が、別の背景の上に置かれる |

### 使い方

```powershell
# フォルダ配下をまとめて
.\check-contrast.ps1 -Path N:\2026\myproject -Recurse

# 1 ファイルだけ
.\check-contrast.ps1 -Path .\README.html

# しきい値を変える（既定 1.5）
.\check-contrast.ps1 -Path . -Recurse -Min 2.0
```

`check-contrast.cmd` をダブルクリックしてもよい（カレントディレクトリが対象）。

ブラウザは `N:\2026\PlayWright` の共有環境のものを使う。場所が違う場合は `-PlaywrightRoot` で指定する。

| 終了コード | 意味 |
|---:|---|
| 0 | 問題なし |
| 1 | 読めない配色がある |
| 2 | **検証できなかった**（Playwright が無い・描画に失敗など）。**「問題なし」ではない** |

### 仕組み

ブラウザで実際にレンダリングし、テキストを持つ全要素について `getComputedStyle` から前景色と実効背景色を取得してコントラスト比を計算する。

| 項目 | 内容 |
|---|---|
| 実効背景色 | `background-color` が透明なら親を遡る。行き当たらなければページの地色（白） |
| グラデーション | 色停止点の**平均色**を使う |
| 半透明 | 下の色と合成してから比を求める |
| 対象外 | SVG（文字色が `fill` で決まる）、非表示要素、サイズ 0 の要素 |
| リダイレクトページ | `meta refresh` / `location.replace` は転送先を二重検査するため除外 |

<strong>しきい値の既定は 1.5:1。</strong>目的は「読みにくい」ではなく<strong>「読めない」</strong>の検出に絞っている。

WCAG AA の 4.5:1 で判定すると、100deg のグラデーションでは**文字が1文字も乗っていない右端の色**まで拾ってしまう。実際に試したところ 16 件中 15 件が誤検出で、本当の問題が埋もれた。値を上げてはいけない。

### 検査自体を確かめる

**検査が壊れていないことを、故意に壊したページで確認してから使う。**

```powershell
.\check-contrast.ps1 -Path .\contrast\selftest.html
```

`contrast\selftest.html` には 7 ケースが入っている。4 件が検出され、3 件が検出されなければ正常。

| ケース | 期待 |
|---|---|
| 変数未定義で背景が消えた白文字 | 検出（1.00:1） |
| 黒背景に黒に近い文字 | 検出（1.13:1） |
| 淡いグレー同士 | 検出（1.10:1） |
| 白文字を継承したまま白い箱に入った | 検出（1.00:1） |
| 濃い紺のグラデーションに白文字 | 検出しない |
| 白背景に濃い文字 | 検出しない |
| 緑のグラデーションに白文字 | 検出しない |

### 直し方

| 原因 | 直し方 |
|---|---|
| 色の `var()` が未定義 | `var(--accent, #12224d)` のように**フォールバックを書く** |
| 配色セレクタが広すぎる | `.toc a` ではなく `.toc ul a` のように**要素構造で絞る** |
| 親から `color` を継承した | その要素に `color` と `background` を**対で指定する** |

`color` を書く宣言ブロックには `background` も書く（逆も同じ）。例外は `body` のみ。
